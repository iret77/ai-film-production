## 1. Pipeline principles
🟢 **Stills-first:** every shot exists as an approved still before any video generation. The look is won in the image; video inherits it. Cheap iteration happens at the image stage.
🟢 **The approved still is a REFERENCE anchor, not a start frame [PP, P22]:** by default the anchor is attached as an @Image reference (look, geometry, blocking) next to sheet and plate, and the take opens already in motion (video-prompting ch. 12). A literal start frame (i2v / first-frame slot) is doctrine ONLY where a take must join an existing clip frame-exactly: chunking a long sequence at the model's maximum take length on a route without an extension mode, or a first/last-frame interpolation between two approved stills of the SAME shot (ch. 16 Start & End Frame — a move, not acting); on Seedance 2.5 forward/backward continuation runs as `video_extension` from the source clip, not from a harvested frame (video-prompting ch. 14b). Everywhere else start and end frames are more often a problem than a help — they carry the still's posed, plastic quality into motion, freeze a composition the model would otherwise develop, and force a static opening the trim rule cuts anyway. Off-doctrine use only when the director explicitly knows they need frame-exact continuity: state the trade-off once, then follow the call. 🟡 [P65, same practitioner as P22, two weeks earlier]: "when I use start frames I notice more plastic-ness coming through"; a start frame is used only when exact placement matters (a character who must stay on one stool), and then the take opens on a DIFFERENT angle (a close-up) so the frozen composition is not the opening. **Multi-shot take (SKILL rule 2):** attach EVERY internal shot's approved anchor, each with its job scoped to its own shot and time range — "@anchor_1A controls look, geometry and blocking of SHOT 1 (0–5 s) only; @anchor_1B controls framing and blocking of SHOT 2 only, from the HARD CUT at 5 s — not before" — so only shot 1's anchor can shape the opening frame (12b plate-pinning). This is the sanctioned exception to 12b's "never place an @tag in a shot where that object is not present": the tag IS present in its own shot; the time scope keeps it out of the others.
🟢 **Vendor-proven at feature length [H-off, P24]:** Higgsfield's 110-minute "The Cully Hill Boys" (Aug 2026, $2M, open-sourced) ran on ONE condition: text-to-video only — no start frame, no image-to-video; every shot born from references plus text, "the assets carry the picture, the wording carries everything else, including the geometry". Stated reason: harder, but the shots cut together. The single exception was a phone-shot stunt clip used as motion reference (renderability §3). Their five production rules: (1) assets first — nothing generates until every face, place and prop is locked; (2) describe everything, every time — the model has no memory (everything = scene, action, geometry, locks; IDENTITY stays in the sheet plus the minimal anchor line, video-prompting 12b — never long appearance prose); (3) change one thing at a time; (4) give the model less freedom — a corner, not a room, a map, not guesswork; (5) shot won't land? simplify the shot, not the words. Reconciled with the economy doctrine: 'everything' = everything the agent OWNS (scene content, beat order and end states, one job per reference, canon), restated per take because the model has no memory across takes — never the axes the model owns (camera composition, cutting, body mechanics, material, light). 'Less freedom' is geography (a corner, a map, a blockout — ch. 8), not more prose.
🟢 **Build-order rule — one rule, three cases (W2 step 1 and W10 stage 5 cite it):** (a) default — location plates → characters → props → composite stills → draft takes → production takes; characters are shot INTO approved plates, never invented alongside them. (b) Stylized 3D / Pixar — character sheets → figure-anchored plates → derived empty plates (pixar-look §8). (c) Any project with a blockout stage (storyboard-first model, workflows W10) — character & prop sheets → 3D blockout → location plates: the blockout needs the figures' proportions (the sheet's comparison object, ch. 3) and the layout map's relations, and the plate needs the blockout's geography. (c) overrides (a); (b) and (c) combine as sheets → blockout → figure-anchored plates.
🟢 **Inverted order for Pixar/stylized projects (hard rule) [PP]:** stylized environments generated WITHOUT a figure default to photoreal on every image model — because stylized-feature environments are themselves near-photoreal, the model has nothing to stylize against. The figure in frame forces the whole render into the stylized mode; figure + environment together IS the look. Hence case (b) of the build-order rule above (the empty plate is derived by removing the figure — the style stays baked in). Alternative for figure-less environment stills: the prompt-only style-forcing method (pixar-look §9) — reliable in bright light; dark scenes need a self-generated bright style anchor. Applies to Pixar and comparable stylized-3D looks; photoreal projects keep the location-first order above.
🟡 **Figure-anchored plate straight into video, with a scale-only role line [P32]:** instead of deriving an empty plate first, the figure-anchored plate can be attached to the video generation as is — role line verbatim: "the figure already standing in @Image 2 is used only as a scale reference to establish her correct proportional size relative to the buildings; do not treat it as a separate character or duplicate her; only one [name] exists". Saves the derivation step; the risk it manages is the duplicate character.
🟢 **Review loop:** generate → review against acceptance criteria → repair in the rule-15 order (remove → change → add) in the NEXT prompt (not only in post) → regenerate. Acceptance criteria always include the project's Verify line next to the shot-specific criteria — the chosen recipe's Verify line (director-recipes), or, where no recipe was chosen, the DEFAULT VERIFY LINE written with the style anchor (workflows W1 step 5) — a take can be technically clean and still off-style. Worth knowing: a defect accepted at the still stage propagates into motion, so a still that is "close enough" often costs more later — the user decides when it is good enough to move on.
🟢 **Sheets vs. in-scene stills:** reference sheets (neutral light) maximize consistency; in-scene stills (scene light) maximize realism. Both exist; sheets feed identity, in-scene stills feed the take.
🟢 **Label discipline:** every asset gets a stable ID (@name) reused verbatim in prompts, filenames, and the continuity ledger (post-audio-legal ch. 19).
🟢 **The reference pool is a project deliverable (Seedance 2.5) [BD-off]:** beyond sheets and plates, build the casting pool out deliberately — wardrobe details, prop stills, style stills, motion clips, voice/audio refs, clay blockouts — ONE reference for every element that must stay consistent anywhere in the production. Per-scene selection then draws from a complete pool instead of improvising prose; an element controlled only by text will drift. Capacity and doctrine: video-prompting ch. 14b.
🟢 **Approved anchor stills are assets too [PP]:** register every APPROVED shot anchor as a named element in the platform library (tag = shot ID: `@anchor_1A`), exactly like characters, locations, and props — video prompts then address it by tag instead of manual image attachment. (Platforms without an element library keep the same tag as a versioned file re-attached per run — production-bible 22c.) Loose anchor images accumulate over a production and manual re-attachment becomes a growing error source (wrong version, wrong shot). Only the final approved anchor is registered; rejected variants never are.

## 2. Script & treatment for generability
Before stage one: the story intake gate and container choice (story-structures ch. 23) — the story comes from the user; the container decision precedes the treatment.
🟢 Write the script in stages: logline → treatment → shot-level script; at each stage run a renderability pass (renderability.md) and cut or rescue red elements — rescue cuts are a writing tool, not a defeat. Candidate-synopsis ideation happens ONLY when the user asks for story help (story-structures 23a) — then labeled PROPOSALS per 23a, never a ten-synopsis batch unasked; the story comes from the user.
🟢 **Deliverable shapes (copy these; do not invent columns):** TREATMENT = Title · Logline · Premise · Container (story-structures ch. 23) · Format / length / platform · Style anchor (the project style-contract paragraph, SKILL.md Workflow step 4) · Synopsis (≤1 page) · Scenes — each: heading (INT/EXT · place · time), beat prose written cause→effect, then the SKILL.md shot table (`| Shot ID | Len | Framing | Action | Assets | Risk | Rescue |`) · Pre-production: Set build (locations + locks + reverse decision) / Casting (sheet orders; expression sheets for animation) / Props (state pairs) · Risk register (SKILL rule 11 shape). SHOT-LEVEL SCRIPT / SHOT LIST = the same shot table, one row per shot, with Shot IDs that are canon for the bible shot board; dialogue lines verbatim in the Action cell with the speaker named. "Screenplay"/"Drehbuch" = the shot-level script by default; standard screenplay page format only when the user explicitly asks for it, and then still followed by the shot table per scene.
🟢 **STORYBOARD (storyboard-first model, workflows W10 stage 3) — four parts, all mandatory:** (1) **Camera setup system** per location: named setups `K1…Kn`, each written in words — position, axis side, height, move (`K1 — door corner, low, left of the axis, static`); the floor-plan numbers and the focal length stay in bible section B3b as a numeric channel and enter a prompt only as a deliberate look control listed in Crew choices (rule 7); every shot belongs to exactly one setup; all setups on one side of the action axis; adjacent shots change setup or shot size by ≥30° / two sizes; recurring wides on the same setup (anchor composition). (2) **Panels**: look-free grey sketches or blockout frames, red arrows for camera and object motion, panel pairs `a/b` for start/end state, setup tag on every panel — a panel is a planning view, never a generation reference (ch. 8 geometry inputs are the layout map and the blockout, not the panel). (3) **Take/cut table**: one record per shot — `shot_id · setup · take · internal_tc · duration_s · camera (setup tag + the setup in words) · action_start · action_end · continuity_in · continuity_out · refs (@tags) · cut_type (model / manual — every ellipsis is manual)` — plus the **state ladder** per changing object (state → in-frame cause → sheet order). (4) **Layout map** per location with the setups drawn in, scale as object relations (register it as a layout schematic, ch. 8). Ranking: setup system + take/cut table + state ladder + anchors bind; panels are the director's checking view ("sketch deviates — setup rules", never a redraw) — a storyboard without a camera setup system is unusable: free camera positions per panel produce the perspective inconsistency that later shows up in the takes. **Export schema (the agent-readable form the skill expects from any planning tool, JSON or a Markdown table with these exact keys):** `shot_id, setup, take, internal_tc, duration_s, camera, action_start, action_end, continuity_in, continuity_out, refs, cut_type` — optional `panel` (file/link) and `state` (state-ladder step). Filled: `K1 — door corner, low, left of the axis, static` · `1A · K1 · S1 · 0:00–0:04 · 4 · K1 static · wet cat at the hatch · cat below the dark lamp, looking up · — · lamp dark · @cat @loc_lamproom @anchor_1A · model` · `@lamp: dark → lit by the cat's push (1B) → @lamp_lit`. The take/cut table's rows ARE the bible shot board's rows (section B4 columns Seq. take · Internal TC · Cut type · Continuity lock · State); Shot IDs are assigned once here. Blockout: ch. 8; storyboard sketch template: ch. 9. **Planning environment:** FilmFlow Pro — `FILMFLOW-WEB@2026-09-07` (capabilities, caveats: platform-ui-workflows §6 row) — use it for W10 stages 2–3 only if its frames stay look-free and it delivers the export schema above; fallback: Markdown shot board + grey sketches (ch. 9 template).
🟢 **Single shot is the default for calm beats [H-off, P47]:** multishot only where action or dialogue must be dynamic — "for pretty much everything else, single shot" (the source behind rule 2's single-shot default).
🟢 **Split physics beats from acting beats [H-off, P69]:** one prompt cannot focus on both — in the vendor's own arena scene the fight (grab, throw, takedown) and the reaction (her worry, his hope draining) were generated as two takes and stitched, because in one prompt "the fight gets softer, the faces get flatter". Same finding on the finale: a 30-s carnival prompt held technically but the beats felt rushed; split into three 15-s prompts the acting "got room to breathe". Rule: when a take carries a physics-heavy event AND a face-carried reaction, they are two takes (SKILL rule 3 complexity budget applied to the axis physics vs performance); the join is an edit, not a HARD CUT inside one generation.
🟢 Open on a hook (first 2 s earn the rest); write endings as their own beat with its own time range.

## 3. Characters
🟢 **Minimal sheet:** front, side, back, face close-up, clothing detail — one character per image, neutral even light, plain background. 🟢 Official course variant: a 3-view sheet (full-body front, full-body back, frontal close-up) generated FROM a reference photo on a grey background — the close-up is what locks the face. 🟢 **Defensive anatomy locks are official practice:** character prompts carry insurance lines ("Both arms whole and both hands normal, intact human hands — no missing limbs") and anti-sheen skin lines ("skin matte and low-sheen — no oily highlights, no specular hotspots") — pre-empting the two most common character defects. [H-off Stage 2] **One-face rule:** exactly one canonical face; never let a second "almost right" face into any reference set.
🟢 **Which sheet to order (selector):** photoreal / licensed likeness → headless 3-panel + two portraits (below) · animation → one pose + 8 expressions [P17] · stylized 3D → CG turnaround (below, P23) · the 5-panel minimal sheet → stills-only or discovery work · real person with photos + consent → hybrid face sheet (P69, below) · many sheets that must share panel geometry → G-panel blank-template variant (P52) · several wardrobes → one headless sheet per wardrobe (P65) · Seedance 2.5 leads → sheet by default, the 14b single-view angle set only when the 10/10 test fails on the sheet. Whatever the format, ONE clean face source per character is the invariant.
🟢 **Size on a sheet is a relation to something ON the sheet, never a measure [PP 2026-09-14; SKILL rule 7]:** when a character's or prop's scale matters (a giant, a miniature, a creature beside a human), the sheet order places a comparison object on the sheet — a turnaround with the reference object standing beside the figure ("shoulder level with the top of the doorframe drawn beside it") — and every downstream prompt repeats that one relation; never a height in metres or body-lengths, on the sheet or in the takes — a sheet has no scale bar either, so a number sets nothing. The order's `Format` row names the comparison object.
🟢 **Headless bodies, two portraits — the feature-film sheet [H-off, P24; independently reproduced by P28, P38]:** three panels — full body front, full body back, one LARGE close portrait in 3/4 view. Remove the heads from the full-body panels: the small, soft face on a wide panel is exactly the face the model copies into wide shots, badly; with the heads gone, the close portrait is the only face source. Make TWO close-ups, with and without a smile — otherwise the model invents the teeth and the smile arrives as somebody else's mouth. For licensed real people the sheet is built from contract photography (the actor's face, not a type) and only the sheet ever enters a shot.
🟡 **G-panel variant with a blank layout template [P52]:** the same headless logic in three vertical panels — LEFT the front body from the collar down (no head, no hair, no headwear), CENTER one complete rear full-body view, RIGHT one 3/4 head-and-shoulders portrait with clear margin all round (head and shoulders fully inside the panel) — generated from TWO references: `@image1` = identity photo ("preserve face, age, proportions, clothing, garment-colour relationships"), `@image2` = an EMPTY three-panel template ("use only as the layout: keep its three equal panels, divider lines and off-white background"). The blank template is a layout-sketch channel (image-model-logic 24c rung 4) that stops the model improvising panel geometry across a cast; the constraint list names the sheet's own failure modes (cropped head or feet, extra poses, props, scenery, text, added borders, duplicate body parts, costume changes, extra characters). 35 style variants of this prompt (GPT Image 2 on OpenArt) are public at cartoonprompts.com; a restyled sheet must transform construction, not add a surface (style-control §7 Rule 5). 🟡 **Anchor stills for dialogue takes: mouth closed [P52]:** an anchor or start still with an open mouth fights the first spoken line — `mouth closed, neutral` in the still's constraints. 🟡 **The 2.5 alternative to a sheet** — several single-view angle images per lead subject — is documented with its conflict in video-prompting ch. 14b [P58].
🟡 **Face first, outfits as their own step [P65]:** build the identity source as a face-only still (plain tank top, no styling, 18% grey), then put each wardrobe onto that face with an edit model (Nano Banana Pro in the source) — and when the edit model's outfit feels wrong, design the outfit on a GENERIC model in a stronger image model (Soul Cinema, which cannot reference your character; Seedream 5.0 for outfits, weak on faces), screenshot it, and have the LLM write the swap prompt from outfit still + headshot. One headless three-panel sheet per wardrobe/scene (interview look, street look, stage look); a six-panel sheet only when an identity prop (a skateboard, an instrument) must carry through — the extra panels show the prop, not more views of the face.
🟢 **The hybrid face sheet for real people [H-off, P69]:** a sheet generated FROM a person's photos (Seedream, "use the attached face references") returns a look-alike actor, never the person — "the bride would notice". The vendor's fix on its own platform: keep the Seedream sheet for costume, body and silhouette, ERASE the head on the full-body panel, and paste the person's real photograph into the portrait panel; the composite sheet is the identity reference. This is the headless sheet (P24) with a photographic face source — consent per ch. 20, and platform acceptance of a real face is tested first (post-audio-legal ch. 20 moderation plan; the vendor ran it on Higgsfield in Aug 2026). 🟢 **Extras as one element [H-off, P69]:** ten distinct pirates lined up on grey and saved as ONE element ("the crew") stopped the background pirates regenerating as "random mush" with a different face per shot — the crowd sheet of renderability §2, vendor-confirmed; every deck shot pulls from the same ten.
🟢 **State sheets:** any persistent change (wet, wounded, dirty, costume change) is a NEW sheet order, never a prompt adjective. The ledger (post-audio-legal ch. 19) tracks which state sheet each shot uses.
🟢 **One asset per state, and a lock test before canon [H-off, P24]:** a hero has as many assets as states he passes through (clean jacket → wet after the river → split brow and blood on the tee); mixing states in one text makes blood fade in and out and jackets return. Every asset passes a stress test before it is locked: ten generations in different poses and light, recognisable in ten of ten (the source does not name the medium; default to image-model stills at draft tier — cheap — and use short draft takes only for an asset whose identity lives in motion) — a fail means the description is wrong, not the model. "Splitting is cheaper than arguing."
🟢 **Asset A/B before lock — one fixed prompt, one swapped variable [H-off, P48]:** keep 2–3 sheet candidates, run the SAME draft-take prompt every time and swap only the hero (or only the location); Soul Cinema sheets on grey ("win rate is way higher on grey"; 🟡 [P65] gives the mechanism and the value — an 18% flat grey background with flat studio light, because white backgrounds with hard studio contrast push the downstream video toward plastic skin); the verbatim erase step for the headless sheet in GPT Image 2.5: "Erase the face from the full body shot on the right panel". LLM-side reference: screenshot a liked moment and give it to the prompt-writing LLM (not the generator) as positioning/lighting context for the next prompts [H-off, P47].
🟢 **Anti-drift ladder:** (1) sheet as reference in every generation, (2) the reference's one line carried verbatim (12b anchor line in the block structure, job sentence in a Caption Spine), (3) frame-harvest a well-liked generation as an additional reference, (4) if drift persists: regenerate the sheet, don't patch outputs.
🟡 **Type descriptions pull a famous face [P37]:** "rugged, 40s, weathered fisherman" returned a recognisable actor; the fix was a reference photo plus DELETING all physical text — keep only what the headshot cannot show (wardrobe). Also: never write mapping labels ("John") into the sheet image itself — causes confusion and duplication [BD-off, ModelArk 2.5 guide]. Scope: this concerns the description that SUBSTITUTES for a face reference. It does not shorten the identity line: in technique B the 12b anchor line keeps age, build, current state and unique visible features; in a Caption Spine the reference's job sentence carries identity and only the current STATE is written in the beat (12h) — those are concrete, this-face facts. What pulled the famous face was the evaluative TYPE stack ("rugged", "weathered") standing in for a reference; with the sheet attached, replace type adjectives by concrete features and never by nothing.
🟢 **The face close-up is the identity carrier — sheets stay clean:** anything that occludes or degrades the face in the sheet (overlays, veils, grids, heavy stylization) costs likeness in EVERY generation downstream. 🟡 Measured once [P19]: a light scratch overlay on Seedance 2.5 cost ≈15–20 % of the likeness across three paired scenes. If a platform refuses a real face, route via the moderation plan in post-audio-legal ch. 20 (test acceptance first, alternative route, face-grid fallback with its stated limits) — never quietly ship a degraded sheet as the project's identity source.
🟡 **Strip small non-identity accessories from the sheet [P20]:** tiny details (a small hat, a thin chain, a pin) don't render sharp in video and can shift the character's features as the model tries to hold them — remove them from the sheet and add them per shot only where the story needs them. Sheet model choice: the Seedream 5.0 Pro note under the table in ch. 5.
🟢 **Anchor standard:** a sheet or plate is iterated until it matches the script situation exactly — "good enough" is a take standard, never an anchor standard, because one wrong anchor multiplies its error across every take that references it; deadline pressure does not lower it. The SKILL rule-15 ladder governs HOW to iterate (channel change after three failed iterations), this standard governs WHEN to stop; the per-shot iteration cap (ch. 10) applies to shots, not to anchors.
🟡 **Beautification drift is a failure class [P19, P20]:** models push faces toward symmetry and polish ("turned up the handsomeness slider"). Lock imperfections on the SHEET (the portrait prompt's 3–5 face-defining features, template below); repeat them in a video prompt's identity line only after a run of this take has shown the face polished (rule 15 order, one line); a bare-noun negative field is the only other channel, per the ch. 24f table. Realism is imperfection — the uncanny valley is the too-perfect face, not the flawed one.
🟢 Voice: the sheet locks the voice along with the face on audio-capable models — accept the native voice where it fits; otherwise replace via the voice pipeline (post-audio-legal ch. 18).
🟢 **Animation sheet variant [P17]:** for ANIMATION projects, expressions beat views — animated video carries far more facial expression than cinematic footage. Layout: one full-body pose + 8 distinct expression panels (instead of the multi-view emphasis); the video model draws on the expression range during acting. Cinematic/photoreal projects keep the multi-view sheet above.
🟢 **CG-turnaround sheet for 3D-stylized projects [H-off, P23]:** A-pose front + back full body plus a large face close-up, neutral background, rendered as a finished 3D character — this sheet sets the project's stylization level and doubles as the style donor for painted environments (pixar-look §8, §10). Identity-bearing small props (glasses, cap) stay on the sheet; only non-identity clutter is stripped. Prompt: "Character turnaround sheet, landscape 16:9, three panels on a plain neutral background: A-pose full-body front, A-pose full-body back, one large face close-up 3/4 view, mouth closed. Rendered as a finished stylized-3D character: [shape language, material, subsurface skin]. Identity props kept: [list]. Even studio light. Avoid: text, labels, extra poses."
🟢 **Crowd sheet:** one multi-variant sheet (6–12 distinct extras) referenced for background population — prevents clone crowds.
🟢 **Large casts: single-view stills for cameos, sheets only for leads [BD-off; P40]:** multi-view sheets for 10–13 characters in one 30-s take produced "twins"; switching cameo characters to single-view single shots (sheets kept for the two leads) mostly fixed it — the official ">5 subjects → single-view images" rule confirmed in production. Reconciled with the casting system (video-prompting ch. 14): the reference lines list EVERY reference once (identity binding only — the casting/ACTIVE REFERENCES block in technique B, one job sentence each in a Caption Spine); the ACTION text mentions each cameo only at its beat (an unmentioned character never shows, a vaguely mentioned one is replaced by a look-alike) and write the exit clause where the cameo leaves — a POSITIVE LOCKS line in technique B, a half-sentence inside that beat in a Caption Spine: "each referenced character appears only during their described encounter and must not reappear after @hero has passed them". Wardrobe stays in words even when it is on the sheet (a red shirt migrated to another character); an instrument visible on a reference gets played — state it.

### Asset order — the deliverable shape
An asset order is delivered like every executable prompt: a Render Slate (SKILL.md rule 11) directly above a standalone still-prompt code block — ONE slate + block per @tag and per state. For orders the slate carries three extra rows after `Inputs`: `Format` — which sheet/plate/pair per the selector above + the state ("headless 3-panel + 2 portraits · state: wet") + the comparison object when scale matters (relation, never a measure — above); `Locks` — the defensive lines written verbatim into the prompt (one canonical face · both arms whole, both hands intact · skin matte, low-sheen · identity props kept: … · clutter stripped: …); `Register as` — `@tag · type · status draft` (→ bible section B3; approved on the director's call, locked only after the 10/10 stress test above). In the treatment's pre-production section (SKILL.md Workflow step 4) list every order as one line — `@tag · type · format · states · reference source · reverse decision (locations only)` — the slates + prompts follow in the asset-order deliverable.
🟢 **Headless 3-panel + two portraits (the photoreal/likeness default, above) — three prompts:** (1) Sheet: "Character reference sheet on a plain neutral grey background, landscape 16:9, three panels separated by white gutters. Panel 1 (left): full-body front view, A-pose, [wardrobe/state]. Panel 2 (centre): full-body back view, same pose and wardrobe. Panel 3 (right, largest): close portrait in 3/4 view, neutral expression, mouth closed — [3–5 face-defining features incl. imperfections, e.g. uneven hairline, bags under the eyes, visible pores]. Even neutral studio light. Skin matte and low-sheen; both arms and both hands whole and intact. Identity props kept: [list]. Avoid: oily highlights, specular hotspots, face shadows, missing limbs, extra accessories, text, labels." (diffusion models: the Avoid list goes into the negative field as bare nouns, rule 6) (2) Edit on the approved sheet: "Erase the face from the full-body shots in panels 1 and 2; keep everything else identical." (3) Edit for the second portrait: "Same character as the reference, identical framing and light: the close portrait now smiling with teeth visible." Register (2) as the sheet and (3) as a second portrait under the same @tag; a state change = a new run of (1)–(3).
🟢 **Location plate set (ch. 4):** Master: "[Location], seen from [camera position and height], the [anchor object] at [position in frame], [light source] from [left/right], one exposure, no people, no text. [project style block]". Detail ×2–3: "Detail plate, same location as @image1 (controls materials, light side, palette — do not copy its framing): [object], same light side, exposure and white balance as @image1." Reverse (only when the reverse decision says yes): NOT free text — ch. 16 rung 3: a purpose-built angle tool or GPT Image 2.5 with the master plate + a layout map attached, prompt "Same room as @image1 (controls layout, materials, light side, palette — do not copy its framing), seen from the opposite side of the [named axis]; the [anchor object] visible at [position]; same light side, exposure and white balance as @image1; no people, no text"; then the reverse test (anchors, openings, light side, palette).
🟢 **Prop state pair (ch. 4):** Still A: "[Prop], [state before], [framing], [light], plain background, no text." Still B as an EDIT of the approved A: "Same object, identical framing, light and background; the only change: [state after]." Two separate stills, registered as @prop_a / @prop_b (never one two-panel image). Plate and prop templates: a Kelvin or lens value only when the style contract fixes it (rule 7), then once.

### Copy-ready sheet & board templates [G2-gallery]
🟢 **Character reference sheet — gallery / stills-only variant (works verbatim; ⚠️ multi-face, no dedicated close-up — NOT for video identity work: order the headless sheet above instead):** "Based on this character [reference attached], create a character reference sheet similar to official setting materials: three-view drawings (front, side, back) · facial expression variations · detailed parts breakdown of clothing and equipment · a color palette · organized layout, white background, [style] illustration." Adapt the style word; keep the structure.
🟢 **Expression grid (feeds the expression-sheet order):** "Create a [N]-panel expression grid of [character, reference attached]. Face shape, hairstyle, and clothing must remain highly consistent across all panels. Expressions: [list them explicitly — happy, sad, angry, surprised, shy, contemplative, scared…]." Naming each expression beats "various emotions".
🟢 **Multi-variant cast grid (THE crowd-sheet tool):** "A single landscape image containing a clean [2×5] character grid. Each panel shows a different [role archetype list — one distinct hairstyle, outfit, prop, and expression each]. Keep all panels consistent in art direction: [style tokens], tidy white gutters, small name tag per panel — a collectible cast-sheet feel." Distinct archetypes per panel prevent clone crowds; the shared art-direction line prevents style drift across panels.
🟢 **Multi-panel consistency rules (all grids/sheets/boards):** state the grid count exactly (3×3, 2×5, 16-panel) · give each panel a role or beat · one shared art-direction sentence covering all panels · white gutters + per-panel labels where identification matters. Structure (canvas, ratio, grid) goes BEFORE subject description — otherwise the model spends its detail budget on the subject and improvises the layout.

## 4. Locations & props
🟢 **Generate locations for the camera angles you will need, never frontal [H-off, P24]:** a frontal room picture is flat wallpaper — the model cannot read volume from it and invents new surroundings past the frame edges every time. Leave one anchor object in every location and tie all staging to it ("the hero at the lamp, facing the door" works; "the hero in the room" is a lottery). **Location kit from one plate (photoreal projects; stylized 3D: figure-anchored plate first, production-pipeline ch. 1, or the walkthrough defaults to photoreal):** generate a video of the EMPTY location with the camera slowly walking through — the model draws the other sides of the room to match the plate; harvest frames as the reverse/side plates (ch. 16 rung 2).
🟢 **Choose the plate for the ACTION's geography, and read the rejects [H-off, P69]:** "about 70% of the final quality comes from the location." Vendor selection pass over a Soul Cinema batch of eight: reject a pier with no room for the crowd and the sprint the scene needs · reject clutter (birds, junk at the frame edge "turn into mush during generation") · reject a plate whose colour cast (a heavy yellow tint) would leak into every take · keep the plate whose sides hold the mess and whose centre stays clean for the action. Read the scene's beats (a packed crowd, a shoulder bump, a long run, a leap onto a ship) before picking; the plate must have room for each. 🟢 **Crowd scenes: generate the plate already populated [H-off, P69]:** an empty carnival square kept breaking when the crowd was added at video time; the plate generated WITH the festival crowd held, and a draft take confirmed the crowd survives motion before the scene was built — the figure-anchored-plate logic (ch. 1) applied to crowds.
🟢 **Views as separate images, assigned per cut [H-off, P47, P48]:** front and back views are separate stills (never stacked into one composite — the vendor retracted its own two-view collage), each assigned in the prompt ("cut 1 uses the front view, cut 2 the back view"); a ceiling-corner "CCTV" angle is a third useful plate. **Prop sheets for tricky anatomy:** a monster claw kept rendering as a held sword until a prop sheet showed the arm "from the outside and from the inside" — the durable fix behind the 12f staging trick. **Multi-face props** (a wall of twelve Polaroids) break every face in one generation — one face per generation, assembled in an editor.
🟢 Per location: one master wide plate + 2–3 detail plates at ONE shared exposure/palette. **Reverse decision up front:** does this location need counter-angles (dialogue, cross-room action)? → build the multi-plate set (platforms-models ch. 13b). Pass-through/B-roll → one wide suffices. Missing reverse plates ordered late are the most expensive single mistake in the pipeline (ch. 16).
🟢 Props with narrative state changes get a **state pair/series of stills** (before/after), treated like character state sheets; a post-state needs its visible cause in frame (break point, debris, crack) or it reads as placed — the state ladder of the STORYBOARD (ch. 2) lists state → cause → sheet order.
🟢 **Light openings as geometry:** describe a window, door, hatch or gap by height, size and depth and let the model derive the light from it; light-geometry words (beam, narrow, strip, shaft) generate visible rays. **Scale as object relations only** ("twice the height of the doorway", "knee-high to @hero" — never a body-length count or a metre value, SKILL rule 7), never adjectives — the layout map (ch. 8) carries the relations.
🟢 **Prop size in composites is set by relation or mask, never by canvas fractions** ("% of image width" is meaningless to an image model) — size mechanics: style-control §2; full control ladders: image-model-logic ch. 24.

## 6. Video prompting basics
🟢 **Position lock:** state where the canon fixes a subject at the start and the state each beat ends in (rule 2 ENDING STATE); an uninvolved object, a gaze direction or a mid-action pose is written only when the canon demands it or a run of this take has shown it drifting (rule 15 order) — a half-sentence inside the beat (Caption Spine, video-prompting ch. 12h) or one POSITIVE LOCKS line (technique B); across the internal shots of one take the position lock is carried verbatim (continuity, W4 step 2). Everything else about writing a video prompt: video-prompting.md (12h / 12 / style-control §6c), SKILL rules 6 and 10.

## 7. Dialogue scenes
🟢 **Framing recycling:** exactly two repeated framings (single ↔ over-shoulder); "shot 3 repeats shot 1's framing" — repetition is what sells coverage.
🟢 Reverse-environment references are mandatory (multi-plate, platforms-models ch. 13b); **180° lock:** name the axis and the side the camera stays on, once per take — the one camera line the agent owns (Division of labour), never as a prohibition. Strongest spatial lock for multi-person dialogue: the 3D blockout path (production-pipeline ch. 8) — seat positions, eye-lines, and cuts pre-decided in gray boxes hold where text-only prompting swaps seats [P18].
🟢 One line per shot beat; speaker tags per platform syntax (video-prompting ch. 12 · platforms-models ch. 21); never two characters speaking simultaneously.

## 7b. Interview scenes (documentary path)
(Dramaturgy of interviews — voice functions, contradiction editing, hook/reveal placement, the held silence — lives in story-structures ch. 23d; this chapter is the production mechanics.)
🟢 **Audio first, face second:** lock the answer as AUDIO before any video — script + voice profile (post-audio-legal ch. 18), then generate the talking head TO the finished track (a lip-sync/avatar tool driven by the finished audio track — a route outside rule 1's stills-as-reference doctrine; post-audio-legal ch. 18), never hoping the video model speaks it right. Write authenticity into the script: fillers, restarts, thinking pauses (an "um" in the dialogue's language, a breath, a false start) — a read-clean answer sounds scripted and kills the documentary contract.
🟢 **The B-roll escape is the lip-sync budget:** real docs cover 60–80% of an answer with cutaways that PROVE the narration — for AI this is the cost weapon: only the opening, the key sentence, and the close stay on-camera; everything between runs under B-roll. Short lip-sync stretches, generated B-roll, huge quality gain per credit.
🟢 **Coverage convention:** two framings per subject from the SAME side of the interviewer axis (wide ↔ tight — the doc version of production-pipeline ch. 7 framing recycling) so answers cut internally; eyeline just off-lens, consistent side per person across ALL their segments; opposing speakers get opposing look sides — the edit builds the debate.
🟢 **Staging patterns — pick ONE per person and keep it for the whole film:**
- **Classic off-lens single** (the default; coverage convention above) — subject 3/4 to camera, answering an unseen interviewer just past the lens.
- **Shot/counter-shot with visible interviewer** — stage it as a production-pipeline ch. 7 dialogue scene: reverse plates, 180° lock, question on camera, answer as the reverse; over-shoulder variants sell presence. The interviewer is a cast asset (sheet + voice profile). "Noddies" — silent listening/nod inserts of the interviewer — are an AI gift: no lip-sync, cheap to generate, and they hide take seams exactly like any cutaway.
- **Direct-to-lens (Interrotron pattern)** — subject speaks straight into the camera; confessional intensity (true-crime/portrait signature). Production bonus: frontal talking heads are what lip-sync/avatar paths handle best — the most reliable staging for long on-camera answers.
- **In-situ / walk-and-talk** — the subject interviewed inside their activity (workshop, kitchen, walking); answers fragment naturally over action, giving short lip-sync stretches by design.
🟢 **B-roll taxonomy + the cut grammar that binds it:** four insert classes — process (hands at work: mid shots, not close-ups — red-list) · environment (place, signage, the classic transit/"walking to" shot) · evidence/archive (documents and era-matched material — in-frame-text rules, style-control §6b era looks) · emotional return (back to the face for the key sentence). Integration is ALWAYS audio-led: J-cut INTO the answer (B-roll first, the voice already speaking), L-cut OUT of the face (voice continues under B-roll). The interview audio track is the spine; the picture leaves it and returns to the face for openings, emotional peaks, and the close.
🟢 **Synthetic interviewees:** fictional witnesses get casting sheets + voice profiles like any character (production-pipeline ch. 3); consistent wardrobe/setting per person, with deliberate small variation between "interview days" as an authenticity cue. Because soundbites scatter across the film in any order (ch. 23d paper edit), either keep ONE look per person, or assign every soundbite to its look BEFORE generation and track it in the continuity ledger — a bite that jumps looks mid-act reads as a continuity error, not authenticity. Real persons: consent + disclosure rules (ch. 20) BEFORE any generation.
🟡 **Presenter / talking head from your OWN reference clip [H-off, P67 — vendor tutorial, Higgsfield MCP]:** the inverse of audio-first: a short clip of the presenter (face, voice, gestures, framing, studio) is the reference and the model generates each take with its own voice. Rules that the vendor states: (1) connection test first — inspect the tools, generate ONE short sample, check that the reference reached the model, the output came back and the clip is usable; (2) split the script into short takes of one complete thought ending at a sentence boundary, so a wrong sentence is regenerated alone; (3) two-section prompt — how the presenter looks and sounds (clothes, desk, background, camera angle) in one section, ONLY the spoken words in the other, plus "start promptly, finish the sentence, leave a small clean hold"; (4) presenter footage without music or built-in graphics — those are edit layers; (5) do not compute runtime from word count — measure the generated takes on the timeline; (6) review every take against the script (dropped words, added phrase, early ending) and listen for product-name pronunciation in the sample, because a mispronunciation repeats across the film; (7) a take log of number · prompt · result · selected file (= bible section B4b); (8) real interface captures, never generated screenshots; (9) disclose the generated presenter in the piece (ch. 20). Reuse the same direction and the same source clip for every take; only dialogue and timing change.
🟢 **Anti-staged tells:** slightly imperfect framing, a focus breath, audible room tone, environment softly readable behind the subject — a too-clean interview reads as corporate, not witnessed (the style-control §6b four-tell rule applied to interviews). Lower-thirds and archive inserts are post/designed graphics, never generated in-frame (renderability §2; era textures via style-control §6b).

## 8. Geometry inputs (when language won't pin space)
🟢 Ascending: **layout map** (top-down schematic generated as an image, fed as reference) → annotated sketch → arrow annotation on a plate → camera-path line drawing → **full 3D blockout video (strongest form, below)**. "One drawing tells the model what 10 sentences can't." Remove any helper geometry you don't want rendered (video-prompting ch. 14). 🟢 **Vendor-confirmed at both rungs [H-off, P69]:** a giant written as "three times taller" was a different size in every batch until a two-outline pencil sketch (hero's head at the giant's mid-thigh, rendered by GPT Image from the sheet) was attached as a reference — the height ruler of video-prompting ch. 12 as an IMAGE; and a 16-shot train robbery whose geography kept breaking (a horse galloping on the rails, an unrequested jump) held once each problem shot was hand-sketched, saved as an element and attached as its storyboard: "if a problem is about spatial logic, stop describing it and draw it" — the LLM reads geometry from the drawing and story from the text.
🟢 **Blockout trigger rule (all production models):** optional for a location with ONE camera axis and flat geography; mandatory for vertical geography, several camera axes in one location, or a documented geography drift (a take that changed the room). Outside the storyboard-first model the blockout is the top rung of this ladder, reached when a lower rung fails; in the storyboard-first model (workflows W10 stage 6) it is a scheduled stage governed by this rule.
🟢 **3D blockout via the Higgsfield Blender plugin [P18] — the strongest spatial/camera control available:** the free plugin bridges the LLM to Blender; the LLM builds editable gray-box scenes, camera rails, and cuts from natural language — no Blender skills required, and existing keyframes steer the AI directly for those who have them. Workflow: describe scene + shot list → iterate the blocking in words ("more handheld sway", "add texture", "recut scene 3") → viewport-render the blocking (1080p/24/MP4) → attach the render and ask the LLM to **write the video prompt second-by-second matching the clip's camera moves** → generate with the duration set to the blocking length. Documented result class: multi-move camera chains (orbit→profile→top-down), floor-rise and robo-arm moves, and a 6-person/4-cut dialogue with zero seat swaps — first try; the identical prompt WITHOUT the blockout drifted, broke the 180° axis, and burned ~5,000 credits without one clean take.
🟢 **Plugin surface [H-off, P50]:** surface, tabs, credits, connector setup: platform-ui-workflows §1 (Blender add-on row, HF-BRIDGE-MCP row). 🟡 **Camera tab = phone as a tracked virtual camera [P50, launch video 2026-09-02]:** the phone's motion drives Blender's camera over the grey-box scene in real time (the consumer form of the Avatar-era simulcam), the captured handheld path becomes the camera keyframes, and Seedance renders the take from that playblast — shown on a macro ant-colony shot with organic handheld drift. What it changes: the P18 "add a subtle handheld pass in words" becomes a physical performance; operator language (ch. 12 CAMERA) is captured, not described. Untested here; an open community question is whether one captured path can be re-used across generations — treat as yes by design (it is a Blender camera track) but verify.
🟢 **Gray-box rules [P18]:** the blockout controls camera + timing, the references control visuals — keep the split explicit in the prompt ("the gray boxes are [who/what]; visuals come from @refs"). Elements that can't be blocked (liquids, magic) stay BLANK/black in the blockout — the model fills them. Camera follows a separate offset target next to the subject (not locked on the head) for a realistic feel; add a subtle handheld pass in words after the mechanical pass. A followed path with control points is drag-editable — tweak angles in Blender, never by re-prompting.
🟡 **Playblast specifics [P31, sponsored, 2026-08-29]:** export the blocking as a playblast at 1920×1080, 24 fps, MP4/H.264, with viewport overlays (camera paths, guide lines) hidden first. Handoff line that worked: "Write me a 15-second prompt of this establishing shot. I'm using this green box video as a blockout reference, not lighting." Grey figures render literally unless character stills are attached (production-pipeline ch. 8 mandatory companions).
🟢 **The blockout is tool-agnostic — Blender is a convenience, not a requirement [W, researched 2026-08].** Clay Render is a ByteDance REFERENCE CLASS ("textureless 3D models" carrying camera/pacing/shot sizes/trajectory/blocking), not a Blender feature: any tool that stages rough geometry and renders a camera move as a video file qualifies. Evidence tiers: **Blender** (documented baseline; the Higgsfield plugin only removes the manual work) · **Maya / Cinema 4D / SketchUp** (vendor-documented as clay-render sources) · **Unreal Engine 5** (practitioner-proven, pre-plugin era — same principle, more manual) · **iClone/Reallusion AI Studio** (STRONGEST non-Blender lane: official ByteDance creative alliance, native Seedance integration translating "spatial layouts, camera settings, and character animation directly into AI inputs"; also bundles Kling/Veo) · **phone-shot rough blocking** (toys, hands, green-screen staging — vendor-documented as motion/staging guides) · plausible-untested: Unity, DAZ, previz apps (Previs Pro/FrameForge/Cine Tracer), game captures, web-3D. Choose by what the team already knows.
🟢 **Agent-driven blockout, end to end, on the vendor's own channel [H-off, P66, 2026-09-12]:** a ChatGPT session (GPT-6 Astra) with the Higgsfield plugin ("add Higgsfield / use Blender" from the chat's plugin menu) built five blockouts in Blender from prose — room, character path, an editable camera curve with a handheld-drift pass, the target tracked on the character's spine — checked its own viewport through computer use, cloned and revised a scene on request, generated the references through the Higgsfield MCP (the opening blocking frame → Nano Banana as LAYOUT reference for the location plate; Soul Cinema for a location; character sheets from a photo), exported the blocking as the motion reference video and ran Seedance 2.5 at 30 s, two versions per take, from the same chat. What the vendor keeps in prose, not in the blockout: the choreography of 66 dancers ("so the model keeps their movement fluid instead of copying the stiff blocking") — the role split of the mandatory-companions rule above. Five protocols from the same video, each a blockout use case: **(a) seamless loop** — build the loop in the blockout and check that the last frame connects to the first BEFORE generating; one base image (generated from the blocking's opening frame) serves as the reference for both boundary frames; the nested-miniature variant (the room sits on a table inside a copy of itself) makes the loop a hook. **(b) impossible mirror pass-through** — a mirrored twin of the set with both characters moving in sync, the "mirror" an opening the camera backs through; one 15-s continuous take (renderability §2 mirror row rescue). **(c) multi-location continuous take** — street → stairs → corridor → kitchen → casino in one 30 s, camera and character paths separate and adjustable, roles colour-coded in the blockout (black = man, white = woman, yellow = kitchen staff), plates and sheets for the leads attached, the staff and guests described in prose — ⚠️ counter-evidence to the 2.0-era one-location-per-take rule (video-prompting 14b, P28), valid WITH a clay render, not for text-only prompting. **(d) formation crowds** — 66 dancers as boxes in rings (10/20/36) plus a distinct shape for the singer, the cut sequence (close-ups, wides, overheads, dolly, push-ins) pre-cut in Blender; positions and facing come from the boxes, movement from the prompt; the formation held across every camera move. **(e) scale + impossible transition in one take** — a 10-cm hero chased by a vacuum, sucked through the hose, the camera pulling back through the clear dust bin to the product reveal; camera size and focal length change inside the take, all planned as one path. The blocking file stays the revision surface for client changes (two-halves principle, P18). **3D Jutsu** (browser blockout, `HF-WEB`): build and adjust the scene in the browser with the assistant in chat, separate camera and character paths, colour and asset edits by chat or by hand, then send the blocking to Seedance — or start from a REFERENCE VIDEO and let 3D Jutsu extract the blocking and camera move from the footage (🟡 behaviour as shown, not receipted; platform-ui-workflows §1).
🟢 **Vendor-proven on a stylized short [H-off, P23]:** Higgsfield's "Passport Rush" ran storyboard (motion arrows, shot numbers) → Blender previs → AI, with the previs as a COLOURED low-poly blockout (colour identity of vehicles carried into the final, geometry not) and its camera moves and cuts reproduced 1:1 in the render; wide shots were rescued by transition from a close/medium inside the take, silent faces hidden behind reflective glass, style unified by naming the character as style donor. Full case: pixar-look §10.
🟢 **Register the layout schematic as an element [H-off, P48]:** a GPT-Image-2.5 schematic drawn WITH the location attached ("mark the fire hydrant, lock the sky dancer to its right, two times a person's height, on the same line") is saved as a named element and reused across scenes ("lock him to the right of the sky dancer using the scene-three schematic"). 🟡 **X/Y frame coordinates [H-off, P47, Seedance 2.0 claim, untested]:** the vendor's system prompt splits the frame into X/Y axes ("20 % on X, 30 % on Y — place the character right here") — a rung below the layout map for POSITION in video; not the same as canvas-fraction SIZE, which image-model-logic forbids — fails the 12h numeral lint; admissible only as a logged draft-take experiment, never in a delivered prompt; the layout map above is the doctrine rung.
🟡 **Seedance-generated clay base — the cheapest blockout source [P21]:** generate the blockout itself as a Seedance 2.5 `t2v` at 480p with the look stated as "textureless white 3D render, flat matte lighting, minimal detail, motion-graphics feel" (the STYLE line of a Caption Spine; the STYLE & RENDERING block in technique B), then re-skin it with the clay clip attached as @Video plus product/character/environment image refs at 720p — per the ch. 14b mode routing this is `omni_reference` (a new take steered by a source video); ⚠️ the practitioner ran it through the "Seedance 2.5 Edit" entry, which locks duration/ratio to the source and bills its full length — verify which mode the live form exposes for a video-steered re-skin before a paid run. No 3D software involved. Proven on product spots (shoe, phone, laptop, apparel, glasses), two-character fights, driving sequences (rally car → buggy or tank, with the vehicle's text/graphics held), destruction/rebuild, creature swaps (stock birds → dragons); stock footage can first be converted INTO the clay style and then re-skinned (the restyle path, style-control §5b). Rules learned: a shape mismatch between base and reference is tolerated (the result adapts to the new design); extra graphics from a ref must be named ("add the holograms from the image"); geometry can contradict itself (a window seen from inside, none outside) — lint the base before re-skinning; harvest a frame of the base into an image model to design the skin (anti-drift ladder step 3). Base clips become a reusable animation library ("the driving folder"); sharpen the result in the upscale pass (post-audio-legal ch. 17).
🟢 **Blockout-video requirements (multi-source):** textureless is the design intent — cubes + a mannequin suffice, low sample count fine, viewport render is enough · **3–5 s per camera move recommended; split longer paths across generations** · total video-reference budget ≈30 s per request (platform-dependent) · match 24 fps (Seedance output is 24 fps fixed) · trajectory is FOLLOWED, not frame-copied — leave creative room, never demand a blind copy · **label every important shape in the prompt** ("the cylinder in the centre is a robot") · strip UI overlays, path lines, gizmos (they render as content, ch. 14). 🟡 1080p/MP4/H.264 playblast specs are community practice, not doctrine.
🟢 **Mandatory companions — the official role split [BD-off]:** the clay render carries ONLY camera/staging; character sheets, a background/location image, and a style still carry the visuals — ByteDance's own pattern: "Refer to @Clay Render 1 for camera movement… Refer to @Image 2 for character design, scene, materials, lighting, color." Without image refs the gray figures render literally 🟡. **Lighting belongs to the IMAGE reference's role line, never the clay render's** — the model derives physically plausible light from the geometry on its own; assigning the lighting job to the blockout invites the gray look into the take.
🟢 **Budget discipline:** validate the blockout-driven prompt at 480p draft first (structure test, not quality test), then render at target. One-shotting off a blockout is the aspiration, not the norm — a documented production case still ran 16 takes; the blockout's real win is that camera/staging stop being the reroll reason.
🟡 **Published worked material:** Higgsfield's "Seedance 4K Breakdown" publishes a full film's per-scene prompts with second-by-second timing, the @-tagged asset references, and a downloadable prompt-writer skill (portable outside Higgsfield) — image-reference-driven, no blockout, but the closest official worked example of the prompt format. The Blender-plugin launch material itself ships setup + the 4-step loop only, no templates.
🟢 **Two-halves principle [P18]:** every blocking-driven prompt has a structural half (the reference video: cuts, camera, timing — never changes) and a style half (what the world looks like). Client notes and restyles touch ONLY one half: recut the blocking for structural notes, swap the style layer for a different world — one edit renders as 2.5D, flat 2D, or toy-box 3D with frame-matched camera. Pitch workflow: three visual worlds on one approved edit in a day.

## 9. Alternative production paths
🟢 **Two storyboard roles — never mixed:** (1) storyboard as PLANNING artefact — the storyboard-first model (workflows W10; shape in ch. 2): panels are look-free checking views and never enter a generation, geometry comes from the layout map and the blockout (ch. 8); (2) storyboard as GENERATION input — the storyboard-to-sequence path below: cheap pre-viz for projects without anchors and blockout, not final control.
🟢 **Storyboard-to-sequence:** a clean storyboard grid (<15 panels, clean line art, minimal text, stated reading order, grid style excluded) drives a sequence at ~70–80% adherence — cheap pre-viz, not final control. **Higgsfield Popcorn** is the platform's sequence-aware storyboard generator: Auto (one prompt → arc) or Manual (per-frame direction), up to 8 frames/run, longer arcs via bridge-frame chaining (last frame = next run's reference), 1–4 reference inputs, export toward video models. [H-off] — receipted `HF-WEB@2026-09-04` (Image → Popcorn, help-center article modified 2026-08-28).
🟢 **Copy-ready storyboard prompt template [G2-gallery]:** "A [6]-panel film storyboard laid out as a [3×2] grid, landscape 16:9. Each panel is a rectangular pencil-and-marker sketch with a white margin border and a small information strip underneath. Scene: [one-line sequence description]. Panel 1 — [SHOT TYPE + content]. Info: 'PANEL 1 · [INT/EXT. LOCATION · TIME] · [WIDE/OTS/CU/LOW ANGLE] / [static|pan left|tilt up|crane down] / [2s]' … [repeat per panel] … Art direction: classic animation-school storyboard — pencil line-work, grey marker shading, red-pencil arrow annotations for camera moves and action arcs, off-white paper texture." The per-panel info strips (shot type / camera move / duration / SFX) are exactly the panel annotations Seedance reads as direction (storyboard-to-sequence above); the arrow annotations double as geometry input on this generation path (role 2 above; in the storyboard-first model the geometry input is the blockout, ch. 8). 🟡 [P53]: when the board is generated WITH a character sheet attached, tag the sheet in EVERY panel line of the storyboard prompt (`Panel 3 — @image1 falls …`) or some panels get a stranger; upload the finished board to the video model as a REFERENCE, never as a start frame, and let the video prompt name the beats in panel order.
🟡 **Performance-capture path — act it on a phone, re-skin with the model [P55, P54; lineage: the P24 phone-shot stunt (renderability §3), ch. 8 phone blocking]:** when a beat needs human-grade acting or timing, record it and let Seedance 2.5 replace the performer with the referenced character. Route on Higgsfield: video-model entry "Seedance 2.5 Edit", raw clip in the VIDEO TO EDIT slot, character / wardrobe / prop / set image references addressed by tag (mode: `omni_reference` per ch. 14b; the practitioners used the "Seedance 2.5 Edit" entry — verify on the live form, ch. 8 P21 note). Seven rules that held: (1) script first — decide the character count against who can act; one actor can play two parts on a locked tripod in two passes, overlaid in the NLE BEFORE the run; (2) build the references before recording; (3) record stable whenever passes must overlay, and show every object that will be replaced clearly in frame — the model cannot re-skin what it cannot see; (4) over-act by one notch: the model takes the motion over and flattens it; (5) stitch all raw shots of a scene into ONE ≤30-s clip and run it once instead of one run per shot (the edit bills the source length either way); redo a single failed shot from its raw cut; test at 480p; (6) the model fills what the reference lacks (it added a practical lamp missing from the reference; the entry side flipped) — write those specifics, and keep the raw background simple so the reference maps cleanly; (7) finish with the ch. 17 anti-plastic pass (grain, a small punch-in). Same route: a door opened on the raw clip becomes a portal when the reveal is replaced by a new environment reference [P54]; the P24 stunt rescue in consumer form.
🟢 **VFX hybrid:** shoot real plates, generate elements/extensions; and the inverse **restyle path** (live footage as motion scaffold → full style transfer) — style-control §5b.
🟢 **Extension chains:** forward/backward extension to build beyond single-take limits — boundary-frame contract every round (ch. 14b; boundary-frame source: ch. 14) and the ≈60-s chain ceiling: 30 s source + ONE 30-s round, then re-anchor a NEW generation from the original references instead of extending an extension (ch. 14b). 180 s single-flow is a Dreamina-only Long-video beta with 30-s seams (ch. 14b), not a chain target on Higgsfield. Long single generations (60 s+) only for montage content, not held scenes.
🟢 **Audio-to-video:** a finished audio track (dialogue/music beat) as timing skeleton for generation where supported.

## 10. QA & slop control
🟢 **Five slop tells:** plastic/waxy skin · drifting faces between cuts · AI shimmer on texture · hectic cutting exactly at hard motion (model hiding failure) · a continuous floating camera behind the hero over a long take — third-person video-game read, "real movies don't shoot like that" [H-off, P25]; fix: HARD CUTs, each internal shot on its own named setup and shot-size word; the vendor added a focal length per setup (50/24/85/35 mm) — under rule 7 a deliberate look control listed in Crew choices, not the fix; 12d holds the FOV conversion when a project steers it. Any tell = reject take — tells are pre-emotion hard rejects (verdict order: post-audio-legal ch. 19); among tell-free takes pick by Murch's ladder, film-craft §4.
🟢 **Reject as a TAKE, harvest as COVERAGE [P22; H-off, P25 — two clips from one batch cut into the vendor's final]:** a run with a slop tell is rejected as the shot's take, but its clean 2–4 s are salvaged into the edit exactly like on-set coverage, then repaired/extended (video-prompting ch. 14b) — never bin a whole run for one bad beat. Cost lesson from the same project: a one-minute three-prompt sketch with extensions — the practitioner's spend was an order of magnitude above a single take; cost: read the live estimate before Generate (platform-ui-workflows).
🟢 **Iteration log and the 10–15 rule [H-off, P24]:** generate scene by scene; every iteration is surgical — one line changes (removed first, changed second, added only third — SKILL rule 15), the rest stays word for word — and every run goes into a log (version · what changed · verdict) — the log's home and line format are defined in the production bible template section B9 (production-bible.md 22b); "version" = the Render ID revision (`…__P02`, SKILL ID discipline). The feature film's log had 137 entries and showed which shots fought back (v15, v10, v9); without it you cannot repeat a good shot or know whether a fix was already tried. Ceiling: not there after 10–15 iterations → the problem is not the wording — simplify the SHOT (split in two, remove an action, change the angle). (the 3-per-prompt and 10–15-per-shot levels are both in SKILL rule 15)
🟢 **Prompt fault vs. bad roll [H-off, P25]:** if the MOTION STRUCTURE of a take is right and only polish varies between runs, batch again — do not rewrite ("this wasn't a prompt issue, it was a batching game"). Batches of four: a lone weird take is a roll, four weird takes are the prompt.
🟢 **Feature-scale yield [H-off, P47, P49, Seedance 2.0]:** roughly one usable take per hundred generations at feature quality (≈109k generations, ≈9.5M credits for 90 min; 72 generations for one 10-s shot; 100k credits scrapped after a script change) — plan iteration budgets and script locks accordingly; expect 2.5 to improve the ratio, not to remove it.
🟡 **Regenerate with a different shot menu, not the same prompt [P38]:** for montage/commercial work, takes 2–3 are generated from a re-shuffled shot list so they become coverage, not duplicates — four generations cut into one 30-s spot (3 × 30 s + 1 × 12 s; cost: read the live estimate before Generate, platform-ui-workflows — the practitioner's spend was an order of magnitude above a single take). **Riskiest scene first [P39]:** generate the beat most likely to hit moderation or physics limits before spending on the rest of the film.
🟡 **Exploratory text-only take as a casting source [P57]:** a reference-less t2v run that fails as a take can still yield a cast, a location and a light worth keeping — screenshot the good moments, register them as references and regenerate the structured take from them (anti-drift ladder step 3, ch. 16 rung 2 applied before an approved take exists); the structured re-run still needs ACTION beats per tagged frame, or it stays vague. 🟡 **Two rolls, cut between them [P17]:** for 30-s takes practitioners roll the SAME prompt twice and cut the good halves together in the NLE — the budget form of the batch of four; [P17]'s shortcut — a first roll that is "absolute garbage" means the prompt — is the practitioner's reading, not the house count: judge the batch, one bad roll is a roll (SKILL rule 15). The same finish rule from [P62]: never lay 5–10-s takes end to end — trim, cut, regenerate the bad stretch, re-design the sound.
🟢 **Batch protocol:** generate 4, watch ALL fully (failures teach the next prompt; the director watches when the agent cannot — the agent then collects the six-pass answers rather than narrating a result it has not seen), review in the separate passes of post-audio-legal ch. 19. Review ADJACENT shots together, not clips in isolation — continuity errors live between shots, never inside one. [W]
🟢 **Keeper phases:** draft tier for exploration → standard tier only for near-final prompts → hero renders last.
🟢 **Resolution ladder:** iterate at 480/720p, render finals at target resolution; judge an upscaler on one exported frame before batch-processing (post-audio-legal ch. 17).

## 11. Model choice inside the Seedance family
🟢 "2.5 is a .5 improvement, not a revolution" — choose PER SHOT: 2.0 for UGC realism and cost efficiency; 2.5 for long takes, choreography with weight, in-shot transformations, multi-stage emotion, reflection-heavy scenes, slow controlled camera moves (2.0 overshoots the subject). Draft on the model the production take will run on, at draft resolution (W3 step 5, draft takes) — a draft validates beats AND how this model reads them; 2.0 or a Mini/Fast tier only for a beat-order check on a shot whose production model is not yet chosen, never as the source of a lock.

## 16. Perspective changes & coverage (cost-ranked)
**Core problem:** image models lack true spatial understanding — free-text reverse/new-angle stills of the same scene are unreliable. Video models switch angles reliably WITHIN a take. Hence the ladder — cheap/reliable to expensive/risky; exhaust each rung first — for coverage needed on an EXISTING take. Planned reverse plates (ch. 4) are pre-production (W2 step 3): start with the empty-location walkthrough of ch. 4 when a master plate exists (rung 2, one cheap video); go to rung 3 (angle tool or GPT Image 2.5 + layout map) when the walkthrough fails the reverse test or a layout map already exists.

**Rung 1 — angle changes inside the generation (default):** new angles as **internal shots of the same take** (production-pipeline ch. 2 shot labels, HARD CUTs) — the model holds set and figures because it builds them in one context. Dialogue: framing recycling (production-pipeline ch. 7). By far the cheapest reliable coverage.
**Rung 2 — harvest angles from existing video:** screenshots from a successful generation are the best references for follow-up angles (light, palette, geography already correct); on a route WITHOUT an extension mode: last frame as start frame + "continue forward, do not replay" (rule 1 case a); on Seedance 2.5: `video_extension` from the source clip, the harvested frame only as the writing aid for the boundary state (ch. 14b). 🟢 2.5 camera-perspective editing — now official with a worked prompt ("Keep the characters, actions, and visual style unchanged. Adjust only the camera movement" + segmented camera plan; video-prompting ch. 14b) — a B-camera pass on an approved performance; [PP]-unproven, budget one test. Same class: Runway Aleph "generate new camera angles" on real footage.
**Rung 3 — dedicated image tools instead of free-text reverse:** when an angle is needed as a STILL: never "same scene from behind" via free text — use a purpose-built angle tool (below — undated, verify first) or GPT Image 2.5 WITH a layout map/master plate as input. Reverse test afterward: anchors, openings, light side, palette must match the master plate. Planned dialogue sets: pre-produce the multi-plate system (platforms-models ch. 13b) — 2–3 plates save dozens of failed generations.
**Rung 4 — geometry inputs** (production-pipeline ch. 8) when nothing pins.
