## 1. Pipeline principles
🟢 **Stills-first:** every shot exists as an approved still before any video generation. The look is won in the image; video inherits it. Cheap iteration happens at the image stage.
🟢 **The approved still is a REFERENCE anchor, not a start frame [PP, P22]:** by default the anchor is attached as an @Image reference (look, geometry, blocking) next to sheet and plate, and the take opens already in motion (video-prompting ch. 12). A literal start frame (i2v / first-frame slot) is doctrine ONLY where a take must join an existing clip frame-exactly: chunking a long sequence at the model's maximum take length on a route without an extension mode, or a first/last-frame interpolation between two approved stills of the SAME shot (ch. 16 Start & End Frame — a move, not acting); on Seedance 2.5 forward/backward continuation runs as `video_extension` from the source clip, not from a harvested frame (video-prompting ch. 14b). Everywhere else start and end frames are more often a problem than a help — they carry the still's posed, plastic quality into motion, freeze a composition the model would otherwise develop, and force a static opening the trim rule cuts anyway. Off-doctrine use only when the director explicitly knows they need frame-exact continuity: state the trade-off once, then follow the call. **Multi-shot take (SKILL rule 2):** attach EVERY internal shot's approved anchor, each with its job scoped to its own shot and time range — "@anchor_1A controls look, geometry and blocking of SHOT 1 (0–5 s) only; @anchor_1B controls framing and blocking of SHOT 2 only, from the HARD CUT at 5 s — not before" — so only shot 1's anchor can shape the opening frame (12b plate-pinning). This is the sanctioned exception to 12b's "never place an @tag in a shot where that object is not present": the tag IS present in its own shot; the time scope keeps it out of the others.
🟢 **Vendor-proven at feature length [H-off, P24]:** Higgsfield's 110-minute "The Cully Hill Boys" (Aug 2026, $2M, open-sourced) ran on ONE condition: text-to-video only — no start frame, no image-to-video; every shot born from references plus text, "the assets carry the picture, the wording carries everything else, including the geometry". Stated reason: harder, but the shots cut together. The single exception was a phone-shot stunt clip used as motion reference (renderability §3). Their five production rules: (1) assets first — nothing generates until every face, place and prop is locked; (2) describe everything, every time — the model has no memory (everything = scene, action, geometry, locks; IDENTITY stays in the sheet plus the minimal anchor line, video-prompting 12b — never long appearance prose); (3) change one thing at a time; (4) give the model less freedom — a corner, not a room, a map, not guesswork; (5) shot won't land? simplify the shot, not the words.
🟢 **Order: location plates → characters → props → composite stills → motion tests → production takes.** Characters are shot INTO approved plates, never invented alongside them.
🟢 **Inverted order for Pixar/stylized projects (hard rule) [PP]:** stylized environments generated WITHOUT a figure default to photoreal on every image model — because stylized-feature environments are themselves near-photoreal, the model has nothing to stylize against. The figure in frame forces the whole render into the stylized mode; figure + environment together IS the look. Build order therefore inverts: (1) character sheets (neutral grey, no location needed) → (2) location ANCHOR plates generated WITH a figure in frame → (3) empty location backgrounds derived via edit model (remove the figure — the style stays baked in). Alternative for figure-less environment stills: the prompt-only style-forcing method (pixar-look §9) — reliable in bright light; dark scenes need a self-generated bright style anchor. Applies to Pixar and comparable stylized-3D looks; photoreal projects keep the location-first order above.
🟡 **Figure-anchored plate straight into video, with a scale-only role line [P32]:** instead of deriving an empty plate first, the figure-anchored plate can be attached to the video generation as is — role line verbatim: "the figure already standing in @Image 2 is used only as a scale reference to establish her correct proportional size relative to the buildings; do not treat it as a separate character or duplicate her; only one [name] exists". Saves the derivation step; the risk it manages is the duplicate character.
🟢 **Review loop:** generate → review against acceptance criteria → fix the weakest instruction in the NEXT prompt (not only in post) → regenerate. Acceptance criteria always include the project's Verify line next to the shot-specific criteria — the chosen recipe's Verify line (director-recipes), or, where no recipe was chosen, the DEFAULT VERIFY LINE written with the style anchor (workflows W1 step 5) — a take can be technically clean and still off-style. Worth knowing: a defect accepted at the still stage propagates into motion, so a still that is "close enough" often costs more later — the user decides when it is good enough to move on.
🟢 **Sheets vs. in-scene stills:** reference sheets (neutral light) maximize consistency; in-scene stills (scene light) maximize realism. Both exist; sheets feed identity, in-scene stills feed the take.
🟢 **Label discipline:** every asset gets a stable ID (@name) reused verbatim in prompts, filenames, and the continuity ledger (post-audio-legal ch. 19).
🟢 **The reference pool is a project deliverable (Seedance 2.5) [BD-off]:** beyond sheets and plates, build the casting pool out deliberately — wardrobe details, prop stills, style stills, motion clips, voice/audio refs, clay blockouts — ONE reference for every element that must stay consistent anywhere in the production. Per-scene selection then draws from a complete pool instead of improvising prose; an element controlled only by text will drift. Capacity and doctrine: video-prompting ch. 14b.
🟢 **Approved anchor stills are assets too [PP]:** register every APPROVED shot anchor as a named element in the platform library (tag = shot ID: `@anchor_1A`), exactly like characters, locations, and props — video prompts then address it by tag instead of manual image attachment. (Platforms without an element library keep the same tag as a versioned file re-attached per run — production-bible 22c.) Loose anchor images accumulate over a production and manual re-attachment becomes a growing error source (wrong version, wrong shot). Only the final approved anchor is registered; rejected variants never are.

## 2. Script & treatment for generability
Before stage one: the story intake gate and container choice (story-structures ch. 23) — the story comes from the user; the container decision precedes the treatment.
🟢 Write the script in stages: logline → treatment → shot-level script; at each stage run a renderability pass (renderability.md) and cut or rescue red elements — rescue cuts are a writing tool, not a defeat. Candidate-synopsis ideation happens ONLY when the user asks for story help (story-structures 23a) — then labeled PROPOSALS per 23a, never a ten-synopsis batch unasked; the story comes from the user.
🟢 **Deliverable shapes (copy these; do not invent columns):** TREATMENT = Title · Logline · Premise · Container (story-structures ch. 23) · Format / length / platform · Style anchor (the project style-contract paragraph, SKILL.md Workflow step 4) · Synopsis (≤1 page) · Scenes — each: heading (INT/EXT · place · time), beat prose written cause→effect, then the SKILL.md shot table (`| Shot ID | Len | Framing | Action | Assets | Risk | Rescue |`) · Pre-production: Set build (locations + locks + reverse decision) / Casting (sheet orders; expression sheets for animation) / Props (state pairs) · Risk register (SKILL rule 10 shape). SHOT-LEVEL SCRIPT / SHOT LIST = the same shot table, one row per shot, with Shot IDs that are canon for the bible shot board; dialogue lines verbatim in the Action cell with the speaker named. "Screenplay"/"Drehbuch" = the shot-level script by default; standard screenplay page format only when the user explicitly asks for it, and then still followed by the shot table per scene.
🟢 **Single shot is the default for calm beats [H-off, P47]:** multishot only where action or dialogue must be dynamic — "for pretty much everything else, single shot". Reconciled with SKILL rule 2 ("generate in sequences, 2–3 internal shots"): the sequence take is the unit for beats that need a cut to hold pace or coverage; a quiet single-event beat is ONE shot in one take, not a padded sequence. 🟢 **Complexity budget per take:** one primary event per shot; 1–3 shots per 15/30-s take — one for a calm beat, 2–3 with explicit labels ("Shot 1/2/3") and HARD CUT markers where a cut is needed (montage/commercial exception: up to 12–15 cuts per 30 s, video-prompting ch. 14b).
🟢 Open on a hook (first 2 s earn the rest); write endings as their own beat with its own time range.

## 3. Characters
🟢 **Minimal sheet:** front, side, back, face close-up, clothing detail — one character per image, neutral even light, plain background. 🟢 Official course variant: a 3-view sheet (full-body front, full-body back, frontal close-up) generated FROM a reference photo on a grey background — the close-up is what locks the face. 🟢 **Defensive anatomy locks are official practice:** character prompts carry insurance lines ("Both arms whole and both hands normal, intact human hands — no missing limbs") and anti-sheen skin lines ("skin matte and low-sheen — no oily highlights, no specular hotspots") — pre-empting the two most common character defects. [H-off Stage 2] **One-face rule:** exactly one canonical face; never let a second "almost right" face into any reference set.
🟢 **Which sheet to order (selector):** photoreal / licensed likeness → headless 3-panel + two portraits (below) · animation → one pose + 8 expressions [P17] · stylized 3D → CG turnaround (below, P23) · the 5-panel minimal sheet → stills-only or discovery work. Whatever the format, ONE clean face source per character is the invariant.
🟢 **Headless bodies, two portraits — the feature-film sheet [H-off, P24; independently reproduced by P28, P38]:** three panels — full body front, full body back, one LARGE close portrait in 3/4 view. Remove the heads from the full-body panels: the small, soft face on a wide panel is exactly the face the model copies into wide shots, badly; with the heads gone, the close portrait is the only face source. Make TWO close-ups, with and without a smile — otherwise the model invents the teeth and the smile arrives as somebody else's mouth. For licensed real people the sheet is built from contract photography (the actor's face, not a type) and only the sheet ever enters a shot.
🟢 **State sheets:** any persistent change (wet, wounded, dirty, costume change) is a NEW sheet order, never a prompt adjective. The ledger (post-audio-legal ch. 19) tracks which state sheet each shot uses.
🟢 **One asset per state, and a lock test before canon [H-off, P24]:** a hero has as many assets as states he passes through (clean jacket → wet after the river → split brow and blood on the tee); mixing states in one text makes blood fade in and out and jackets return. Every asset passes a stress test before it is locked: ten generations in different poses and light, recognisable in ten of ten (the source does not name the medium; default to image-model stills at draft tier — cheap — and use short motion tests only for an asset whose identity lives in motion) — a fail means the description is wrong, not the model. "Splitting is cheaper than arguing."
🟢 **Asset A/B before lock — one fixed prompt, one swapped variable [H-off, P48]:** keep 2–3 sheet candidates, run the SAME motion-test prompt every time and swap only the hero (or only the location); Soul Cinema sheets on grey ("win rate is way higher on grey"); the verbatim erase step for the headless sheet in GPT Image 2: "Erase the face from the full body shot on the right panel". LLM-side reference: screenshot a liked moment and give it to the prompt-writing LLM (not the generator) as positioning/lighting context for the next prompts [H-off, P47].
🟢 **Anti-drift ladder:** (1) sheet as reference in every generation, (2) verbatim identity anchor line in every prompt, (3) frame-harvest a well-liked generation as an additional reference, (4) if drift persists: regenerate the sheet, don't patch outputs.
🟡 **Type descriptions pull a famous face [P37]:** "rugged, 40s, weathered fisherman" returned a recognisable actor; the fix was a reference photo plus DELETING all physical text — keep only what the headshot cannot show (wardrobe). Also: never write mapping labels ("John") into the sheet image itself — causes confusion and duplication [BD-off, ModelArk 2.5 guide]. Scope: this concerns the description that SUBSTITUTES for a face reference. It does not shorten the 12b anchor line (🟢, applies to every video prompt): keep age, build, current state, unique visible features and the positive imperfection locks below — those are concrete, this-face facts. What pulled the famous face was the evaluative TYPE stack ("rugged", "weathered") standing in for a reference; with the sheet attached, replace type adjectives by concrete features and never by nothing.
🟢 **The face close-up is the identity carrier — sheets stay clean:** anything that occludes or degrades the face in the sheet (overlays, veils, grids, heavy stylization) costs likeness in EVERY generation downstream. 🟡 Measured once [P19]: a light scratch overlay on Seedance 2.5 cost ≈15–20 % of the likeness across three paired scenes. If a platform refuses a real face, route via the moderation plan in post-audio-legal ch. 20 (test acceptance first, alternative route, face-grid fallback with its stated limits) — never quietly ship a degraded sheet as the project's identity source.
🟡 **Strip small non-identity accessories from the sheet [P20]:** tiny details (a small hat, a thin chain, a pin) don't render sharp in video and can shift the character's features as the model tries to hold them — remove them from the sheet and add them per shot only where the story needs them. Sheet model choice: the Seedream 5.0 Pro note under the table in ch. 5.
🟡 **Beautification drift is a failure class [P19, P20]:** models push faces toward symmetry and polish ("turned up the handsomeness slider"). Lock imperfections POSITIVELY in the anchor line — bags under the eyes, uneven hairline, visible pores, the asymmetry — and give the sheet a reference role line ("@hero controls face and body only, exactly as in the sheet"); a bare-noun negative field is the only other channel, per the ch. 24f table. Realism is imperfection — the uncanny valley is the too-perfect face, not the flawed one.
🟢 Voice: the sheet locks the voice along with the face on audio-capable models — accept the native voice where it fits; otherwise replace via the voice pipeline (post-audio-legal ch. 18).
🟢 **Animation sheet variant [P17]:** for ANIMATION projects, expressions beat views — animated video carries far more facial expression than cinematic footage. Layout: one full-body pose + 8 distinct expression panels (instead of the multi-view emphasis); the video model draws on the expression range during acting. Cinematic/photoreal projects keep the multi-view sheet above.
🟢 **CG-turnaround sheet for 3D-stylized projects [H-off, P23]:** A-pose front + back full body plus a large face close-up, neutral background, rendered as a finished 3D character — this sheet sets the project's stylization level and doubles as the style donor for painted environments (pixar-look §8, §10). Identity-bearing small props (glasses, cap) stay on the sheet; only non-identity clutter is stripped.
🟢 **Crowd sheet:** one multi-variant sheet (6–12 distinct extras) referenced for background population — prevents clone crowds.
🟢 **Large casts: single-view stills for cameos, sheets only for leads [BD-off; P40]:** multi-view sheets for 10–13 characters in one 30-s take produced "twins"; switching cameo characters to single-view single shots (sheets kept for the two leads) mostly fixed it — the official ">5 subjects → single-view images" rule confirmed in production. Reconciled with the casting system (video-prompting ch. 14): the upfront mapping block lists EVERY reference once (identity binding only); the ACTION text mentions each cameo only at its beat (an unmentioned character never shows, a vaguely mentioned one is replaced by a look-alike) and add the exit clause to POSITIVE LOCKS: "each referenced character appears only during their described encounter and must not reappear after @hero has passed them". Wardrobe stays in words even when it is on the sheet (a red shirt migrated to another character); an instrument visible on a reference gets played — state it.

### Asset order — the deliverable shape
An asset order is delivered like every executable prompt: a Render Slate (SKILL.md rule 10) directly above a standalone still-prompt code block — ONE slate + block per @tag and per state. For orders the slate carries three extra rows after `Inputs`: `Format` — which sheet/plate/pair per the selector above + the state ("headless 3-panel + 2 portraits · state: wet"); `Locks` — the defensive lines written verbatim into the prompt (one canonical face · both arms whole, both hands intact · skin matte, low-sheen · identity props kept: … · clutter stripped: …); `Register as` — `@tag · type · status draft` (→ bible section B3; approved on the director's call, locked only after the 10/10 stress test above). In the treatment's pre-production section (SKILL.md Workflow step 4) list every order as one line — `@tag · type · format · states · reference source · reverse decision (locations only)` — the slates + prompts follow in the asset-order deliverable.
🟢 **Headless 3-panel + two portraits (the photoreal/likeness default, above) — three prompts:** (1) Sheet: "Character reference sheet on a plain neutral grey background, landscape 16:9, three panels separated by white gutters. Panel 1 (left): full-body front view, A-pose, [wardrobe/state]. Panel 2 (centre): full-body back view, same pose and wardrobe. Panel 3 (right, largest): close portrait in 3/4 view, neutral expression, mouth closed — [3–5 face-defining features incl. imperfections, e.g. uneven hairline, bags under the eyes, visible pores]. Even neutral studio light, no shadows on the face; skin matte and low-sheen — no oily highlights, no specular hotspots. Both arms whole and both hands normal, intact human hands — no missing limbs. Identity props kept: [list]; no other accessories; no text, no labels." (2) Edit on the approved sheet: "Erase the face from the full-body shots in panels 1 and 2; keep everything else identical." (3) Edit for the second portrait: "Same character as the reference, identical framing and light: the close portrait now smiling with teeth visible." Register (2) as the sheet and (3) as a second portrait under the same @tag; a state change = a new run of (1)–(3).
🟢 **Location plate set (ch. 4):** Master: "[Location], seen from [camera position and height], the [anchor object] at [position in frame], [light source] from [left/right], white balance [K], one exposure, no people, no text. [project style block]". Detail ×2–3: "Detail plate, same location as @image1 (controls materials, light side, palette — do not copy its framing): [object], same exposure and white balance [K]." Reverse (only when the reverse decision says yes): NOT free text — ch. 16 rung 3: a purpose-built angle tool or GPT Image 2 with the master plate + a layout map attached, prompt "Same room as @image1 (controls layout, materials, light side, palette — do not copy its framing), seen from the opposite side of the [named axis]; the [anchor object] visible at [position]; same light side, exposure and white balance [K]; no people, no text"; then the reverse test (anchors, openings, light side, palette).
🟢 **Prop state pair (ch. 4):** Still A: "[Prop], [state before], [framing/lens], [light], plain background, no text." Still B as an EDIT of the approved A: "Same object, identical framing, light and background; the only change: [state after]." Two separate stills, registered as @prop_a / @prop_b (never one two-panel image).

### Copy-ready sheet & board templates [G2-gallery]
🟢 **Character reference sheet — gallery / stills-only variant (works verbatim; ⚠️ multi-face, no dedicated close-up — NOT for video identity work: order the headless sheet above instead):** "Based on this character [reference attached], create a character reference sheet similar to official setting materials: three-view drawings (front, side, back) · facial expression variations · detailed parts breakdown of clothing and equipment · a color palette · organized layout, white background, [style] illustration." Adapt the style word; keep the structure.
🟢 **Expression grid (feeds the expression-sheet order):** "Create a [N]-panel expression grid of [character, reference attached]. Face shape, hairstyle, and clothing must remain highly consistent across all panels. Expressions: [list them explicitly — happy, sad, angry, surprised, shy, contemplative, scared…]." Naming each expression beats "various emotions".
🟢 **Multi-variant cast grid (THE crowd-sheet tool):** "A single landscape image containing a clean [2×5] character grid. Each panel shows a different [role archetype list — one distinct hairstyle, outfit, prop, and expression each]. Keep all panels consistent in art direction: [style tokens], tidy white gutters, small name tag per panel — a collectible cast-sheet feel." Distinct archetypes per panel prevent clone crowds; the shared art-direction line prevents style drift across panels.
🟢 **Multi-panel consistency rules (all grids/sheets/boards):** state the grid count exactly (3×3, 2×5, 16-panel) · give each panel a role or beat · one shared art-direction sentence covering all panels · white gutters + per-panel labels where identification matters. Structure (canvas, ratio, grid) goes BEFORE subject description — otherwise the model spends its detail budget on the subject and improvises the layout.

## 4. Locations & props
🟢 **Generate locations for the camera angles you will need, never frontal [H-off, P24]:** a frontal room picture is flat wallpaper — the model cannot read volume from it and invents new surroundings past the frame edges every time. Leave one anchor object in every location and tie all staging to it ("the hero at the lamp, facing the door" works; "the hero in the room" is a lottery). **Location kit from one plate (photoreal projects; stylized 3D: figure-anchored plate first, production-pipeline ch. 1, or the walkthrough defaults to photoreal):** generate a video of the EMPTY location with the camera slowly walking through — the model draws the other sides of the room to match the plate; harvest frames as the reverse/side plates (ch. 16 rung 2).
🟢 **Views as separate images, assigned per cut [H-off, P47, P48]:** front and back views are separate stills (never stacked into one composite — the vendor retracted its own two-view collage), each assigned in the prompt ("cut 1 uses the front view, cut 2 the back view"); a ceiling-corner "CCTV" angle is a third useful plate. **Prop sheets for tricky anatomy:** a monster claw kept rendering as a held sword until a prop sheet showed the arm "from the outside and from the inside" — the durable fix behind the 12f staging trick. **Multi-face props** (a wall of twelve Polaroids) break every face in one generation — one face per generation, assembled in an editor.
🟢 Per location: one master wide plate + 2–3 detail plates at ONE shared exposure/palette. **Reverse decision up front:** does this location need counter-angles (dialogue, cross-room action)? → build the multi-plate set (platforms-models ch. 13b). Pass-through/B-roll → one wide suffices. Missing reverse plates ordered late are the most expensive single mistake in the pipeline (ch. 16).
🟢 Props with narrative state changes get a **state pair/series of stills** (before/after), treated like character state sheets.
🟢 **Prop size in composites is set by relation or mask, never by canvas fractions** ("% of image width" is meaningless to an image model) — size mechanics: style-control §2; full control ladders: image-model-logic ch. 24.
🟢 Screenshot workaround: frames from an approved video generation are legitimate (often superior) plate sources — they carry light and geography correctly.

🟡 **Seedream 5.0 Pro — where it earns its place [P17][P20][P22]:** sheets from scratch (single source, [P17]) and sheets FROM a reference image at 2K ([P20], who moved off GPT Image 2 because its sheets read noisy and degrade through image→video passes); scene plates with cinematic imperfection — overexposure, halation, glow around hot sources — that carries into the video ([P22]). ⚠️ Faces invented from scratch: [P22] reports misses and keeps Nano Banana Pro for faces — use Seedream for plates and reference-driven sheets, Nano Banana Pro when a face must be invented. ⚠️ Counter-report [P41, sponsored]: Nano Banana Pro gives "plasticky skin", GPT Image 2 preferred for sheets from a photo — the sheet-model question is unsettled across practitioners; judge on the ten-of-ten stress test (production-pipeline ch. 3), not on the model name.
🟢 **Every image edit costs quality — composite instead of re-editing [H-off, P48]:** "every time you edit an asset the quality takes a hit — that's exactly how you get the flat, plastic AI-slop look". Official fix: keep the ORIGINAL still on top in any photo editor, the edited version below, and mask only the changed part (outfit, prop) — face, skin and background stay from the original. Companion facts [H-off, P49]: a context image handed to an image model is COMPOSITED, not read (a city plate for an interior yields a room outdoors — give context to the LLM, not the generator); edit chains decay after ~3 rounds (details drop, objects stop placing) → describe the liked layout and regenerate from scratch (style-control §2 three-edit rule). Still-side anti-plastic levers on Nano Banana Pro: light atmospheric haze, film grain, crushed blacks, a colder cast 🟡.

🟢 **Mix and match per asset [P17]:** no single image model wins across a project — pick per asset and compare; image credits are cheap, video credits are not: "spend more time getting the best image than fixing it in video generations."

## 6. Video prompting basics
🟢 **Keep list (officially rewarded):** subject specificity, active verbs with direction/speed, scene with time-of-day/weather, ONE committed visual style, one camera verb per shot, audio always described.
🟢 Choreography beats adjectives: write micro-cues (eyes, brows, mouth, breathing, hands) instead of emotion labels; cause before reaction (contact → movement → sound → reaction) — never leave the causal link to the model.
🟢 Timestamps are pacing budgets, not frame guarantees; a timestamped beat = short take.
🟢 **Position lock:** state where every subject starts, faces, and ends.
🟢 **Audio:** describe diegetic sound naturally; **always exclude music** ("original fictional score" only where a score is wanted as diegetic; the real score is built in post, post-audio-legal ch. 18).

## 7. Dialogue scenes
🟢 **Framing recycling:** exactly two repeated framings (single ↔ over-shoulder); "shot 3 repeats shot 1's framing" — repetition is what sells coverage.
🟢 Reverse-environment references are mandatory (multi-plate, platforms-models ch. 13b); **180° lock:** name the axis and forbid crossing it in every dialogue prompt. Strongest spatial lock for multi-person dialogue: the 3D blockout path (production-pipeline ch. 8) — seat positions, eye-lines, and cuts pre-decided in gray boxes hold where text-only prompting swaps seats [P18].
🟢 One line per shot beat; speaker tags per platform syntax (video-prompting ch. 12 · platforms-models ch. 21); never two characters speaking simultaneously.

## 7b. Interview scenes (documentary path)
(Dramaturgy of interviews — voice functions, contradiction editing, hook/reveal placement, the held silence — lives in story-structures ch. 23d; this chapter is the production mechanics.)
🟢 **Audio first, face second:** lock the answer as AUDIO before any video — script + voice profile (post-audio-legal ch. 18), then generate the talking head TO the finished track (lip-synced i2v/avatar path), never hoping the video model speaks it right. Write authenticity into the script: fillers, restarts, thinking pauses (an "um" in the dialogue's language, a breath, a false start) — a read-clean answer sounds scripted and kills the documentary contract.
🟢 **The B-roll escape is the lip-sync budget:** real docs cover 60–80% of an answer with cutaways that PROVE the narration — for AI this is the cost weapon: only the opening, the key sentence, and the close stay on-camera; everything between runs under B-roll. Short lip-sync stretches, generated B-roll, huge quality gain per credit.
🟢 **Coverage convention:** two framings per subject from the SAME side of the interviewer axis (wide ↔ tight — the doc version of production-pipeline ch. 7 framing recycling) so answers cut internally; eyeline just off-lens, consistent side per person across ALL their segments; opposing speakers get opposing look sides — the edit builds the debate.
🟢 **Staging patterns — pick ONE per person and keep it for the whole film:**
- **Classic off-lens single** (the default; coverage convention above) — subject 3/4 to camera, answering an unseen interviewer just past the lens.
- **Shot/counter-shot with visible interviewer** — stage it as a production-pipeline ch. 7 dialogue scene: reverse plates, 180° lock, question on camera, answer as the reverse; over-shoulder variants sell presence. The interviewer is a cast asset (sheet + voice profile). "Noddies" — silent listening/nod inserts of the interviewer — are an AI gift: no lip-sync, cheap to generate, and they hide take seams exactly like any cutaway.
- **Direct-to-lens (Interrotron pattern)** — subject speaks straight into the camera; confessional intensity (true-crime/portrait signature). Production bonus: frontal talking heads are what lip-sync/avatar paths handle best — the most reliable staging for long on-camera answers.
- **In-situ / walk-and-talk** — the subject interviewed inside their activity (workshop, kitchen, walking); answers fragment naturally over action, giving short lip-sync stretches by design.
🟢 **B-roll taxonomy + the cut grammar that binds it:** four insert classes — process (hands at work: mid shots, not close-ups — red-list) · environment (place, signage, the classic transit/"walking to" shot) · evidence/archive (documents and era-matched material — in-frame-text rules, style-control §6b era looks) · emotional return (back to the face for the key sentence). Integration is ALWAYS audio-led: J-cut INTO the answer (B-roll first, the voice already speaking), L-cut OUT of the face (voice continues under B-roll). The interview audio track is the spine; the picture leaves it and returns to the face for openings, emotional peaks, and the close.
🟢 **Synthetic interviewees:** fictional witnesses get casting sheets + voice profiles like any character (production-pipeline ch. 3); consistent wardrobe/setting per person, with deliberate small variation between "interview days" as an authenticity cue. Because soundbites scatter across the film in any order (ch. 23d paper edit), either keep ONE look per person, or assign every soundbite to its look BEFORE generation and track it in the continuity ledger — a bite that jumps looks mid-act reads as a continuity error, not authenticity. Real persons: consent + disclosure rules (ch. 20) BEFORE any generation.
🟢 **Anti-staged tells:** slightly imperfect framing, a focus breath, audible room tone, environment softly readable behind the subject — a too-clean interview reads as corporate, not witnessed (the §6b four-tell logic applied to interviews). Lower-thirds and archive inserts are post/designed graphics, never generated in-frame (renderability §2; era textures via style-control §6b).

🟡 **Seedance-generated clay base — the cheapest blockout source [P21]:** generate the blockout itself as a Seedance 2.5 `t2v` at 480p with a STYLE & RENDERING block ("textureless white 3D render, flat matte lighting, minimal detail, motion-graphics feel"), then re-skin it with the clay clip attached as @Video plus product/character/environment image refs at 720p — per the ch. 14b mode routing this is `omni_reference` (a new take steered by a source video); ⚠️ the practitioner ran it through the "Seedance 2.5 Edit" entry, which locks duration/ratio to the source and bills its full length — verify which mode the live form exposes for a video-steered re-skin before a paid run. No 3D software involved. Proven on product spots (shoe, phone, laptop, apparel, glasses), two-character fights, driving sequences (rally car → buggy or tank, with the vehicle's text/graphics held), destruction/rebuild, creature swaps (stock birds → dragons); stock footage can first be converted INTO the clay style and then re-skinned (the restyle path, style-control §5b). Rules learned: a shape mismatch between base and reference is tolerated (the result adapts to the new design); extra graphics from a ref must be named ("add the holograms from the image"); geometry can contradict itself (a window seen from inside, none outside) — lint the base before re-skinning; harvest a frame of the base into an image model to design the skin (anti-drift ladder step 3). Base clips become a reusable animation library ("the driving folder"); sharpen the result in the upscale pass (post-audio-legal ch. 17).
🟢 **Blockout-video requirements (multi-source):** textureless is the design intent — cubes + a mannequin suffice, low sample count fine, viewport render is enough · **3–5 s per camera move recommended; split longer paths across generations** · total video-reference budget ≈30 s per request (platform-dependent) · match 24 fps (Seedance output is 24 fps fixed) · trajectory is FOLLOWED, not frame-copied — leave creative room, never demand a blind copy · **label every important shape in the prompt** ("the cylinder in the centre is a robot") · strip UI overlays, path lines, gizmos (they render as content, ch. 14). 🟡 1080p/MP4/H.264 playblast specs are community practice, not doctrine.
🟢 **Mandatory companions — the official role split [BD-off]:** the clay render carries ONLY camera/staging; character sheets, a background/location image, and a style still carry the visuals — ByteDance's own pattern: "Refer to @Clay Render 1 for camera movement… Refer to @Image 2 for character design, scene, materials, lighting, color." Without image refs the gray figures render literally 🟡. **Lighting belongs to the IMAGE reference's role line, never the clay render's** — the model derives physically plausible light from the geometry on its own; assigning the lighting job to the blockout invites the gray look into the take.
🟢 **Budget discipline:** validate the blockout-driven prompt at 480p draft first (structure test, not quality test), then render at target. One-shotting off a blockout is the aspiration, not the norm — a documented production case still ran 16 takes; the blockout's real win is that camera/staging stop being the reroll reason.
🟡 **Published worked material:** Higgsfield's "Seedance 4K Breakdown" publishes a full film's per-scene prompts with second-by-second timing, the @-tagged asset references, and a downloadable prompt-writer skill (portable outside Higgsfield) — image-reference-driven, no blockout, but the closest official worked example of the prompt format. The Blender-plugin launch material itself ships setup + the 4-step loop only, no templates.
🟢 **Two-halves principle [P18]:** every blocking-driven prompt has a structural half (the reference video: cuts, camera, timing — never changes) and a style half (what the world looks like). Client notes and restyles touch ONLY one half: recut the blocking for structural notes, swap the style layer for a different world — one edit renders as 2.5D, flat 2D, or toy-box 3D with frame-matched camera. Pitch workflow: three visual worlds on one approved edit in a day.

## 10. QA & slop control
🟢 **Five slop tells:** plastic/waxy skin · drifting faces between cuts · AI shimmer on texture · hectic cutting exactly at hard motion (model hiding failure) · a continuous floating camera behind the hero over a long take — third-person video-game read, "real movies don't shoot like that" [H-off, P25]; fix: hard cuts with their own setups (vendor wrote 50/24/85/35 mm; FOVs 47°/84°/29°/63° are our 12d conversion). Any tell = reject take — tells are pre-emotion hard rejects (verdict order: post-audio-legal ch. 19); among tell-free takes pick by Murch's ladder, film-craft §4.
🟢 **Reject as a TAKE, harvest as COVERAGE [P22; H-off, P25 — two clips from one batch cut into the vendor's final]:** a run with a slop tell is rejected as the shot's take, but its clean 2–4 s are salvaged into the edit exactly like on-set coverage, then repaired/extended (video-prompting ch. 14b) — never bin a whole run for one bad beat. Cost lesson from the same project: a one-minute three-prompt sketch with extensions cost the practitioner ≈800 credits on Higgsfield (Aug 2026) — an order of magnitude, not a planning number; read the live estimate before Generate (platform-ui-workflows). Temporary "unlimited Seedance 2.5" promos for new accounts exist — verify before budgeting around them.
🟢 **Iteration log and the 10–15 rule [H-off, P24]:** generate scene by scene; every iteration is surgical — one line changes, the rest stays word for word — and every run goes into a log (version · what changed · verdict) — the log's home and line format are defined in the production bible template section B9 (production-bible.md 22b); "version" = the Render ID revision (`…__P02`, SKILL ID discipline). The feature film's log had 137 entries and showed which shots fought back (v15, v10, v9); without it you cannot repeat a good shot or know whether a fix was already tried. Ceiling: not there after 10–15 iterations → the problem is not the wording — simplify the SHOT (split in two, remove an action, change the angle). ⚠️ Reconciled with SKILL rule 14: rule 14's "never patch the same prompt past 3 iterations" governs a single prompt text (rewrite from scratch after 3); the 10–15 ceiling is the total budget per shot across rewrites and channel changes, after which the shot itself is simplified.
🟢 **Prompt fault vs. bad roll [H-off, P25]:** if the MOTION STRUCTURE of a take is right and only polish varies between runs, batch again — do not rewrite ("this wasn't a prompt issue, it was a batching game"). Batches of four: a lone weird take is a roll, four weird takes are the prompt.
🟢 **Feature-scale yield [H-off, P47, P49, Seedance 2.0]:** roughly one usable take per hundred generations at feature quality (≈109k generations, ≈9.5M credits for 90 min; 72 generations for one 10-s shot; 100k credits scrapped after a script change) — plan iteration budgets and script locks accordingly; expect 2.5 to improve the ratio, not to remove it.
🟡 **Regenerate with a different shot menu, not the same prompt [P38]:** for montage/commercial work, takes 2–3 are generated from a re-shuffled shot list so they become coverage, not duplicates — four generations cut into one 30-s spot (3 × 30 s + 1 × 12 s ≈ 660 credits at 720p, Higgsfield, Aug 2026 — order of magnitude only). **Riskiest scene first [P39]:** generate the beat most likely to hit moderation or physics limits before spending on the rest of the film.
🟢 **Batch protocol:** generate 4, watch ALL fully (failures teach the next prompt; the director watches when the agent cannot — the agent then collects the six-pass answers rather than narrating a result it has not seen), review in the separate passes of post-audio-legal ch. 19. Review ADJACENT shots together, not clips in isolation — continuity errors live between shots, never inside one. [W]
🟢 **Keeper phases:** draft tier for exploration → standard tier only for near-final prompts → hero renders last.
🟢 **Resolution ladder:** iterate at 480/720p, render finals at target resolution; judge an upscaler on one exported frame before batch-processing (post-audio-legal ch. 17).

## 16. Perspective changes & coverage (cost-ranked)
**Core problem:** image models lack true spatial understanding — free-text reverse/new-angle stills of the same scene are unreliable. Video models switch angles reliably WITHIN a take. Hence the ladder — cheap/reliable to expensive/risky; exhaust each rung first — for coverage needed on an EXISTING take. Planned reverse plates (production-pipeline ch. 4 reverse decision) skip to rung 3 in pre-production (W2 step 3):

**Rung 1 — angle changes inside the generation (default):** new angles as **internal shots of the same take** (production-pipeline ch. 2 shot labels, HARD CUTs) — the model holds set and figures because it builds them in one context. Dialogue: framing recycling (production-pipeline ch. 7). By far the cheapest reliable coverage.
**Rung 2 — harvest angles from existing video:** screenshots from a successful generation are the best references for follow-up angles (light, palette, geography already correct); last frame + "continue forward, do not replay". 🟢 2.5 camera-perspective editing — now official with a worked prompt ("Keep the characters, actions, and visual style unchanged. Adjust only the camera movement" + segmented camera plan; video-prompting ch. 14b) — a B-camera pass on an approved performance; [PP]-unproven, budget one test. Same class: Runway Aleph "generate new camera angles" on real footage.
**Rung 3 — dedicated image tools instead of free-text reverse:** when an angle is needed as a STILL: never "same scene from behind" via free text — use a purpose-built angle tool (below — undated, verify first) or GPT Image 2 WITH a layout map/master plate as input. Reverse test afterward: anchors, openings, light side, palette must match the master plate. Planned dialogue sets: pre-produce the multi-plate system (platforms-models ch. 13b) — 2–3 plates save dozens of failed generations.
**Rung 4 — geometry inputs** (production-pipeline ch. 8) when nothing pins.
**Per location, worth deciding up front:** whether it needs reverse angles (production-pipeline ch. 4) — settling it early is cheaper than discovering it mid-production, but it stays the user's call.
