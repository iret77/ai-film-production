## Prompting techniques — the menu (SKILL rule 4; read before ch. 12 / 12h / style-control §6c)

The skill offers three prompt shapes for video and prescribes none as a default: **the technique is a project decision**, taken with the director at intake together with the project type, the basic look and the video model (selection protocol below; SKILL rule 4, Workflow step 1, W1 step 3, production-bible section B1). In every technique the economy doctrine and the division of labour bind (SKILL.md): the prompt states only what is necessary or deliberately steered, nothing twice, no contradictions, nothing out of distrust; every video prompt ships with the `Lint` row (12h). Length is not limited: a prompt that states what belongs in it, once, limits itself (12h, "What belongs in the prompt").

Model containers do not change with the technique: MiniMax H3 keeps its official field schema (platforms-models ch. 21, the technique's content rules inside the fields); Veo 3.1 puts the camera first (Google's formula); camera-first on Kling 3.x and style-qualifier-first on Grok Imagine are 🟡 practitioner recommendations, not vendor rules (12g). Seedance 2.0 know-how holds on 2.5 unless a documented difference says otherwise (14b version table): timecode beats are a 2.5 form — on 2.0 the beats are numbered shots. **Selection protocol:** (1) at intake the director and the agent name the candidate — usually one: A for a clear beat, B when the project will steer many axes, C for a medium look; (2) if two candidates remain, generate ONE representative beat in both at draft tier (batch of 4 each, same references — W3 step 5 settings) and judge by the six passes; (3) record the winner with the frame decisions — it is a project constant, changed only by a documented decision, never per prompt; (4) never two techniques in one prompt, never a technique argued from a model version.

**Binding for every technique.**

**Core principle — write the visible.** The model reacts to what can be seen and measured, not to mood words. Translate every abstraction into something observable: not "tense scene" but "man freezes, slowly clenches his fist, light only from the side, half his face in shadow". Fewer precise words beat many vague ones. Before generating, mentally *watch* the prompt: is the first frame non-empty, is it clear where each subject is and looks, where the light comes from.

**Output is a single standalone prompt in a code block.** Each generation is a blank slate with no memory of other shots — a prompt is a sealed single-shot document. Never carry in scene numbers, script headings, prior-scene summaries, "as above / continues" phrasing, or unused tags/characters/props.

## 12. The prompt block structure — technique B (explicit per-axis control)

**Technique B of the SKILL rule-4 menu** — chosen per project with the director, never a default, never tied to a model version: Seedance 2.x (documented version differences: 14b table), Cinema Studio, and — with the reordered spine of 12g — Kling, Veo and Grok; H3 keeps its official schema (ch. 21) and is never adapted. It is the officially documented Seedance block system: each concern has one home, nothing is forgotten, nothing collides. Fit, price and evidence: the menu row above; the measured failure of habit-filled blocks: 12h evidence. The economy doctrine binds inside B: a block carries only what is necessary or deliberately steered, a lock lives once, a value is written because the look needs it, nothing is written out of distrust.

### Block order — ● = the skeleton of technique B (written when the take has something necessary or deliberately steered for it) · ○ = only when the shot needs it. Never rename a block; a block with nothing necessary or deliberately steered is omitted, never padded (economy doctrine). No word ceiling: a block carries what belongs in it, once (12h); a platform's own prompt cap is a technical limit (Dreamina: 5,000 characters, 14b); a revision is never longer than the one before (SKILL rule 15).
```
● SCENE CONTEXT       1–2 sentences: what happens, where, when. Geo-positions of characters.
● ACTIVE REFERENCES   (whenever anything is attached — style-control §7 Rule 0) one line per attached reference,
                      fixed shape: "@tag controls only <one job> — <minimal anchor>. 100% matches the reference.
                      Do not copy <non-transfer>." — the exclusion only after that non-transfer has occurred
                      in a run (economy doctrine). Anchor content by class: character = role/build,
                      current state, 2–4 unique visible features, action-critical details (voice only if it
                      speaks); plate = layout + light side; prop = shape + state; style still = rendering
                      signals only.
○ LOCATION MAP        (written whenever two or more characters share the frame — the model cannot guess
                      their geography; and when a camera move is deliberately steered) foreground /
                      midground / background; where the camera sits; movement paths (the light source lives
                      in LIGHTING only).
                      Naturalistic colour can live here.
○ FIRST FRAME/BLOCKING (written in the chain case, where the first frame must match the previous end state,
                      and for two or more characters, whose opening positions and gaze the model cannot
                      guess) who is where in the first frame: positions, orientation, gaze. Composition rule
                      for THIS scene.
● FORMAT MODE         one continuous shot / sequential cuts / timed multishot (segment syntax: ACTION block
                      below; cut budget 1–3 shots per take: production-pipeline ch. 2; montage exception 12–15
                      cuts: 14b; total runtime of a multishot take goes here).
● OPTICS              shot size as a word; FOV° per segment and lens character only as deliberate look
                      controls (12d, rule 7); where a FOV is steered on a multishot take, it is stated per
                      segment and protected once with "no drift mid-segment" — the negation exists only for
                      a written FOV value.
○ CAMERA              (only where continuity across internal cuts or the canon demands it, or as a
                      deliberate steer — Division of labour) operator behaviour: height and distance as
                      relations to things in frame (rule 7), movement, focus; camera-body tonal character
                      as a LOOK, not a model name.
● ACTION              events at the precision the shot needs; camera motion and subject motion stated
                      separately; cause before reaction. Multishot takes segment it as "SHOT 1 (0.0–5.0 s): …
                      HARD CUT. SHOT 2 (5.0–10.0 s): …" — ranges consecutive and non-overlapping, one primary
                      event per shot, match-cut lock 12f. A take declared ONE continuous shot uses relative
                      timing ("three seconds after …") and end states, never stamped segments (14b).
○ PERFORMANCE         (when acting matters) muscle-level emotion, precise eye-line, catch-lights,
                    breath, pore-level skin realism.
○ PHYSICS             (when it matters) mass, inertia, contact shadows, fluids, particles.
● LIGHTING            source, direction, exposure, key/fill, haze — priority block.
○ COLOR GRADE         (only when the grade is strong/stylised) palette as material + light + role;
                    omit for naturalistic looks and fold colour into LOCATION/LIGHTING.
○ WARDROBE            (when costume matters) material + condition, scene-logical.
● AUDIO               only the needed sound / line, in ONE 12b audio notation — the diegetic list, plus the
                      music exclusion once when the take runs with audio on (rule 10).
● ENDING STATE        MANDATORY on every take: the last frame as a still description — who is where, facing
                      what, prop states, light state. The next take / extension starts from this text
                      (ch. 14 state chaining). Never a dramatic peak here.
● STYLE               technical-style suffix: overall look in words, photoreal, format, grain.
○ OUTPUT SETTINGS     (only for aspects the platform exposes NO control for) anamorphic squeeze, real-time vs
                      slow-mo per segment, frame-rate LOOK in words — never ratio, duration or resolution: those
                      are platform settings and live in the Render Slate (SKILL slate).
● POSITIVE LOCKS      locks stated nowhere else in the prompt — a lock lives ONCE, here or in its block,
                      never in both (economy doctrine); continuity lives here. Typical: subject count, the
                      state that changes in this take, the load-carrying style aspect.
```

### Complete example — the delivered shape of technique B (Seedance 2.x, sequence take S1: three internal shots; the same take as a Caption Spine: worked-example.md §3b)
Block names in CAPITALS followed by a colon, one block per paragraph, in the ch. 12 order; optional blocks the shot does not need are omitted, never renamed or left empty. The Render Slate that must sit above every delivered prompt (SKILL rule 11) is omitted here; see worked-example.md §3 for the full delivery.
```
SCENE CONTEXT: Night, rain, lamp room of a lighthouse. @cat has just slipped in through the hatch and will push the brass lever to relight the dark lamp above.
ACTIVE REFERENCES: @anchor_1A is the opening composition of SHOT 1 (0.0–4.0 s) and of SHOT 3 (7.0–10.0 s); the take opens already in motion. @anchor_1B is the opening composition of SHOT 2, from the HARD CUT at 4.0 s onward. @cat controls only the cat — small grey tabby, wet clumped fur, white chest patch, green eyes, one notch in the left ear. 100% matches the reference. @loc_lamproom controls only the set. 100% matches the reference. @prop_lever controls only the lever — shape, state: down. 100% matches the reference.
LOCATION MAP: foreground wet floorboards; midground the brass lever on the right wall, the hatch on the left wall; background rain-streaked windows, the dark lamp above centre. Camera in the rear-left corner of the room.
FIRST FRAME/BLOCKING: the cat mid-squeeze through the half-open hatch, body toward frame centre, gaze up at the lamp.
FORMAT MODE: sequential cuts, three shots, 10 s total — Shot 1 0.0–4.0 s, Shot 2 4.0–7.0 s, Shot 3 7.0–10.0 s.
OPTICS: Shots 1 and 3 medium-wide at 63°; Shot 2 close-up at 47°; soft rounded rendering.
CAMERA: Shots 1 and 3 static, lens at the height of the cat's shoulders; Shot 2 static, lens level with the lever and close enough that the lever fills the frame's height.
ACTION: SHOT 1 (0.0–4.0 s): the cat lands on the floorboards, shakes rain off in two shakes — droplets catch the window light — then looks up at the lamp. HARD CUT; the cat's pose at the end of Shot 1 exactly matches its start in Shot 2. SHOT 2 (4.0–7.0 s): the cat rears up and pushes the brass lever with both forepaws and its whole body weight; the lever tips up with one heavy clunk; only then a warm glow blooms from above. HARD CUT. SHOT 3 (7.0–10.0 s): the cat settles onto its haunches in the amber light, eyes widening, ears rising, and goes still.
LIGHTING: Shot 1 one cold key from the windows screen-right, 8500K, low exposure, the cat's far side in shadow; from the ignition in Shot 2 a warm 3200K top light, brighter than the window key, contact shadows under the cat.
AUDIO: <rain on glass, continuous> <two wet shakes> <one heavy metallic clunk at 6.0 s> <low warm hum from the lamp from 6.0 s> No music, no BGM — room tone and effects only.
ENDING STATE: cat seated on its haunches facing the lit lamp, lever up, room in warm amber, rain continuing on the glass.
STYLE: stylized 3D animated-feature look, matte rendered materials, soft global illumination; clean, grain-free image.
POSITIVE LOCKS: exactly one cat in every frame.
```

The four numerals (63°, 47°, 8500K, 3200K) are this take's deliberate look controls — the cold-to-warm turn of a stylized-3D look — and are listed in the slate's `Crew choices` (worked-example.md §3). A take without that look decision writes the shot-size words and "cold window key" / "warm top light" and nothing else (12c/12d scope).

### The three placement rules that make it work
1. **Nothing style-related opens the prompt.** The prompt starts on SCENE CONTEXT / ACTIVE REFERENCES. **There is no style-prefix block** — style is not one thing in one place; each aspect lives in the block that already governs it (light → LIGHTING, colour → COLOR GRADE or LOCATION, optics → OPTICS, acting/skin → PERFORMANCE, physics → PHYSICS). Only *technical* style (grain, frame-rate look, anamorphic character, overall look word — never resolution/ratio/duration, which are slate settings) sits as a short suffix stack (STYLE, OUTPUT SETTINGS) just before POSITIVE LOCKS. (This overrides the "glued style prefix" pattern that Higgsfield's own Shotlist-Director skill emits [H-off, P38] — official output, deliberately not adopted here: in block prompts a keyword prefix ahead of the blocks was ignored while the reference image and per-block placement carried the look; the Caption Spine's STYLE line is a different shape — 8–10 tokens as line 2 of a ≤ 300-word prose prompt — and held in the 12h runs; neither finding transfers to the other technique; style-control §1 and the primacy caveat below.)
2. **CAMERA sits mid-prompt — after the space/subject blocks (SCENE CONTEXT … FORMAT MODE), together with OPTICS, and directly BEFORE ACTION.** In layer terms: space/subject → optics+camera → action → style suffix → locks. Moved to the end, FOV gets ignored; moved to the opening, it fights identity. The block order above is the literal order — never reorder it.
3. **A lock is placed next to what it protects** and phrased positively ("headlights stay glowing in every shot"). Write densely where control matters, sparsely where it doesn't; say each important thing once.

If the user supplies their own prefix or block text, use it verbatim. Technique C (style-control §6c) is a separate technique — a Master Style Block followed by a short prose-beat story part; it never carries the ch. 12 blocks.

🟡 **Primacy caveat ⚠️ [P22]:** a practitioner skill (Cinema Director v3, Aug 2026) AND Higgsfield's own Shotlist-Director skill [H-off, P38] top-load shot count, total runtime, per-shot timing AND the technical look stack at the very top, arguing the model holds what comes first. The structural facts already sit at the top of this template — FORMAT MODE carries shot count and the per-shot time budget, SCENE CONTEXT what happens where; put total runtime into FORMAT MODE on multishot takes. The look stack's position stays governed by placement rule 1; move it up only as a documented experiment when a look drifts, never as the default.
🟡 **Prefer opening in motion [P22]:** the FIRST FRAME/BLOCKING block describes a moment already underway (mid-step, mid-gesture, machines running) rather than a pose the character then leaves — a take that starts from stillness reads as posed and adds the soft start the trim rule (post-audio-legal ch. 17) cuts anyway. Exception: the chain case, where the first frame must match the previous clip's end state.
🟡 **Name the ontology of what the model sees [P22]:** a person in an animal suit is written as "a human in a gorilla costume, matte synthetic fur, treated as a costume" — otherwise the model animates a gorilla. The same applies to mannequins, puppets, statues, reflections: say what the thing IS, not only what it looks like (ch. 24b generator logic).
🟢 **Four devices from a feature-film corridor prompt [H-off, P24]:** (1) the **height ruler** — never "taller", always a body landmark: "Horace's eye-line at the level of Cal's mouth"; (2) the **off-screen event** — a kicked door written as a list of concrete objects that must NOT appear (not a limb, not a shadow, not a reflection) — stated once, objects only (⚠️ never style words, never repeated: ch. 14 third class); (3) **different rhythms** — two people react to one event never in sync, a synchronised reaction reads as animation; (4) the speech count lock (12b). Give the model less freedom: a corner, not a room.
🟢 **Anchor the camera to a VIEW TARGET, not to a prop [H-off, P49]:** "camera right next to the fridge" repeatedly moved the fridge toward the camera instead (72 generations); what landed was a view target plus a named part of the reference — "starts with a focus on the dark hallway, parallel tracking … the top-right corner of the top panel". Camera placement is written as what the camera SEES from where, never as adjacency to an object the model may relocate.
🟡 **Community vocabulary sources (unverified as production receipts, checked 2026-09-02 / 2026-09-12) [P20, P59]:** [camera movements](https://aicameramovements.com/) — Dan Kieft's own cheat sheet (P59, 2026-07): 46 moves in seven categories (pan/tilt, zoom/lens, dolly/track, physical, human camera, drone/crane, specials), one copy-ready phrase each in the four-field shape below · [camera angles](https://aicameracontrol.com/) · [emotion direction, 25 copyable emotions](https://seedance-emotion-direction.vercel.app/) · [42 camera movements, AI Shot Studio](https://aishotstudio.com/42-camera-movements-ai-prompts) (P64, Jan 2026, pre-2.0 era: name + one-clause definition per move — the minimal form of the ch. 14 "translate the technique" rule; useful for the terms the other lists lack: vertigo / zolly, hyperlapse, barrel roll, worm's-eye tracking, reveal-from-blur, through shot, cosmic hyper zoom) — phrase banks for the CAMERA and PERFORMANCE blocks, never production receipts.
🟡 **Four-field camera phrase [P59]:** every move written as `<move>. Movement: <what the camera physically does>. Speed: <pace>. Framing: <what stays readable / how the composition changes>. End: <the settled final framing>.` — e.g. `dolly in. Movement: move the camera physically forward in a straight line toward the main subject. Speed: smooth controlled push. Framing: keep camera height, lens direction and subject position consistent while distance closes. End: finish in a tighter composition.` The End field is the motion endpoint a CAMERA block needs when written (Kling's 99%-hang rule, 12g; the camera's share of ENDING STATE); a deliberately steered 12c/12d value (km/h, FOV°) goes inside the fields; distance stays a relation (rule 7). Use it as the sentence shape of the CAMERA block, one phrase per move, one move per shot (renderability §5).

## 12b. Reference tagging & audio syntax

🟢 **Reference + text split:** the `@tag` image sets appearance and identity; text sets what happens and locks critical details. Both are required. Keep the character description in the prompt MINIMAL — long appearance text conflicts with the image and degrades it. Anchor line format: `@TAG: age + role/build + current state + unique visible features + action-critical details + voice (only if it has a line). 100% matches the reference.` This anchor is the MIDDLE segment of the ACTIVE REFERENCES line (order: job → anchor → "100% matches" → exclusions, the last only after a non-transfer has occurred) — technique B; in a Caption Spine the same facts form the one job sentence (12h). style-control §7 Rules 1–4 and SKILL rule 5 ("job line + exclusions") describe this same single line, never a second one.
🟢 State action-critical details (a logo as a shape, a colour, a damage state) in words even if they appear on the reference — the model can drop them. **Never place an `@tag` in a shot where that object is not present** — the model forces it into frame (the casting-system mapping block is the exception: it binds identities without placing them; placement happens in ACTION at the beat — production-pipeline ch. 3 large casts; second exception: per-shot anchors in a multi-shot take, time-scoped — production-pipeline ch. 1).
🟢 **Tag token rule — the token in the prompt equals, character for character, the label the live surface shows for that input.** Resolve the form BEFORE writing (style-control §7 Rule 2) from the receipt (SKILL rule 17) or the user's pasted UI: Higgsfield → the Element/asset name exactly as registered (`@hero`, `@anchor_1A`; a clay blockout is registered as an Element too and addressed by THAT name — `@Clay Render` is the ByteDance class label, not a Higgsfield token) · ByteDance-documented surfaces (Dreamina, ModelArk/BytePlus) → the guide's forms `@Image 1` / `@Video 1` / `@Audio 1` / `@Clay Render 1` (capitalised class + space + upload index) · other surfaces → the index form their upload hint shows (platforms-models ch. 13 lists Hailuo UI `@Image 1`, fal `Image1`, ComfyUI `<Picture 1>`). `@image1 @video1 @audio1` in this file is the skill's class-neutral shorthand for "index by upload order" — never deliver it as-is unless the surface shows exactly that form. If the surface cannot be seen, deliver the form the user/receipt gave and mark the slate Inputs row `🟡 token form unverified — match the upload label before running`; never invent a form. User's explicit `@tag_name` wins; tags are not portable across platforms.
🟢 **Mode A** @image-tags by upload order; **Mode B** no tags — describe the visible feature ("the woman with the silver streak").
🟢 **Reference budgets (officially confirmed):** ≤8 image subjects (stretch 9–12), ≤5 video/audio subjects, clips 5–10 s; >5 subjects → single-view images, separate angles, never a collage grid. Trim order when over budget: characters > props > scene > style. (Seedance 2.5: 30 images + 10 video + 10 audio per generation across four reference classes incl. `@Clay Render` — build the project pool maximally, select per scene deliberately; full doctrine ch. 14b.)
🟢 **Audio notation — two admissible forms, ONE per prompt (Seedance family: Seedance on Higgsfield/Cinema Studio, Dreamina, BytePlus/ModelArk; other models keep their own syntax — Hailuo `<d>` tags, platforms-models ch. 21; Veo/Kling: plain prose).** (a) **Plain prose with quotation marks** — the form of Higgsfield's official Seedance 2.5 guide and of most official ByteDance examples [H-off, BD-off]: speaker, delivery, then the line in quotes (`The keeper says in a low, tired voice, natural — not exaggerated: "Pull it, Oli."`); sounds as clauses inside the beat or the AUDIO block. (b) **The ByteDance symbols [BD-off: 2.0 guide "Special character standards", 2.5 tutorial "Prompt rules", `sd25-pe`]** — for prompts where content types must be told apart: `( )` = music · `< >` = one sound effect per physical cause, counted (sound-at-event-granularity below) · `{ }` = the spoken line, verbatim, language and delivery written BEFORE the braces · `【 】` = a SUBTITLE meant to appear on screen, never anything else. With `< >` in use, never wrap a subject name in angle brackets. Copy-ready (b): `AUDIO: <rain on the glass, steady> <one metallic clunk as the lever tips> The keeper says in a low, tired voice, natural — not exaggerated: {Pull it, Oli.} No background music, no BGM — room tone and effects only. — the take contains exactly three words.` ⚠️ Corrected in v3.5: this skill used to map the four symbols differently and put the music exclusion inside `【 】` — the vendor's subtitle bracket; no source for that mapping exists. Music is excluded by ONE plain sentence whenever the take runs with audio on — negative control is vendor-documented exactly for audio and subtitles ("No BGM; generate only environmental sounds and action sounds", "No subtitles") [BD-off]: in the AUDIO block (technique B), inside the closing prohibition sentence of a Caption Spine (technique A), inside the terminal list (technique C); never a second music statement (rule 10; the documented-bleed restatement below is the only exception). Storyboard grids/sheets used as references: the job sentence names the figure only ("@cat is the cat on the sheet"); their drawing style and panel borders are excluded once, only after they have transferred in a run (ch. 12 ACTIVE REFERENCES shape).
🟡 **Seedance 2.5 fills unspecified dialogue and blocking with inventions [P19]:** in a paired two-character 30-s dialogue test the model inserted an unprompted spoken line and let one character leave the scene without a motivated beat — while keeping eyelines and the 180° axis correct on its own. Consequence for dialogue takes: the speech count lock below is the default lock on the spoken text; lock the blocking end state in ENDING STATE; an unspecified beat is filled by the model exactly as an unspecified camera is.
🟢 **The speech count lock [H-off, P24]:** state the exact number of words a take contains as its own lock (`"Pull it, Oli." — the take contains exactly three words`) — without it the model adds a mumble or a line in another language; it does not like silence. (Feature-film confirmation of the invented-dialogue note above.) 🟢 **Voice as a fixed conditions block:** in text, the voice is a fixed set of conditions (the reference half of the voice channel — cloned voice / @Audio / P17 clip — is chosen in 14b) — register, tempo, accent, manner — pasted into the audio field VERBATIM every time the character speaks; not even a synonym changes, because new wording widens what the model samples from and the voice drifts. The accent is written phonetically inside the line itself (th → f/v, dropped h, glottal t, -ing → -in'); one character, one accent, never drifts.
🟡 **Exact-lines lock [P52] — a rule-15 escalation, not a default:** when the count lock holds but the model rewords a line in two runs, add once, in AUDIO next to the lines: `keep the exact lines — no paraphrasing, no overlap, no added pauses` (Seedance rewords a line while keeping its sense, which the count lock alone does not catch).
🟢 **Phonetic spelling for names and hard words [H-off, P47]:** write proper nouns as they sound ("Kan-dal-FEE-na", not "Candalfina") — the same channel as the phonetic accent. 🟢 **A plate reference can pin the opening composition [H-off, P49]:** a location/prop reference attached to a shot whose framing should differ made the take open on that frame and "slide" away — attach only plates whose framing the shot actually uses (12b tag rule from the composition side).
🟡 **Sound at event granularity [P20]:** one sound per physical cause, counted and placed — "each step: one closed rubber-sole squeak, then one small wet splash under that foot"; "soft hydraulic door hiss, then one heavy steel slam". Vague sound words return generic ambience. ⚠️ Practitioners also place NON-diegetic hits in-model ("hard sub-bass hit on the frame the light dies") — the model can do it, but the skill keeps score/stingers in post (rule 10): an in-model hit is baked into the mix and cannot be re-timed or replaced.
🟡 **Music bleeding into Seedance 2.5 takes despite the AUDIO exclusion [P22]:** this is the one permitted second statement of an exclusion (SKILL rule 6) — on a documented repeat (music appeared twice), restate the exclusion once in POSITIVE LOCKS (block structure) or inside the affected beat (Caption Spine). ⚠️ Last resort, logged as a primacy experiment because it breaks placement rule 1: prepend "NO MUSIC WHATSOEVER / NO BGM" as the first line — community remedy, reported effective, unverified here; never the default.
🟡 **Verbatim exclusion that held where "no music" failed [P39]:** "No background music, no BGM, no score, no soundtrack, no ambient musical pad. Diegetic room tone and sound effects only." — music bleeds most at action escalations (a sprint, a chase); the string sat at the END of that prompt (⚠️ vs the prepend remedy above — position unsettled, wording is the constant). Generated SFX can be as flat as generated score: mute and re-design in post, not only the music [P39]. Audio uploaded WITHOUT its @tag is used as a voice but speaks gibberish [P40] — address every audio file.

## 12c. Quantification — look controls, never defaults (write measurable where you steer, not everywhere)
⚠️ **Scope (v3.5, SKILL rule 7 — economy doctrine):** the units below are LOOK CONTROLS: written only where the project deliberately steers exactly that aspect for its look — then once, in the beat or block it belongs to, listed in the slate's `Crew choices` — never as a habit for every block, in any technique and on any model version. (The quantified-by-default block prompts were the reject class of the 12h evidence.) Metres, body-lengths and unit counts are not look controls but measures without a referent — never written (SKILL rule 7). What is always valid because it describes rather than measures: left/right from the camera, colour tied to material + light + role, physical environment interaction, emotion as muscle movement, equipment as a look, camera on the shadow side, layered foreground/midground/background.
🟢 Where a value IS steered deliberately, the highest-leverage habit is to replace the adjective with the unit the model can measure:
- **Speeds in km/h:** not "fast/slow" → "moves at 40 km/h", "camera pans at 5 km/h". Second form, vendor-proven [H-off, P25]: a ratio to a known cinematic move — "three times faster than a typical cinematic dolly pull"; camera paths as relations to things in frame ("orbit in from beyond the table's edge to arm's length, dropping from above his head to his chest") — "video models prefer arithmetic over words like *dramatically*".
- **Atmosphere in % or as a visible relation:** not "light fog" → "fog density 40%", "haze swallowing everything beyond the far doorway". Atmosphere builds in STEPS across shots (shot 1: 20% → shot 2: 40% → shot 3: 60%).
- **Giant scale as a relation in the same frame:** not "huge", "three metres tall" or "as tall as four humans stacked" → "towering over the two-storey house beside it" (SKILL rule 7).
- **White balance in Kelvin** — when the look steers it, one value per scene, held across the scene's takes (3200K / 4000K / 5600K / 8500K).
- **Left/right is from the camera.** "Subject moves left" = left from the camera's view.
- **Colour tied to material + light beam + compositional role,** never a flat list: not "the woman wears red" → "crimson silk scarf catching the cold tungsten spill from the corridor".
- **Environment interaction stated physically:** snow melts on skin, rain runs down hair, wind moves fabric.
- **Emotion through muscle movement, not labels** (ch. 14 emotion formula). **Equipment as a look, never gear names** — camera/film/lens model names get ignored or break complex moves (VIDEO rule; for STILLS the vendor endorses photographer language — lens, aperture, stock, halation — style-control §2 [H-off, P47]). **Camera on the shadow side,** operator axis stated (drama doctrine; commercials default to a soft frontal key — genre-baselines Commercial [H-off, P48]). **Background in explicit foreground/midground/background layers.**

## 12d. Optics: shot size + FOV in degrees (the FOV value is a look control, never a default)
⚠️ **Scope (v3.5, SKILL rule 7):** the shot-size word is always written (inside the beat in a Caption Spine, in OPTICS in the block structure); the FOV value only when the project deliberately steers a lens look — then per segment, once, from the anchor table below, listed in `Crew choices`. By default the optics are the model's (Division of labour): the beat names the shot size (one vocabulary, below) and nothing else — no degrees, no millimetres, no distance [PP 2026-09-14].
🟡 **A lens look baked into the anchor still survives only until the first cut [P26]:** a 50 mm swirl-bokeh still held in a single-shot take and was lost the moment a multi-shot take cut away from it — optics must be written in OPTICS per segment (and in the platform's video-side control where it bites), never carried by the still alone.
🟢 Two levers define how a shot is framed: **shot size** and **focal length**. Shot size is one vocabulary, written as the word or its abbreviation, one form per project: insert / extreme close-up (ECU) · close-up (CU) · medium close-up (MCU) · medium (MS) · medium-wide (MWS) · wide (WS) · extreme wide (EWS) — the word in a Caption Spine, either form in blocks. A steered focal length is written as **FOV in degrees** (house unit, tested here) or in mm after a project A/B (divergence note below) — never both units in one prompt.

**FOV anchor table — use only these discrete steps (never "23°" → use 18° or 29°):**
| FOV | mm equiv | Purpose | When |
|---|---|---|---|
| 180° | fisheye | spherical distortion | POV, dream-state |
| 107° | 14–16mm | architectural ultra-wide | huge interiors, epic establish |
| 84° | 20–24mm | wide | establish, group blocking |
| 63° | 28–35mm | observational | wide observation, reportage |
| 47° | 40–50mm | neutral human perspective | universal establish, medium |
| 29° | 75–85mm | portrait compression | medium-isolate, dialogue bust |
| 18° | 100–135mm | natural portrait | close-portrait, identity-preserving |
| 12° | 180–200mm | tele-detail | hands, objects, detail-on-wide |
| 8° | 300–400mm | extreme compression | observation, broadcast |

⚠️ 🟡 **Practitioner divergence — millimetres in video prompts [P51, P58]:** the P51 story prompts and P58's formats carry per-shot focal lengths in mm ("0:06–0:09 — Close-up, 85mm") on Seedance 2.5 and land. This skill keeps degrees as the house unit for VIDEO because it is the channel tested here, not because mm is shown to fail; a project may A/B once and record the winner in the bible — but never both units in one prompt (image-model-logic 24b item 5).

## 12e. Optical technique patterns (copy-ready look controls — each a deliberate steer for a specific look, never a default: economy doctrine)
🟢 **Observation / hidden-camera effect — all three at once:** (1) a foreground occlusion out of focus covering roughly a third of the frame's edge (wall, pillar, branch), (2) atmospheric haze between camera and subject, (3) distance vantage at 8–12° super-tele, operator anchored far away. Change the occlusion type between beats; keep the vantage single.
🟢 **Sports broadcast:** 8° super-tele + fine handheld tremor + "anchored at distance, finding the action".
🟢 **Detail-on-wide (snake cam):** 84° wide FOV + low angle right up against a small object — foreground object exaggerated, background recedes.
🟢 **Hidden occupants behind glass (faces that must stay blank) [H-off, P23]:** "GLASS: all the [vehicle]'s windows are semi-transparent and heavily reflective, sky, road and passing scenery slide across them, and the interior sits in shadow. The [N] passengers are almost invisible, present only as soft dark silhouettes veiled by the reflections and the tint, their poses and gestures readable purely by shape." — the vendor's own fix for silent characters; goes in LIGHTING/OPTICS, the silhouettes' poses in ACTION.
🟢 **Body-rig product shot (snorricam) [H-off, P48]:** "single body rig snorricam locked on the right ear cup. Camera bolted to his body. The headphones rock solid dead centre. Everything behind him whipping past in motion blur." — worked first try; the pattern for any worn product.
🟢 **Intimate wide:** 63–84° wide FOV on a close face — face centred, surroundings readable without blur.
🟢 **Tele compressed air column** (8–12°): "dust suspended in the long compressed air column between camera and subject", "heat shimmer compressed into a wall of haze in front of the figure".

## 12f. Special protocols (any technique — the numeric values inside them are look controls, written only when the beat needs exactly that value; in a Caption Spine the protocol is one sentence inside the beat)
⚠️ **Exception to the nothing-twice rule, scoped to 8°/107° multishot takes only:** 🟢 an extreme-FOV multishot (8° or 107°) needs a 4-mechanism consistency stack or it breaks after 2–3 beats: (1) sequence-wide identity lock — single location reference across all beats; (2) LENS LOCK opener — explicit FOV phrase at the start of each beat; (3) LENS CHECK closer — confirm FOV at the end of the beat; (4) colour via material + light, not a list. All four required.
🟢 **Whip-pan timing:** a whip under 0.8 s renders as a hard cut without blur. Pattern: `0.3s subject A settled → 0.8s WHIP motion-blur transition → 1.4s subject B settled`.
🟢 **Time-speed changes inside a take [BD-off]:** Seedance 2.5 lists bullet time and speed ramp among the camera techniques that are written directly — name the action beat at which the motion accelerates, decelerates or rebounds, and the final hold state (official examples run "In slow motion, …" mid-take). On Seedance 2.0, or when a run of this take shows the ramp smearing, fall back to a hard cut between two speed modes. 🟡 Untested first-party: a selective effect — the world slowed while one character keeps moving normally — written as one beat.
🟢 **Cracks/breaks without impact (anti-impact lock):** "crowd PRESSES, not strikes" · "fracture originates from edge stress, not centre impact" · "no impact point — pressure-based crack" · sequential timing edge-to-centre, not radial from a point.
🟢 **In-shot transformation: hard sub-second duration + mechanical ontology [H-off, P25]:** an unspecified transformation defaults to a glowing anime power-up every time; write "a weapon deploying, not a magic sequence" and a hard number ("0.4 s") — the instant snap is what keeps it real.
🟢 **Contact outcomes by material hierarchy [H-off, P25]:** for blade/impact beats set one hard PHYSICS rule that decides the outcome ("crystal always beats steel" → the steel shatters), write the blade-to-blade distance as a relation ("a hand's width apart, closing"), and describe the geometry of the impact ("a vertical chop meeting a diagonal parry").
🟢 **Match-cut lock across HARD CUTS inside a take [H-off, P25]:** "the poses at the end of shot one exactly match the start of shot two" — spelled out, or the model treats the cut as a brand-new scene and throws the poses away. Same contract as state chaining (ch. 14), applied within one generation.
🟢 **Staging beats banning for anatomy invariants [H-off, P25]:** a monster's blade-arm kept growing a hand and a sword despite "no held objects, no handle"; the fix was to stage the arm INTO view ("he raises his arm") so the model sees the invariant — write the visible (ch. 24b), never the ban.
🟡 **Seamless transition between two approved clips [P57 — the prompt shape for the "seamless transition" mode that 14b lists as documented]:** attach both takes and write `@Video 1 is the before-transition clip, @Video 2 the after-transition clip; keep the character's appearance consistent. At the end of @Video 1: <trigger action>. Camera: <move during the bridge>. <What transforms>. End on the exact opening position of @Video 2; the audio transitions smoothly.` Set the DURATION to the bridge alone (the source used 6 s between two 10-s clips), never the combined length; the result cut cleanly on both sides. Known miss: the receiving environment's scale drifted (a pool read too large) — anchor scale as a visible relation in the bridge text (SKILL rule 7) or attach the location plate.
🟢 **Seamless loop [H-off, P66]:** a take that must replay without a seam is planned in the blockout first — the camera path's last frame is checked against its first BEFORE generating — and ONE base image (derived from the blocking's opening frame) is attached as the reference for both boundary frames; the ENDING STATE is written as the opening frame. The nested-miniature loop (pull back to reveal the room on a table inside a copy of itself, landing on the opening frame) is the vendor's worked example (production-pipeline ch. 8 protocol a).

## 12g. Adapting the block structure to other video models

The block structure (ch. 12) is Seedance/CS-native. Other models want the same *ingredients* — subject, action, scene, camera, lighting, audio, references — but in a **different block order**, and they disagree on one thing above all: **where the camera goes**. Whichever technique the project chose (SKILL rule 4), this table decides where the camera goes: in the block structure keep the ch. 12 blocks and their content rules (12b tagging; 12c/12d values as deliberate look controls) and reorder the opening spine per model; in a Caption Spine the one camera line (optional on Seedance, written in every prompt on Kling and Veo) takes the model's camera position; H3 keeps its own schema. Cross-model camera vocabulary itself is portable (all these models trained on professional film footage); only the ordering and a few model quirks change. [W, multi-source]

**The one rule that flips per model — camera position in the spine:**
| Model | Camera goes | Spine (documented) |
|---|---|---|
| **Seedance / CS** | **mid** (space/subject → OPTICS+CAMERA → action → style → locks) | ch. 12 block order, placement rule 2 |
| **Kling 3.0** | 🟡 **first, recommended** — a practitioner pattern [W]; Kling's own VIDEO 3.0 examples open on the setting or the character, its Omni multi-shot examples on the shot size [K-off] | Caption Spine: the camera line, when written, opens the prompt; block structure: Camera → Scene → Action → Vibe/Lighting → Time/Audio |
| **Veo 3.1** | **FIRST** — Google's official formula leads on cinematography | camera first in every technique — Caption Spine: the one camera line opens the prompt (written on this model in every prompt), beats as range timestamps; block structure: Cinematography → Subject → Action → Context → Style & Ambiance |
| **MiniMax H3** | **do not port** | H3 has an official fixed schema (three-field base form, six-section Ref2VA, `[Shot N] At MM:SS.mmm,` cut points) — write it in that schema verbatim from platforms-models ch. 21 [MM-off], never by adapting ch. 12 blocks |
| **Grok Imagine** | **after action**; 🟡 a leading style qualifier is a practitioner pattern [W] — xAI documents no order, its examples open on the subject or the camera [xAI-off] | Subject → Action → Camera → Scene → Style → Sound → one Constraint (short verb-led for I2V) |

**Per-model adaptation notes:**
🟢 **MiniMax H3** — no block adaptation: the official prompt-writing guides define fixed fields (`integrated_multimodal_description` / `overall_soundscape` / `non_diegetic_music`, and the six-section reference form) with their own tag syntax (`<Subject N>`, `<Picture N>`, `<d>[lang]…</d>`, `(S1)`) — use platforms-models ch. 21 as the template. What carries over from ch. 12: the reference-role discipline (declare each file's job once, then use the bare name), the audio-as-timeline-layer habit, and physical action leading with the camera following.
🟡 **Kling 3.0** — camera first is a practitioner pattern [W] ("Slow dolly push forward" opens the prompt and sets the 3D space), not a vendor rule: Kling's official VIDEO 3.0 examples open on the setting or the character, the 3.0 Omni multi-shot examples on `Shot N (Xs): <shot size>` [K-off]; keep one order per project. Then ground the scene, then ONE subject doing ONE clear thing, then vibe/lighting, then time/audio. Anchor identity in the first sentence and reuse the exact descriptor every prompt of a sequence (Kling interprets each generation independently — platforms-models ch. 21). Element budget: unverified for Kling 3.0 here — read the live Elements panel limit and record it in the receipt; last documented 2.6: ~5–7 distinct elements (treat that as the working ceiling until the live value is known — do not fall back to the 3–4 of pre-2.6 tiers). Over-budget prompts overload and morph. Add a motion endpoint ("…then settles back into place") to prevent the 99%-hang failure. [W]
🟢 **Veo 3.1** — Google's official five-part formula leads on cinematography, then subject, action, context, style & ambiance. Multi-shot in one clip via timestamp prompting (`[00:00–00:02] medium shot, [00:02–00:04] reverse shot`). Physics-correct motion fights stylized looks — prompt the motion grammar (platforms-models ch. 21 / style-control §5b). Native audio (SFX line) is Veo-specific; the visual camera language is portable to the others. [W]
🟡 **Grok Imagine (1.5)** — a style qualifier at the very start is a practitioner pattern [W] for stylized looks (native stylization bias); xAI's documentation gives no order and its examples open on the subject or the camera [xAI-off]. Iterate in passes: structure (subject+action+camera) → style (light/color/texture) → stability (constraints) → variants (3 style variants, keep the most stable). Negatives phrase positively where possible; resolution per the platforms-models ch. 21 Grok line. [W]

**What stays identical across all models:** reference-tag-then-address (12b), one main action + one camera move per shot, cause-before-reaction, and "write the visible"; the 12c/12d values in any technique only as deliberate look controls (SKILL rule 7). Port those unchanged; only reorder the spine and respect each model's camera-position and audio-handling quirk.

## 12h. The Caption Spine — technique A of the prompting-technique menu (SKILL rule 4) 🟢 house doctrine [PP 2026-09-14]

**Scope.** Technique A of the SKILL rule-4 menu — chosen per project with the director, never a one-size-fits-all, never tied to a model version: Seedance 2.5 (`t2v` / `omni_reference` / `video_edit` / `video_extension`, on Higgsfield, Cinema Studio, Dreamina, fal, ModelArk) — and Seedance 2.0 with numbered shots in place of timecode beats, because 2.0 does not respond to timestamps [BD-off, 14b version table] — Veo 3.1 with the camera line first, Kling 3.x by the 12g recommendation, MiniMax H3 inside its official field schema (platforms-models ch. 21). It fits the common case: a beat whose content is clear and whose craft the model can carry. The doctrine behind it is SKILL.md "Economy and division of labour"; the shape is also the vendor's own — the official 2.5 guide builds a prompt as asset referencing → one-sentence summary → plot by timestamps or `Shot N` → notes for what stays constant [BD-off].

**Form — eight elements, in this order, prose, no labels other than the ones printed here; no word ceiling (what belongs: below):**
1. **Title sentence** — one sentence: duration, quality register, genre/register, place. `Create a 10-second stylized 3D animated short inside the dark lamp room of a lighthouse on a rainy night.`
2. **STYLE:** one line, 8–10 short positive tokens: render register, light, material, depth of field, mood, motion register, sound register where it matters. `STYLE: matte rendered materials, soft global illumination, cold window light, wet reflective floorboards, shallow depth of field, hushed mood, slow deliberate motion, room-tone sound.`
3. **Character(s):** one sentence per character, purely visual, the reference token first when a reference exists; closing `Keep <name> visually consistent throughout.` `@cat is a small grey tabby cat with wet clumped fur, a white chest patch, green eyes and a notch in its left ear. Keep the cat visually consistent throughout.`
4. **Location style:** (optional, only with a location reference) one sentence giving the reference exactly one job — `@loc shows the look of the room only` or `@loc is the exact background`.
5. **Camera:** (optional on Seedance and Kling; written in every prompt on Veo 3.1 — per-model placement below) exactly one line, only where continuity across internal cuts or the canon demands it: position, height as a relation, viewing direction, moving or holding still. No focal length, no FOV, no distance in numbers on this line — a deliberately steered lens value lives in the STYLE line or its beat (rule below). `Camera: low, at the height of the cat's shoulders, looking across the floorboards toward the lever; the camera holds still.`
6. **Timecode beats** — 3–6 s per beat, whole seconds, consecutive, without a gap and summing to the duration; ONE main event per beat (a beat may change the shot size). An overfilled window is what produces unrequested cuts or a dropped event, an underfilled one makes the model improvise [BD-off] — so stamps are admissible on a take with internal cuts AND on a take declared ONE continuous shot: a stamp is an event budget, never a cut point (the official 2.5 examples stamp a "single continuous take … no cuts"). Seedance 2.5 knows three timing forms — consecutive ranges, a time point ("at the 5-second mark …"), relative time ("three seconds after …"); use ONE form per prompt and never stamp a high-frequency action. On Seedance 2.0 write `Shot 1 / Shot 2 / Shot 3` without stamps (14b). Each beat carries the shot size as a word inside the sentence (the 12d vocabulary), ONE action written as its start state and its end state, an observable action or expression for every character the beat names (a concrete physical detail, never an emotion word — a named character with nothing to do is filled in by the model), and the sound as part of the beat, diegetic; the character's gaze after the action or an uninvolved object held in a half-sentence only where the canon demands it or a run of this take has shown the drift (rule below). Every beat ends in a resting state. `0–4 s, medium-wide: the cat drops from the hatch onto the floorboards, shakes the rain off and looks up at the lamp; the lever stays down; rain drums on the glass.`
7. **"End with …"** — its own paragraph after the last beat: the closing image and, on the last take of a sequence, the fade-out (no fade-out on a take that will be extended — ch. 14b boundary frame). `End with the cat seated and still beneath the lamp, the room warm amber.`
8. **One prohibition sentence** at the very end: `No dialogue, no subtitles, no text, no music. Maintain <one thing> throughout.` — the music clause whenever the take runs with audio on (rule 10).

**What belongs in the prompt, what does not, and when it is complete (every technique — this replaces a word ceiling).** ByteDance sets no limit and names the fault: "Keep descriptions as concise as possible, avoid redundancy, and avoid semantic conflicts"; "Do not impose a fixed word limit" — compress "repeated style terms, repeated constraints" [BD-off]. The first-party rejects of the over-instructed prompts were prompt faults, not render faults [PP review 2026-09-18]; their eight causes are the checks:
1. **No contradiction inside the prompt** — states, timing, geography and names agree in every paragraph.
2. **Scenic, not technical.** Describe what is seen; a technical term that must stay is written as the term plus its visible result ("Rack focus: the focus shifts smoothly; the trees … become blurred, while the character … gradually becomes clear") [BD-off]; lens, aperture and shutter values only supplement a visible result, they never replace it.
3. **Relations, not measures** (SKILL rule 7) — position and distance relative to stable objects: doors, tables, counters, roads [BD-off].
4. **Acting directions present** — every character a beat names gets an observable action or expression, written as a descriptive sentence.
5. **One timeline** — whole seconds, consecutive, summing to the duration; one main event per beat.
6. **One geography** — the same thing keeps the same name and the same place; spatial relationships go through a reference image first, through words second [BD-off].
7. **Literal wording** — no metaphors, no idioms, no mood adjective standing in for an event; a figurative word pulls the model toward its literal picture.
8. **Working lines are carried forward** — a line that worked in the last approved prompt of this take or sequence stays verbatim; a revision replaces the failing line and drops nothing else.

**Does not belong:** anything on an axis the model owns that is not deliberately steered · a second mention of anything · what an accurate reference already carries ("simply state that it should be referenced and avoid repeatedly describing the scene in detail" [BD-off]) · reasons, explanations, quality words, unrequested constraints · UI settings. **Complete when** it states, each once: what is in the scene and where · what happens in which order and the state each beat ends in · an action for every named character · each reference and its job · the canon facts of this beat · the one camera line where continuity or canon needs it · the sound a beat has · the closing sentence. Stop there.

**Rules of the spine (each one is a measured failure of the over-instructed block prompts [PP]):**
- **One statement per thing.** Nothing is said again in a second paragraph. There is no POSITIVE LOCKS block; a lock is a sentence inside the beat it protects. Scale and distance (SKILL rule 7) are stated once, as a relation between two things in frame.
- **No numbers in prose by default** beyond the timecodes and the duration: no metres, no body-lengths as a unit, no rates ("at the same pace, no part quicker"). A lens, aperture or colour-temperature value only when the project's look needs exactly it (SKILL rule 7) — once, in the STYLE line or the beat it belongs to, listed in `Crew choices`. Which numerals are fixed terms and not numbers: the Lint paragraph below.
- **No explaining to the reader — the goal and a transition contract are part of the form.** No rules ("Rule for this take"), no reasons, no physics lectures, no dramaturgy comments ("the slowness is the tragedy"), no "must read to the audience as": the model receives the description of a film, not notes to a crew (ch. 24b item 1), and ByteDance keeps "the analysis process, evaluation notes … or reasons for changes" out of the prompt [BD-off]. Admissible, once each: the goal sentence that says what the take is (the title sentence — the vendor's one-sentence summary), and a transition contract — trigger point plus method, and what stays aligned across the cut ("At the 5-second mark, the camera quickly transitions leftward using a left wipe combined with a natural dissolve" [BD-off]; the 12f match-cut lock). 🟡 First-party, unverified: a goal sentence may name the turn the take prepares ("… ends by revealing that …").
- **A reference is one job, positively phrased.** `@cat is …` · `@loc shows the look of the room only` · `@anchor_1A is the exact background and the opening composition`. No `Do not copy …` list for a reference used WHOLE — what it must not deliver follows from the job sentence. Measured: with zero exclusion lines, none of four runs showed reference fighting. A reference used IN PART — a video for its motion only, an image for its light only, an audio clip for the voice only — names the part and what is not taken, from the first run: `@Video 1 is used for the hand movement only; do not use its characters or scene` [BD-off].
- **Negations: exactly the one closing sentence.** A second negation only after the same fault has appeared in two runs of THIS take, and then as a sentence inside the affected beat (SKILL rule 6). The vendor documents negative control for subtitles and audio only ("Use positive descriptions whenever possible") [BD-off] — the closing sentence stays inside that.
- **Sound is written inside the beat, diegetic.** The platform's audio setting is a project decision in the Render Slate, never prompt text.
- **Nothing on an axis the model owns** — unless the canon says it in so many words, the look needs exactly that control, or a run of this take showed the model doing that one thing differently; then one sentence in the beat it concerns, listed in `Crew choices` (SKILL.md Economy and division of labour).

**Per-model placement.** Seedance 2.5 / Cinema Studio: the order above verbatim; Seedance 2.0: the same order with `Shot N` beats. Veo 3.1: the one camera line is written in every prompt and opens it (Google's cinematography-first formula; with an input image it carries only the move); Kling 3.x: camera-first is a 🟡 recommendation (12g) — a camera line that is written opens the prompt; everything else in the order above; Veo may carry the beats as `[00:00–00:04]` ranges (ch. 21), Kling as plain prose with a motion endpoint. MiniMax H3: the official ch. 21 fields are the container — the beats go into the integrated description with H3's cut-point syntax, the STYLE tokens into its style wording, the one closing sentence at the end of the description; no ch. 12 blocks, no second spine. Medium-emulation looks are usually technique C (Master Style Block + short prose-beat story, style-control §6c); a project may instead carry the medium's tokens on the STYLE line of a Caption Spine — the intake draft takes decide (SKILL rule 4); never both shapes in one prompt.

**Lint before delivery — seven measures, written into the slate's `Lint` row for EVERY video prompt in any technique (SKILL checklist step 5), in this format:** `words n · negations n/1 — prohibition sentences; clauses inside one sentence count once; B: once per governing block · numerals outside TC n/0 — each exception a look control named in Crew choices · absolute measures n/0 · double mentions none · contradictions none · beats complete`. `words n` is a count, never a ceiling: it is reported so a revision after a failed run can be held against the one before (SKILL rule 15 — never longer). `contradictions none` = checks 1, 5 and 6 above. `beats complete` = every beat has one main event, its end state and an action for every character it names, and the timeline is consecutive and sums to the duration. A numeral inside a fixed term (3D, an @tag, a shot label such as SHOT 2, a timecode, the take's duration in the title sentence or the FORMAT MODE line, a vendor-verbatim lock string such as "100% matches the reference") is not a number. The closing image — the "End with …" sentence (A, C), the ENDING STATE block (B) — restates the last frame by contract (ch. 14) and is not a double mention. A prompt that fails a measure is repaired before delivery, never delivered with a justification. Repair after a failed run in the rule-15 order (remove → change → add) in the NEXT prompt; the word count never rises (SKILL rule 15).

## 14. Sequence prompting (the generation unit)
**Doctrine: write shot-first, prompt sequence-first.** The sequence — a take of 1–3 internal shots: ONE shot for a calm single-event beat, 2–3 where pace or coverage needs a cut (production-pipeline ch. 2) — is the generation unit; state chains across takes.

**Format precedence (binding):** every delivered Seedance / Cinema Studio prompt is written in the project's technique (SKILL rule 4: A Caption Spine 12h · B block structure ch. 12 · C Master Style Block + story style-control §6c) — the structures quoted in this chapter (fal 9-part note, ByteDance base formula, stage format, edit format) and the Higgsfield prompt-builder scaffold (platforms-models ch. 13b) are SOURCE EVIDENCE for content rules, never alternative delivery shapes; "Drop unused lines" and similar usage notes describe the source, not our output. Mapping into technique A (Caption Spine, 12h): FORMAT → Render Slate settings · REFERENCE MAP / casting mapping → one job sentence per reference (the character and location-style lines) · GLOBAL STYLE → the STYLE line · TIMELINE / Stage N / shot-by-shot action → the timecode beats, shot size as a word inside each · Stage "Initial state" → the first beat's opening state · CAMERA → the one optional camera line, or nothing · AUDIO → a clause inside the beat · Stage "End state" / ENDING STATE → "End with …" · CONSISTENCY anchors / CONSTRAINTS / RULES → the one closing sentence, and a lock sentence inside the beat it protects — never a block. Mapping into technique B (ch. 12 blocks): FORMAT → Render Slate settings, not prompt text · REFERENCE MAP / casting mapping block → ACTIVE REFERENCES · GLOBAL STYLE / "The visuals feature [style]" → distributed per placement rule 1 (LIGHTING, COLOR GRADE, OPTICS, PERFORMANCE) + the STYLE suffix — never a third block · TIMELINE / Stage N / shot-by-shot action / [Subject] performs [action] → ACTION (time-ranged segments) · Stage "Initial state" → FIRST FRAME/BLOCKING · CAMERA / "Use [shot size, angle, movement, cuts]" → OPTICS + CAMERA (+ FORMAT MODE for cuts) · AUDIO → AUDIO · Stage "End state" / ENDING STATE → ENDING STATE · CONSISTENCY anchors / [Maintain Consistency] / CONSTRAINTS → POSITIVE LOCKS. Mapping into technique C: GLOBAL STYLE / "The visuals feature [style]" → the Master Style Block (style-control §6c); the story part maps as technique A's beats. Practitioner formats map the same way: the P58 advanced format GOAL / REFERENCES / CONTINUITY / SCENE / STAGES / LOOK / CAMERA & PERFORMANCE / AUDIO / RULES → GOAL = SCENE CONTEXT · REFERENCES = ACTIVE REFERENCES (grouped per subject) · CONTINUITY + RULES = POSITIVE LOCKS · STAGES ("stage N at ~second X, named, what happens, how framed") = ACTION with time ranges · LOOK = LIGHTING / COLOR GRADE / STYLE; P62's "Seedance structure" (subject + action + environment + style + audio) is the ByteDance base formula above. 🟢 **Negative rule (revised — official docs overruled the earlier strict taxonomy):** negations are established practice in official sources, BOTH kinds: procedural prohibitions ("no cuts, no slow motion, no duplicated props, no speed-ramps") AND content exclusions ("no subtitles, no logos, no music", "NOT plastic", "NO blood") — evidenced in fal prompts with shown results, Runway official examples and Higgsfield's official CS production prompts. Backward guard: mark materials that belong ONLY to the original clip, or later figures/props appear too early; "connect to the source video" is not enough — write the source's start frame as an explicit end state. 🟢 **Emotion formula:** trigger → immediate visible reaction → gradual shift (eyes/brows/mouth/breath/gaze/hand) → settled; 2–4 cues suffice; chain multiple shifts to events. Expressions in descriptive sentences, few idioms [BD-off].
🟢 **Action detail by version [BD-off]:** Seedance 2.5 — "Give priority to general descriptions … Only write specific details for a few memorable actions, and avoid repeating the same actions" (the division of labour, from the vendor). Seedance 2.0 — refine by body part with range, speed and force, prefer slow continuous small movements, write the transition between two actions.
🟢 **Translate camera technique:** keep the term AND write the visible change ("Rack focus: … leaves gradually blur while the face changes from soft to sharp"); dolly zoom/bullet time/speed ramp need defined parameters.
🟢 **Language pattern:** language → regional variety/accent → delivery → speaker → line; "authentic Los Angeles English" beats "English". Restate the language if the model switches. 🟡 Accent guard [P20]: an accent word alone yields caricature — write pace, energy and emotional state into the delivery slot, add "natural, not exaggerated, not a comedy voice", and say how the voice CHANGES on the beat ("when the shock hits, the voice jumps and the words get short"). Dialogue direction reads the same way: the broken apology, the pause, the cut-off, the tone shift as observable behaviour with an explicit end state.

## 14b. Seedance 2.5 production doctrine — references, edit suite, extension chains

The 2.5 feature set changes the WORKFLOW, not just the specs: control shifts from prose to references, repairs shift from rerolls to edits, and scenes are built by extension. An agent guiding a 2.5 production runs THIS doctrine — a 2.0-era loop (describe everything in text, regenerate on every fault, stitch cold cuts) wastes the model. The prompt shape is the project's technique (SKILL rule 4); in every technique prose is for what happens, references are for what persists. Researched against official sources 2026-08 (ByteDance Seed launch blog, Higgsfield product pages/changelog, official Dreamina prompt-guide templates via [X-ext]).

🟢 **Mode routing comes first [H-off/X-ext]:** every job picks one of four modes BEFORE any prompt is written — **`t2v`** (new shot from prose + refs) · **`omni_reference`** (new shot with a source video attached as reference: performance re-skins, green-screen relocations; duration settable, source ≥4 s) · **`video_edit`** (scoped fix inside an approved take; duration + ratio locked to source ±0.3 s; on Higgsfield this is the model-selector entry **"Seedance 2.5 Edit"** with the "Edit video" task and the VIDEO TO EDIT source slot [PP]) · **`video_extension`** (forward/backward, 4–30 s per round). The same sentence means different things per mode; two modes silently lock parameters. UI-label map (mode id ↔ Higgsfield label, written in the slate as `id ("UI label")`): platform-ui-workflows §1 mode table.
🟢 **Official ModelArk 2.5 guide items (BytePlus docs, via verified reproduction [BD-off, P40]):** `sd25-pe` is the official prompt-optimizer skill (ask any LLM optimizer "is this per the official 2.5 guide?" — generic optimizers produce headed, categorised prompts where the official examples are screenwriter prose with timestamps and a one-sentence summary); any aspect ratio in **[0.4, 2.5]**; export takes as **.mov** when they feed edits or extensions (continuity); edit calls use `duration = -1` and `ratio = adaptive`; **seamless transition between two videos** and **one-click video** are documented modes; storyboards ≤15 panels, line art, no text on the board; video edits are most stable on inputs up to 20 s with 1–5 reference images (6–8 less stable); timestamps in 1-s units, never for high-frequency actions; no mapping labels inside reference images.
🟢 **Seedance 2.0 → 2.5: what carries over and what does not [BD-off: 2.5 guide "Differences from Seedance 2.0", 2.0 series guide, `sd25-pe`].** Know-how from 2.0 holds on 2.5 unless one of these documented differences says otherwise:

| Axis | Seedance 2.0 | Seedance 2.5 |
|---|---|---|
| Timing | does not respond to timestamps, only to shot numbers; "support for precise timing … is unstable" | integer-second timestamps: ranges, time points, relative time |
| Take length | ≤ 15 s | ≤ 30 s |
| Subject references | multi-view images not recommended (read as several subjects → twins); headshot + full-body | single-view and multi-view supported for 1–5 subjects; above 5, single views as separate images |

| Edit / extension output | — | `.mov` recommended for continuity |

🟢 **The edit suite — repair before reroll.** An approved take is never regenerated for a local fault. - **Subject swap:** Timeline Inheritance clause mandatory (ch. 14).
- **Audio-category edits:** dialogue, spoken language, voice, BGM, SFX edit independently ("Remove only the original background music. Keep the character dialogue, lip sync, ambience, and action sound effects").

Log each edit round as a Take ID.

🟢 **Extension chains [BD-off]:** 4–30 s per round, forward or backward; carries main characters, environment, narrative pacing, audio continuity. **Chain ceiling ≈60 s** (30 s source + one 30 s extension) — beyond that, re-anchor a NEW generation from the original references instead of extending an extension (degradation compounds). Boundary-frame contract every round: forward — "the first frame of the extended segment directly continues from the last frame of @Video 1" (the last clean frame — boundary-frame source, ch. 14); backward — write the source's first frame as the extension's explicit END state and declare which materials must not appear early ("then connect to the source video" is the documented failure; ch. 14 extension rules). Restate the continuity list each round. 180 s single-flow is a Dreamina-only beta, not a Higgsfield plan (⚠️ [P58] reported a 180-s option on the Higgsfield surface in Aug 2026 — "six 30-s videos stitched from one 5,000-character prompt" — same mechanism, same verdict: not for held scenes; read the live form). 🟡 **Copy-ready extension wording that held without extra references [P57]:** forward — `Extend @Video 1 forward, directly continued from its last frame, matching the subject's pose, position, background, camera angle, lighting and motion direction. New action: …`; backward — `Extend @Video 1 backward: before the video starts, …` (a 19-s prequel cut cleanly against the source's first 5 s). 🟡 **Video-as-reference continuation drifts geometry [P52]:** "continue from @Video 1" with the clip attached as a reference (omni-style, not an extension) changed a prop's size between clips; extension or last-frame chaining holds geometry better — if omni continuation is used, attach the prop as its own reference.
🟡 **One location per take for narrative intercuts [P28, Seedance 2.0 evidence]:** do not prompt A/B parallel action inside one generation (hero ship ↔ enemy ship); generate one take per location and cut in the NLE — the complexity budget (SKILL rule 3) applied to locations. Montage/commercial takes (next line) are exempt: they may span locations because no parallel action is implied. ⚠️ Scope [H-off, P66]: the rule holds for text-only prompting; a continuous JOURNEY through several locations (street → corridor → kitchen → casino, 30 s) held on 2.5 when a clay render carried the route (production-pipeline ch. 8 protocol c) — parallel intercuts stay one-location-per-take, a travelled route with a blockout does not.
🟡 **Montage ceiling and the missing agent [P38]:** commercials/montages are the exception to the 2–3-shot drama budget — cap at **12–15 cuts per 30-s take** ("so it can focus on each cut"; an LLM's first draft had far more). Name the ACTOR of every action: "onions are chopped" rendered a kitchen with no hands in frame — write "the chef's hands chop". 🟢 **Everything unreferenced goes static — write background life explicitly [P39, P41; H-off, P69]:** with ~9 references the composite held but crowd and sky froze; the vendor's harbour scene had "NPC crowds staring into space" until the prompt forced every background person to be mid-action in every frame — write it ("people moving in the beach bar", "every passer-by mid-stride") or get a ghost town. The same vendor fix for a beat that over-shot (a shoulder bump rendered as a hug): write the physical mechanics — shoulders hit, suitcases swing, momentum carries them half a step past, planted feet turn — "when the collision becomes physics, the romance feels natural" (ch. 14 cause before reaction).
🟡 **Write the boundary state from harvested frames [P22]:** before prompting an extension, frame-harvest the source's first/last frame plus 2–3 keyframes, and let the agent write the continuation FROM those stills — who stands where, what each hand holds, where the light comes from — so positions, hand contact and eyeline are held verbatim ("his hand stays on the side of the washing machine"). A well-anchored extension cut together with its source was reported seamless.

Still budgets, not frames — "timestamps allocate proportion, not frames" [F]: never demand events inside one second, never plan frame-accurate hits (precision limits, ch. 14).
🟢 **Beats inside a declared single shot — settled by version [BD-off; H-off P47 vs P49 for 2.0]:** Seedance 2.5 takes integer-second stamps inside one continuous take — a stamp is an event budget, never a cut point, and the official examples stamp a "single continuous take … no cuts".
