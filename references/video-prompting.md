## 12. The prompt block structure (the core prompt-writing method)

**This is the default way to write any Seedance / Cinema Studio prompt.** It is the officially documented Seedance block system, adopted as our standard because it beats loose prose: each concern has one home, nothing is forgotten, nothing collides. Binding for Seedance 2.0/2.5 and Cinema Studio; for Kling, Veo and Grok keep the block CONTENT rules but reorder the spine and drop the block headers per 12g and the copy-ready instances in platforms-models ch. 21; for H3 do not adapt at all — write the official H3 schema from ch. 21 verbatim. Treat the guidance as holding for 2.5 as well as 2.0 unless a model-specific note says otherwise.

**Core principle — write the visible.** The model reacts to what can be seen and measured, not to mood words. Translate every abstraction into something observable: not "tense scene" but "man freezes, slowly clenches his fist, light only from the side, half his face in shadow". Fewer precise words beat many vague ones. Before generating, mentally *watch* the prompt: is the first frame non-empty, is it clear where each subject is and looks, where the light comes from.

**Output is a single standalone prompt in a code block.** Each generation is a blank slate with no memory of other shots — a prompt is a sealed single-shot document. Never carry in scene numbers, script headings, prior-scene summaries, "as above / continues" phrasing, or unused tags/characters/props.

### Block order — ● = mandatory on every video prompt · ○ = only when the shot needs it. Never rename a block; omit an optional block rather than leave it empty.
```
● SCENE CONTEXT       1–2 sentences: what happens, where, when. Geo-positions of characters.
● ACTIVE REFERENCES   (whenever anything is attached — style-control §7 Rule 0) one line per attached reference,
                      fixed shape: "@tag controls only <one job> — <minimal anchor>. 100% matches the reference.
                      Do not copy <concrete non-transfers>." Anchor content by class: character = role/build,
                      current state, 2–4 unique visible features, action-critical details (voice only if it
                      speaks); plate = layout + light side; prop = shape + state; style still = rendering
                      signals only.
○ LOCATION MAP        (mandatory when the shot has more than one character or a camera move) foreground /
                      midground / background; where the camera sits; where light comes from; movement paths.
                      Naturalistic colour can live here.
○ FIRST FRAME/BLOCKING (mandatory in the chain case and for any take with two or more characters) who is
                      where in the first frame: positions, orientation, gaze. Composition rule for THIS scene.
● FORMAT MODE         one continuous shot / sequential cuts / timed multishot (segment syntax: ACTION block
                      below; cut budget 1–3 shots per take: production-pipeline ch. 2; montage exception 12–15
                      cuts: 14b; total runtime of a multishot take goes here).
● OPTICS              shot size + FOV° per segment + lens character. Multishot: add "no drift mid-segment".
● CAMERA              operator behaviour: height, distance, movement, focus; camera-body tonal
                      character as a LOOK, not a model name.
● ACTION              events at the precision the shot needs; camera motion and subject motion stated
                      separately; cause before reaction. Multishot takes segment it as "SHOT 1 (0.0–5.0 s): …
                      HARD CUT. SHOT 2 (5.0–10.0 s): …" — ranges consecutive and non-overlapping, one primary
                      event per shot, match-cut lock 12f. A take declared ONE continuous shot uses relative
                      timing ("three seconds after …") and end states, never stamped segments (14b).
○ PERFORMANCE         (when acting matters) muscle-level emotion, precise eye-line, catch-lights,
                    breath, pore-level skin realism.
○ PHYSICS             (when it matters) mass, inertia, contact shadows, fluids, particles.
● LIGHTING            source, direction, exposure, key/fill, haze — priority block.
○ COLOR GRADE         (only when the grade is strong/stylised) palette as material + light + role;
                    omit for naturalistic looks and fold colour into LOCATION/LIGHTING.
○ WARDROBE            (when costume matters) material + condition, scene-logical.
● AUDIO               only the needed sound / line, in the 12b bracket grammar — at minimum the diegetic
                      list + the music exclusion (rule 9).
● ENDING STATE        MANDATORY on every take: the last frame as a still description — who is where, facing
                      what, prop states, light state. The next take / extension starts from this text
                      (ch. 14 state chaining). Never a dramatic peak here.
● STYLE               technical-style suffix: overall look in words, photoreal, format, grain.
○ OUTPUT SETTINGS     (only for aspects the platform exposes NO control for) anamorphic squeeze, real-time vs
                      slow-mo per segment, frame-rate LOOK in words — never ratio, duration or resolution: those
                      are platform settings and live in the Render Slate (12b, SKILL slate).
● POSITIVE LOCKS      short hard fixers against likely failures, restating critical info once; continuity
                      lives here. At minimum: subject count, continuity of the state that changes in this
                      take, the load-carrying style aspect.
```

### Complete example — the delivered shape (Seedance 2.5 t2v, two internal shots)
Block names in CAPITALS followed by a colon, one block per paragraph, in the ch. 12 order; optional blocks the shot does not need are omitted, never renamed or left empty. The Render Slate that must sit above every delivered prompt (SKILL rule 10) is omitted here; see worked-example.md §3 for the full delivery.
```
SCENE CONTEXT: Night, rain, lamp room of a lighthouse. @cat has just slipped in through the hatch (screen-left) and will push the brass lever (screen-right) to relight the dark lamp above. Two internal shots, 10 s.
ACTIVE REFERENCES: @anchor_1A controls only look, geometry and blocking of SHOT 1 (0.0–5.0 s); the take opens already in motion, it is not frame 1. @anchor_1B controls only framing and blocking of SHOT 2, from the HARD CUT at 5.0 s — not before. @cat controls only the cat — grey tabby, wet clumped fur, white chest patch, green eyes. 100% matches the reference. Do not copy its neutral pose or grey background. @loc_lamproom controls only the set — brass lever, rain-streaked glass, dark lamp. 100% matches the reference. Do not copy its emptiness. @prop_lever controls only the lever — shape, wall position, state: down. 100% matches the reference. Do not copy its background.
LOCATION MAP: foreground wet floorboards; midground the brass lever on the right wall, the hatch on the left wall; background rain-streaked windows, the dark lamp above centre. Camera in the rear-left corner of the room. Light enters from the windows, screen-right.
FIRST FRAME/BLOCKING: the cat mid-squeeze through the half-open hatch, screen-left, body toward frame centre, gaze up at the lamp. Rule for this scene: hatch stays screen-left, lever screen-right.
FORMAT MODE: sequential cuts, two shots, 10 s total — Shot 1 0.0–5.0 s, Shot 2 5.0–10.0 s.
OPTICS: Shot 1 WS at 63°; Shot 2 MS at 47°; no drift mid-segment; soft rounded rendering, no lens flare.
CAMERA: Shot 1 static, lens 40 cm above the floor, 3 m from the cat. Shot 2 static, lens 60 cm high, 1.5 m from the lever; one slow focus pull from the cat to the lever over 1 s as the paws land.
ACTION: SHOT 1 (0.0–5.0 s): the cat lands on the floorboards, shakes rain off in two shakes — droplets catch the window light — then looks up at the dark lamp. HARD CUT; the cat's pose at the end of Shot 1 exactly matches its start in Shot 2. SHOT 2 (5.0–10.0 s): the cat rears up and pushes the brass lever with both forepaws and its whole body weight; the lever tips up with one heavy clunk; only then a warm glow blooms from above and washes the room amber; the cat's eyes widen, ears rise, it settles onto its haunches.
PHYSICS: the lever moves only under the cat's full weight; wet fur clumps and drips; droplets fall at natural speed.
LIGHTING: Shot 1 one cold key from the windows screen-right, 8500K, low exposure, the cat's far side in shadow. Shot 2 the lamp ignites at 7.0 s: warm 3200K top light, 60% brighter than the window key, contact shadows under the cat.
AUDIO: {rain on glass, continuous} {two wet shakes} {one heavy metallic clunk at 7.0 s} {low warm hum from the lamp from 7.0 s} 【no music, no BGM — room tone and effects only】
ENDING STATE: cat seated on its haunches facing the lit lamp, lever up, room in warm amber, rain continuing on the glass.
STYLE: stylized 3D animated-feature look, matte rendered materials, soft global illumination; 24 fps, no grain.
POSITIVE LOCKS: exactly one cat in every frame; the lever starts down and tips up only at the push; the poses at the end of Shot 1 match the start of Shot 2; the camera never crosses the hatch–lever axis; wet-fur state holds in every frame; every frame keeps the stylized 3D rendering.
```

### The three placement rules that make it work
1. **Nothing style-related opens the prompt.** The prompt starts on SCENE CONTEXT / ACTIVE REFERENCES. **There is no style-prefix block** — style is not one thing in one place; each aspect lives in the block that already governs it (light → LIGHTING, colour → COLOR GRADE or LOCATION, optics → OPTICS, acting/skin → PERFORMANCE, physics → PHYSICS). Only *technical* style (grain, frame-rate look, anamorphic character, overall look word — never resolution/ratio/duration, which are slate settings) sits as a short suffix stack (STYLE, OUTPUT SETTINGS) just before POSITIVE LOCKS. (This overrides the "glued style prefix" pattern that Higgsfield's own Shotlist-Director skill emits [H-off, P38] — official output, deliberately not adopted here: in tests Seedance ignores a floating keyword prefix while the reference image and per-block placement carry the look; style-control §1 and the primacy caveat below.)
2. **CAMERA sits mid-prompt — after the space/subject blocks (SCENE CONTEXT … FORMAT MODE), together with OPTICS, and directly BEFORE ACTION.** In layer terms: space/subject → optics+camera → action → style suffix → locks. Moved to the end, FOV gets ignored; moved to the opening, it fights identity. The block order above is the literal order — never reorder it.
3. **A lock is placed next to what it protects** and phrased positively ("headlights stay glowing in every shot"). Write densely where control matters, sparsely where it doesn't; say each important thing once.

If the user supplies their own prefix or block text, use it verbatim.

🟡 **Primacy caveat ⚠️ [P22]:** a practitioner skill (Cinema Director v3, Aug 2026) AND Higgsfield's own Shotlist-Director skill [H-off, P38] top-load shot count, total runtime, per-shot timing AND the technical look stack at the very top, arguing the model holds what comes first. The structural facts already sit at the top of this template — FORMAT MODE carries shot count and the per-shot time budget, SCENE CONTEXT what happens where; put total runtime into FORMAT MODE on multishot takes. The look stack's position stays governed by placement rule 1; move it up only as a documented experiment when a look drifts, never as the default.
🟡 **Prefer opening in motion [P22]:** the FIRST FRAME/BLOCKING block describes a moment already underway (mid-step, mid-gesture, machines running) rather than a pose the character then leaves — a take that starts from stillness reads as posed and adds the soft start the trim rule (post-audio-legal ch. 17) cuts anyway. Exception: the chain case, where the first frame must match the previous clip's end state.
🟡 **Name the ontology of what the model sees [P22]:** a person in an animal suit is written as "a human in a gorilla costume, matte synthetic fur, treated as a costume" — otherwise the model animates a gorilla. The same applies to mannequins, puppets, statues, reflections: say what the thing IS, not only what it looks like (ch. 24b generator logic).
🟢 **Four devices from a feature-film corridor prompt [H-off, P24]:** (1) the **height ruler** — never "taller", always a body landmark: "Horace's eye-line at the level of Cal's mouth"; (2) the **off-screen event** — a kicked door written as a list of concrete objects that must NOT appear (not a limb, not a shadow, not a reflection) — stated once, objects only (⚠️ never style words, never repeated: ch. 14 third class); (3) **different rhythms** — two people react to one event never in sync, a synchronised reaction reads as animation; (4) the speech count lock (12b). Give the model less freedom: a corner, not a room.
🟢 **Anchor the camera to a VIEW TARGET, not to a prop [H-off, P49]:** "camera right next to the fridge" repeatedly moved the fridge toward the camera instead (72 generations); what landed was a view target plus a named part of the reference — "starts with a focus on the dark hallway, parallel tracking … the top-right corner of the top panel". Camera placement is written as what the camera SEES from where, never as adjacency to an object the model may relocate.
🟡 **Community vocabulary sources (unverified, checked 2026-09-02) [P20]:** [camera movements](https://aicameramovements.com/) · [camera angles](https://aicameracontrol.com/) · [emotion direction, 25 copyable emotions](https://seedance-emotion-direction.vercel.app/) — phrase banks for the CAMERA and PERFORMANCE blocks, never production receipts.

## 12b. Reference tagging & audio syntax

🟢 **Reference + text split:** the `@tag` image sets appearance and identity; text sets what happens and locks critical details. Both are required. Keep the character description in the prompt MINIMAL — long appearance text conflicts with the image and degrades it. Anchor line format: `@TAG: age + role/build + current state + unique visible features + action-critical details + voice (only if it has a line). 100% matches the reference.` This anchor is the MIDDLE segment of the ACTIVE REFERENCES line (order: job → anchor → "100% matches" → exclusions). style-control §7 Rules 1–4 and SKILL rule 5 ("job line + exclusions") describe this same single line, never a second one.
🟢 State critical details (small text, logos, colour) in words even if they appear on the reference — the model can drop them. **Never place an `@tag` in a shot where that object is not present** — the model forces it into frame (the casting-system mapping block is the exception: it binds identities without placing them; placement happens in ACTION at the beat — production-pipeline ch. 3 large casts; second exception: per-shot anchors in a multi-shot take, time-scoped — production-pipeline ch. 1).
🟢 **Tag token rule — the token in the prompt equals, character for character, the label the live surface shows for that input.** Resolve the form BEFORE writing (style-control §7 Rule 2) from the receipt (SKILL rule 16) or the user's pasted UI: Higgsfield → the Element/asset name exactly as registered (`@hero`, `@anchor_1A`; a clay blockout is registered as an Element too and addressed by THAT name — `@Clay Render` is the ByteDance class label, not a Higgsfield token) · ByteDance-documented surfaces (Dreamina, ModelArk/BytePlus) → the guide's forms `@Image 1` / `@Video 1` / `@Audio 1` / `@Clay Render 1` (capitalised class + space + upload index) · other surfaces → the index form their upload hint shows (platforms-models ch. 13 lists Hailuo UI `@Image 1`, fal `Image1`, ComfyUI `<Picture 1>`). `@image1 @video1 @audio1` in this file is the skill's class-neutral shorthand for "index by upload order" — never deliver it as-is unless the surface shows exactly that form. If the surface cannot be seen, deliver the form the user/receipt gave and mark the slate Inputs row `🟡 token form unverified — match the upload label before running`; never invent a form. User's explicit `@tag_name` wins; tags are not portable across platforms.
🟢 **Mode A** @image-tags by upload order; **Mode B** no tags — describe the visible feature ("the woman with the silver streak").
🟢 **Reference budgets (officially confirmed):** ≤8 image subjects (stretch 9–12), ≤5 video/audio subjects, clips 5–10 s; >5 subjects → single-view images, separate angles, never a collage grid. Trim order when over budget: characters > props > scene > style. (Seedance 2.5: 30 images + 10 video + 10 audio per generation across four reference classes incl. `@Clay Render` — build the project pool maximally, select per scene deliberately; full doctrine ch. 14b.)
🟢 **Audio bracket grammar (Seedance family: Seedance on Higgsfield/Cinema Studio, Dreamina, BytePlus/ModelArk; other models keep their own syntax — Hailuo `<d>` tags, platforms-models ch. 21; Veo/Kling: plain prose).** Write every AUDIO block that contains speech in this form; a take without speech may use `{ }` / 【 】 alone or plain prose: `( )` = the spoken line, verbatim, one pair per line · `< >` = delivery/tone direction, placed directly BEFORE its line, after the speaker name · `{ }` = one sound effect per physical cause, counted (sound-at-event-granularity below) · 【 】 = ambience/music directive, including the no-music exclusion. Copy-ready: `AUDIO: {rain on the glass, steady} {one metallic clunk as the lever tips} Keeper, <low, tired, natural — not exaggerated> ("Pull it, Oli.") 【no background music, no BGM, no score — room tone and effects only】 — the take contains exactly three words.` Never mix classes: SFX never inside ( ), directions never inside ( ). Exclude music by default (production-pipeline ch. 6). Storyboard grids/sheets used as references: exclude their own drawing style and panel borders explicitly. Prompt length: stay under ~5000 characters; every vague word is a coin flip. Generation parameters (ratio, duration, resolution) are platform settings, never VIDEO prompt text (Render Slate Settings row). Image prompts keep their canvas/ratio line in the prompt — style-control §2.
🟡 **Seedance 2.5 fills unspecified dialogue and blocking with inventions [P19]:** in a paired two-character 30-s dialogue test the model inserted an unprompted spoken line and let one character leave the scene without a motivated beat — while keeping eyelines and the 180° axis correct on its own. Consequence for dialogue takes: lock the spoken text explicitly ("only these lines — no additional dialogue, narration, or voice-over") and the blocking end state (ch. 12 POSITIVE LOCKS + ENDING STATE); an unspecified beat is filled by the model exactly as an unspecified camera is.
🟢 **The speech count lock [H-off, P24]:** state the exact number of words a take contains as its own lock (`("Pull it, Oli.") — the take contains exactly three words`) — without it the model adds a mumble or a line in another language; it does not like silence. (Feature-film confirmation of the invented-dialogue note above.) 🟢 **Voice as a fixed conditions block:** in text, the voice is a fixed set of conditions (the reference half of the voice channel — cloned voice / @Audio / P17 clip — is chosen in 14b) — register, tempo, accent, manner — pasted into the audio field VERBATIM every time the character speaks; not even a synonym changes, because new wording widens what the model samples from and the voice drifts. The accent is written phonetically inside the line itself (th → f/v, dropped h, glottal t, -ing → -in'); one character, one accent, never drifts.
🟢 **Phonetic spelling for names and hard words [H-off, P47]:** write proper nouns as they sound ("Kan-dal-FEE-na", not "Candalfina") — the same channel as the phonetic accent. 🟢 **A plate reference can pin the opening composition [H-off, P49]:** a location/prop reference attached to a shot whose framing should differ made the take open on that frame and "slide" away — attach only plates whose framing the shot actually uses (12b tag rule from the composition side).
🟡 **Sound at event granularity [P20]:** one sound per physical cause, counted and placed — "each step: one closed rubber-sole squeak, then one small wet splash under that foot"; "soft hydraulic door hiss, then one heavy steel slam". Vague sound words return generic ambience. ⚠️ Practitioners also place NON-diegetic hits in-model ("hard sub-bass hit on the frame the light dies") — the model can do it, but the skill keeps score/stingers in post (rule 9): an in-model hit is baked into the mix and cannot be re-timed or replaced.
🟡 **Music bleeding into Seedance 2.5 takes despite the AUDIO exclusion [P22]:** this is the one permitted second statement of an exclusion (SKILL rule 6) — on a documented repeat (music appeared twice), restate the exclusion once in POSITIVE LOCKS next to the diegetic list. ⚠️ Last resort, logged as a primacy experiment because it breaks placement rule 1: prepend "NO MUSIC WHATSOEVER / NO BGM" as the first line — community remedy, reported effective, unverified here; never the default.
🟡 **Verbatim exclusion that held where "no music" failed [P39]:** "No background music, no BGM, no score, no soundtrack, no ambient musical pad. Diegetic room tone and sound effects only." — music bleeds most at action escalations (a sprint, a chase); the string sat at the END of that prompt (⚠️ vs the prepend remedy above — position unsettled, wording is the constant). Generated SFX can be as flat as generated score: mute and re-design in post, not only the music [P39]. Audio uploaded WITHOUT its @tag is used as a voice but speaks gibberish [P40] — address every audio file.

## 12c. Quantification doctrine (write measurable, not moody)
🟢 The single highest-leverage habit across all block writing — replace adjectives with units the model can measure:
- **Speeds in km/h:** not "fast/slow" → "moves at 40 km/h", "camera pans at 5 km/h". Second form, vendor-proven [H-off, P25]: a ratio to a known cinematic move — "three times faster than a typical cinematic dolly pull"; camera paths as raw numbers ("orbit from 8 m down to 4 m distance, 3 m down to 2 m height") — "video models prefer arithmetic over words like *dramatically*".
- **Atmosphere in %/metres:** not "light fog" → "fog density 40%", "haze visible at 15 metres depth". Atmosphere builds in STEPS across shots (shot 1: 20% → shot 2: 40% → shot 3: 60%).
- **Giant scale via human-height comparison:** not "huge"/"three metres tall" → "stands as tall as four humans stacked head to toe".
- **White balance in Kelvin,** fixed within a scene (3200K / 4000K / 5600K / 8500K), set to scene mood.
- **Left/right is from the camera.** "Subject moves left" = left from the camera's view.
- **Colour tied to material + light beam + compositional role,** never a flat list: not "the woman wears red" → "crimson silk scarf catching the cold tungsten spill from the corridor".
- **Environment interaction stated physically:** snow melts on skin, rain runs down hair, wind moves fabric.
- **Emotion through muscle movement, not labels** (ch. 14 emotion formula). **Equipment as a look, never gear names** — camera/film/lens model names get ignored or break complex moves (VIDEO rule; for STILLS the vendor endorses photographer language — lens, aperture, stock, halation — style-control §2 [H-off, P47]). **Camera on the shadow side,** operator axis stated (drama doctrine; commercials default to a soft frontal key — genre-baselines Commercial [H-off, P48]). **Background in explicit foreground/midground/background layers.**

## 12d. Optics: shot size + FOV in degrees
🟡 **A lens look baked into the anchor still survives only until the first cut [P26]:** a 50 mm swirl-bokeh still held in a single-shot take and was lost the moment a multi-shot take cut away from it — optics must be written in OPTICS per segment (and in the platform's video-side control where it bites), never carried by the still alone.
🟢 Two levers define how a shot is framed: **shot size** and **focal length**. Write shot size as an abbreviation and focal length as **FOV in degrees** (mm is for thinking, degrees go in the prompt).

**Shot sizes:** ECU (extreme close-up: eyes, button, headlight) · CU (full face) · MCU (head + shoulders) · MS (to the waist) · WS (full figure + surroundings) · EWS (scale, location).

**FOV anchor table — use only these discrete steps (never "23°" → use 18° or 29°):**
| FOV | mm equiv | Purpose | When |
|---|---|---|---|
| 180° | fisheye | spherical distortion | POV, dream-state |
| 107° | 14–16mm | architectural ultra-wide | huge interiors, epic establish |
| 84° | 20–24mm | wide | establish, group blocking |
| 63° | 28–35mm | observational | wide observation, reportage |
| 47° | 40–50mm | neutral human perspective | universal establish, medium |
| 29° | 75–85mm | portrait compression | medium-isolate, dialogue bust |
| 18° | 100–135mm | natural portrait | close-portrait, identity-preserving |
| 12° | 180–200mm | tele-detail | hands, objects, detail-on-wide |
| 8° | 300–400mm | extreme compression | observation, broadcast |

In a multishot, set FOV **per segment** and add "no drift mid-segment".

## 12e. Optical technique patterns (copy-ready)
🟢 **Observation / hidden-camera effect — all three at once:** (1) foreground occlusion out of focus over 20–30% of frame (wall, pillar, branch), (2) atmospheric haze between camera and subject, (3) distance vantage at 8–12° super-tele, operator anchored far away. Change the occlusion type between beats; keep the vantage single.
🟢 **Sports broadcast:** 8° super-tele + handheld 1–2 cm tremor + "anchored at distance, finding the action".
🟢 **Detail-on-wide (snake cam):** 84° wide FOV + low angle right up against a small object — foreground object exaggerated, background recedes.
🟢 **Hidden occupants behind glass (faces that must stay blank) [H-off, P23]:** "GLASS: all the [vehicle]'s windows are semi-transparent and heavily reflective, sky, road and passing scenery slide across them, and the interior sits in shadow. The [N] passengers are almost invisible, present only as soft dark silhouettes veiled by the reflections and the tint, their poses and gestures readable purely by shape." — the vendor's own fix for silent characters; goes in LIGHTING/OPTICS, the silhouettes' poses in ACTION.
🟢 **Body-rig product shot (snorricam) [H-off, P48]:** "single body rig snorricam locked on the right ear cup. Camera bolted to his body. The headphones rock solid dead centre. Everything behind him whipping past in motion blur." — worked first try; the pattern for any worn product.
🟢 **Intimate wide:** 63–84° wide FOV on a close face — face centred, surroundings readable without blur.
🟢 **Tele compressed air column** (8–12°): "dust suspended in the long compressed air column between camera and subject", "heat shimmer compressed into a wall of haze in front of the figure".

## 12f. Special protocols
🟢 **Extreme-FOV multishot (8° or 107°) needs a 4-mechanism consistency stack** or it breaks after 2–3 beats: (1) sequence-wide identity lock — single location reference across all beats; (2) LENS LOCK opener — explicit FOV phrase at the start of each beat; (3) LENS CHECK closer — confirm FOV at the end of the beat; (4) colour via material + light, not a list. All four required.
🟢 **Whip-pan timing:** a whip under 0.8 s renders as a hard cut without blur. Pattern: `0.3s subject A settled → 0.8s WHIP motion-blur transition → 1.4s subject B settled`.
🟢 **Mixed time-speed (real-time + slow-mo):** hard cuts only between speed modes; each shot is ONE speed start to finish.
🟢 **Cracks/breaks without impact (anti-impact lock):** "crowd PRESSES, not strikes" · "fracture originates from edge stress, not centre impact" · "no impact point — pressure-based crack" · sequential timing edge-to-centre, not radial from a point.
🟢 **In-shot transformation: hard sub-second duration + mechanical ontology [H-off, P25]:** an unspecified transformation defaults to a glowing anime power-up every time; write "a weapon deploying, not a magic sequence" and a hard number ("0.4 s") — the instant snap is what keeps it real.
🟢 **Contact outcomes by material hierarchy [H-off, P25]:** for blade/impact beats set one hard PHYSICS rule that decides the outcome ("crystal always beats steel" → the steel shatters), map tension in centimetres per second (blade-to-blade distance), and describe the geometry of the impact ("a vertical chop meeting a diagonal parry").
🟢 **Match-cut lock across HARD CUTS inside a take [H-off, P25]:** "the poses at the end of shot one exactly match the start of shot two" — spelled out, or the model treats the cut as a brand-new scene and throws the poses away. Same contract as state chaining (ch. 14), applied within one generation.
🟢 **Staging beats banning for anatomy invariants [H-off, P25]:** a monster's blade-arm kept growing a hand and a sword despite "no held objects, no handle"; the fix was to stage the arm INTO view ("he raises his arm") so the model sees the invariant — write the visible (ch. 24b), never the ban.

## 12g. Adapting the block structure to other video models

The block structure (ch. 12) is Seedance/CS-native. Other models want the same *ingredients* — subject, action, scene, camera, lighting, audio, references — but in a **different block order**, and they disagree on one thing above all: **where the camera goes**. Keep the ch. 12 blocks and their content rules (quantification 12c, FOV table 12d, reference tagging 12b); reorder the opening spine per model. Cross-model camera vocabulary itself is portable (all these models trained on professional film footage); only the ordering and a few model quirks change. [W, multi-source]

**The one rule that flips per model — camera position in the spine:**
| Model | Camera goes | Spine (documented) |
|---|---|---|

## 14. Sequence prompting (the generation unit)
**Doctrine: write shot-first, prompt sequence-first.** The sequence — a take of 1–3 internal shots: ONE shot for a calm single-event beat, 2–3 where pace or coverage needs a cut (production-pipeline ch. 2) — is the generation unit; state chains across takes.

**Format precedence (binding):** every delivered Seedance / Cinema Studio prompt is written in the ch. 12 block structure — the structures quoted in this chapter (fal 9-part note, ByteDance base formula, stage format, edit format) and the Higgsfield prompt-builder scaffold (platforms-models ch. 13b) are SOURCE EVIDENCE for content rules, never alternative delivery shapes; "Drop unused lines" and similar usage notes describe the source, not our output. Mapping into ch. 12: FORMAT → Render Slate settings, not prompt text · REFERENCE MAP / casting mapping block → ACTIVE REFERENCES · GLOBAL STYLE / "The visuals feature [style]" → distributed per placement rule 1 (LIGHTING, COLOR GRADE, OPTICS, PERFORMANCE) + the STYLE suffix — never a third block · TIMELINE / Stage N / shot-by-shot action / [Subject] performs [action] → ACTION (time-ranged segments) · Stage "Initial state" → FIRST FRAME/BLOCKING · CAMERA / "Use [shot size, angle, movement, cuts]" → OPTICS + CAMERA (+ FORMAT MODE for cuts) · AUDIO → AUDIO · Stage "End state" / ENDING STATE → ENDING STATE · CONSISTENCY anchors / [Maintain Consistency] / CONSTRAINTS → POSITIVE LOCKS. Only the official fixed schemas of OTHER models (H3, platforms-models ch. 21) replace ch. 12; see 12g.

🟢 **fal 9-part production note:** FORMAT (ratio/duration handled by platform) → REFERENCE MAP (one job per reference) → GLOBAL STYLE → TIMELINE (time-ranged beats) → CAMERA → AUDIO → CONSISTENCY anchors → **ENDING STATE** (explicit final frame description — the next take's start) → CONSTRAINTS. [F] (source pattern — deliver in ch. 12 blocks per the precedence line above)
🟢 **State chaining:** every take's prompt begins from the previous ENDING STATE ("continue forward, do not replay"); harvest the final frame as the next start frame — the chain case, the one place a start frame is doctrine (production-pipeline ch. 1); on Seedance 2.5 prefer `video_extension` over a harvested frame (ch. 14b). **Boundary-frame source:** harvest from the RAW export (untrimmed .mov, 14b) — the ch. 17 trim is a post step on the assembled cut and is never applied to a take before it is chained or extended. The last frames of a take lie inside the soft zone the trim rule names: if the true last frame is blurred or frozen, harvest the last CLEAN frame instead, write the ENDING STATE for that frame, record its timestamp in the slate `Handoff` row, and for `video_extension` cut the source to that frame before extending (the one trim that precedes generation).
🟢 **Cause before reaction:** contact → movement → sound → reaction as separate ordered actions.
🟢 **Occlusion continuity:** if a subject passes behind something, state that it re-emerges unchanged.
🟢 **Negative rule (revised — official docs overruled the earlier strict taxonomy):** negations are established practice in official sources, BOTH kinds: procedural prohibitions ("no cuts, no slow motion, no duplicated props, no speed-ramps") AND content exclusions ("no subtitles, no logos, no music", "NOT plastic", "NO blood") — evidenced in fal prompts with shown results, Runway official examples, the ByteDance guide ("**Omission is not a reliable negative instruction** — unwanted elements MUST be named"), and Higgsfield's official CS production prompts. Remaining caution where positive-only still holds: (1) **image generators/stills** — negations process unreliably; describe materials positively ("matte, powdery, light-absorbing" instead of "no reflections"); (2) **negated emotion/state descriptions in Seedance 2.0** ("he's not crying" → documented confusion). Motto: **prohibitions and exclusions may be negative; descriptions of appearance and emotion stay positive.** 🟢 **Third class — style/genre/quality bans are RED and never repeated [H-off, P25]:** Higgsfield's own Hell Grind rebuild wrote "not a game, no CGI" a dozen times and got a video-game look — "AI models completely ignore the word not; it sees *game* a dozen times and goes with it". A repeated ban is a positive attractor. Replace every look ban with the wanted lighting, texture and camera grammar ("no cheap effects" → the actual light and material), and state any surviving exclusion ONCE (sole exception: the documented-bleed restatement in POSITIVE LOCKS, 12b — one extra mention of a concrete exclusion, never of a style/genre/quality word). ⚠️ Reconciled with the P24 off-screen device (ch. 12: a kicked door written as "not a limb, not a shadow, not a reflection"): concrete-OBJECT exclusions stated once are that device and stay allowed; style/genre/quality words and any repetition are the red class. **Scope split:** negation-OK for prohibitions/exclusions — proven on Seedance 2.5 (API/Dreamina/Runway), 🟡 for Cinema Studio 4.0 until your own test; the third class — evidenced on Seedance 2.0 inside Cinema Studio (Hell Grind), 🟡 for 2.5 until tested, but treat it as binding either way because the mechanism (repetition = attention) is model-agnostic — for VIDEO prompts; on AR image stills the one-time style-repulsion anchor of style-control §2 / pixar-look §9 remains legitimate (24f). ### Official ByteDance guide additions [BD-off]
🟢 **Base formula (6 elements, 4 lines):** [Subject] performs [action] in [scene]. / The visuals feature [style]. / Use [shot size, angle, movement, cuts]. / Audio includes [dialogue, ambience, SFX, music]. Drop unused lines; generation parameters stay out. (Source pattern — deliver in ch. 12 blocks per the precedence line above.)
🟢 **Casting system for many references:** group blocks [Characters]/[Props]/[Scenes]; write every mapping individually ("<Conservator> corresponds to @Image 1. Use only appearance, hairstyle, clothing.") — collective mappings ("@Images 1–4 define four characters respectively") bind nothing. "Do not interchange their appearances." Declare prop ownership ("belongs only to <X>"). ONE profile per recurring character incl. a do-not-use line; **select references per scene** — "Fifty references is a casting pool, not a shopping list."
🟢 **Stage format** (official; matches state chaining): [Generation Goal] → [Stage N: Initial state / Primary event / End state] → [Maintain Consistency]. ONE main change per stage. (Source pattern — deliver in ch. 12 blocks per the precedence line above.)
🟢 **Timing patterns:** range (budget) / exact point (one critical beat) / **relative** ("three seconds after he presses the button…"). Ranges consecutive, non-overlapping; three actions in one second don't work.
🟢 **Edit format:** [Edit Goal] / [Source Video Role: "@Video 1 is the sole editing master"] / [Edit Scope] / [Content to Preserve]. **Subject swaps must inherit the original timeline** (write out every entrance, movement, occlusion, exit with identical timing/path/tempo — the Timeline Inheritance clause) + explicit target count ("keep exactly one X throughout"). **Scope every edit in time explicitly** — whole clip vs. windowed ("Only from 4–7 seconds, change the cool blue light on the right wall to warm orange" — official worked example); unscoped edits are the documented cause of mid-clip reversions. Audio edits as their own instruction. Edit inherits ratio + duration (±0.3 s); source clip <20 s + 1–5 ref images. Full 2.5 edit suite (camera-perspective, green-screen, audio-category): ch. 14b.
🟢 **Extension rules:** describe the boundary frame BEFORE the new action. Backward guard: mark materials that belong ONLY to the original clip, or later figures/props appear too early; "connect to the source video" is not enough — write the source's start frame as an explicit end state.
🟢 **First/last frame & keyframes:** name each anchor separately (combined mention binds neither); both images same ratio or stretch. Multi-keyframes: "use @Image 1 through N as keyframes in this order" + state per image; **separate images beat grid collages**. 3D blockouts: rough = timing/blocking/camera/cut points (map every gray shape by name), fine = re-render with held structure; **remove path lines, axes, camera frustums beforehand — they get rendered.** 3D whitebox is its own reference type: lay out set + camera path before the first render.
🟢 **Emotion formula:** trigger → immediate visible reaction → gradual shift (eyes/brows/mouth/breath/gaze/hand) → settled; 2–4 cues suffice; chain multiple shifts to events.
🟢 **Translate camera technique:** keep the term AND write the visible change ("Rack focus: … leaves gradually blur while the face changes from soft to sharp"); dolly zoom/bullet time/speed ramp need defined parameters.
🟢 **Language pattern:** language → regional variety/accent → delivery → speaker → line; "authentic Los Angeles English" beats "English". Restate the language if the model switches. 🟡 Accent guard [P20]: an accent word alone yields caricature — write pace, energy and emotional state into the delivery slot, add "natural, not exaggerated, not a comedy voice", and say how the voice CHANGES on the beat ("when the shock hits, the voice jumps and the words get short"). Dialogue direction reads the same way: the broken apology, the pause, the cut-off, the tone shift as observable behaviour with an explicit end state.
🟢 **Precision limits (official):** timestamps = budgets; edits without frame guarantees; seamless transitions = continuity, not pixel identity; **subtitles, formulas, signage, product specs that must be exact → post-compositing.**

## 14b. Seedance 2.5 production doctrine — references, edit suite, extension chains

The 2.5 feature set changes the WORKFLOW, not just the specs: control shifts from prose to references, repairs shift from rerolls to edits, and scenes are built by extension. An agent guiding a 2.5 production runs THIS doctrine — a 2.0-era loop (describe everything in text, regenerate on every fault, stitch cold cuts) wastes the model. Researched against official sources 2026-08 (ByteDance Seed launch blog, Higgsfield product pages/changelog, official Dreamina prompt-guide templates via [X-ext]).

🟢 **Mode routing comes first [H-off/X-ext]:** every job picks one of four modes BEFORE any prompt is written — **`t2v`** (new shot from prose + refs) · **`omni_reference`** (new shot with a source video attached as reference: performance re-skins, green-screen relocations; duration settable, source ≥4 s) · **`video_edit`** (scoped fix inside an approved take; duration + ratio locked to source ±0.3 s; on Higgsfield this is the model-selector entry **"Seedance 2.5 Edit"** with the "Edit video" task and the VIDEO TO EDIT source slot [PP]) · **`video_extension`** (forward/backward, 4–30 s per round). The same sentence means different things per mode; two modes silently lock parameters. UI-label map (mode id ↔ Higgsfield label, written in the slate as `id ("UI label")`): platform-ui-workflows §1 mode table.
🟢 **Official ModelArk 2.5 guide items (BytePlus docs, via verified reproduction [BD-off, P40]):** `sd25-pe` is the official prompt-optimizer skill (ask any LLM optimizer "is this per the official 2.5 guide?" — generic optimizers produce headed, categorised prompts where the official examples are screenwriter prose with timestamps and a one-sentence summary); any aspect ratio in **[0.4, 2.5]**; export takes as **.mov** when they feed edits or extensions (continuity); edit calls use `duration = -1` and `ratio = adaptive`; **seamless transition between two videos** and **one-click video** are documented modes; storyboards ≤15 panels, line art, no text on the board; timestamps in 1-s units, never for high-frequency actions; no mapping labels inside reference images.
🟡 **Dreamina-only surfaces, observed Aug 2026 [P29, P30 — Dreamina partner channel]:** (1) **Long video mode** — AI video → model "Dreamina Seedance 2.5" → toggle "Long video" → durations past 30 s up to 3 min, single file (CapCut's variant returns separate clips). Behaviour: NOT continuous — an audible click and visible seam about every 30 s, mild degradation, the model re-paces dialogue on its own (rushes, then pauses; timestamps made it worse), 3-min requests errored for hours, and the 5,000-character prompt cap is hard. Treat it as an internal extension chain with 30-s seams: same boundary discipline as ch. 14b chains, no dialogue-heavy pacing inside it. (2) **Smart Edit** — clip → "Edit", or model Seedance 2.5 → mode "Smart Edit": rectangle/brush/arrow/text/eraser/mark annotations, each "Add to chat" with its instruction, reference images inline; several edits (remove ×2, replace, add) succeeded in ONE submission with reflections and ground patterns held, slight degradation at 720p — but the AUDIO of a removed subject stayed (footsteps): pair every visual removal with an audio-category edit. Dreamina also exposes a reference-weight slider (unverified, [P35]).
🟢 **Music track as timing input [H-off, P48, Seedance 2.0 on Higgsfield]:** "add the music track as an input and have the hero dance in time with its beat" — the track is loaded as an audio reference beside the prompt and every move landed on the beat; a TIMING reference, not generated score (rule 9 holds). Choreography still needs move-by-move language (renderability §3).

🟢 **Plan the reference set BEFORE the prose [BD-off].** Official capacity: 30 images + 10 video + 10 audio per generation; ByteDance: "a larger volume and wider variety of references can better capture the user's intent." The agent's duty at shot-brief time: walk the shot's element list and give EVERY element that must stay consistent its own reference — characters (4-view sheet, one view a strong expression), wardrobe, key props, location plates, style still, motion clips, voice/audio, clay blockout. **Prose is for what happens; references are for what persists** — an element controlled only by text will drift. Reference-maximal ≠ reference-dump: stability ranges stay ≤8 distinct image subjects (9–12 degrades), 1–5 video/audio subjects, clips 5–10 s, audio ≤10 clips / ~30 s combined [X-ext]; one deliberate reference per element beats a cluttered set [H-off]. Selection stays per-scene (casting pool, ch. 14) — but the POOL is built out maximally as a project asset (production-pipeline ch. 1).

🟢 **The four reference classes and their default jobs [BD-off]:** `@Image` = identity/appearance · `@Video` = **motion/pacing by default, not identity** — say so explicitly when you mean otherwise · `@Audio` = voice/dialogue/ambience/music via a role line ("@Audio 1 defines <character>'s voice") — voice consistency across scenes is an official capability, and audio refs drive lip-sync performance · **`@Clay Render`** = staging (official ByteDance reference class): a textureless 3D blockout carries "camera movement, pacing, shot-size transitions, subject trajectory, and blocking"; 2.5 derives physically plausible LIGHTING (source direction, colour temperature, shadow projection) from its spatial info on its own — but the lighting JOB is assigned to an image reference's role line, never to the clay render's ("Refer to @Clay Render 1 for camera movement… @Image 2 for character design, scene, materials, lighting, color" is the official pattern; production-pipeline ch. 8 role split). Coarse vs. fine blockout discipline: ch. 14 (strip path lines, axes, camera frustums — they render as content). On Higgsfield, attach the Blender viewport render/recording as a normal reference (Blender plugin, platforms-models ch. 13). **The clay render is also the hard SIZE and staging control for props/creatures** — the video-side answer to image-model-logic ch. 24d.

🟢 **Voice channel per character — text half always, reference half by surface:** the verbatim voice-conditions block (12b) is the TEXT half and goes into every take where the character speaks. The REFERENCE half is exactly one of, in this order: (1) a saved/cloned platform voice where the surface offers one (post-audio-legal ch. 18); (2) an `@Audio` reference — one compilation of the character's approved generated lines, combined <30 s, uploaded as an AUDIO file, role line "@Audio N defines <character>'s voice — timbre and manner only, do not reuse its words" (the audio-slot form of the ch. 18 P17 harvest); (3) the surface takes video but no audio references: the ch. 18 P17 black-screen MP4 as `@Video`, role line "@Video N carries <character>'s voice only — it is not a motion, pacing or framing reference" (the exclusion is mandatory: @Video defaults to motion). Never attach the same compilation as both @Audio and @Video; never list a voice reference for a character who has no line in the take (12b tag rule).

🟢 **The edit suite — repair before reroll.** An approved take is never regenerated for a local fault. All official [BD-off], all invoked as prompts (Higgsfield's Video page exposes no mask/annotation editor as of 2026-08-31 — describe the region in words; 🟡 a draw-over tool was sighted in Cinema Studio's Edit → Advanced on 2026-09-01, platform-ui-workflows §1):
- **Region edit:** `[what] + [change] + [effective time range]` — "repaints just that region, no full regeneration, no seed lottery" [H-off]. Always time-scope (ch. 14 edit format).
- **Camera-perspective edit = a B-camera pass on an approved performance:** "Edit @Video 1. Keep the characters, actions, and visual style unchanged. Adjust only the camera movement." + a segmented camera plan per time range (official worked prompt). Coverage tool: production-pipeline ch. 16 rung 2.
- **Green-screen relocation** (runs as `omni_reference` with the source clip attached): moves a performance into a new environment; the model adapts cloth flutter, hair, gait rhythm, and lighting interaction to the new scene.
- **Subject swap:** Timeline Inheritance clause mandatory (ch. 14).
- **Audio-category edits:** dialogue, spoken language, voice, BGM, SFX edit independently ("Remove only the original background music. Keep the character dialogue, lip sync, ambience, and action sound effects").
Constraints [X-ext]: edit source ≤20 s recommended, 1–5 accompanying refs; **an edit bills the source's FULL duration on Higgsfield** — the saving is fewer attempts, not per-run price. Consequence: **draft at 10 s; once the beats lock, regenerate the locked prompt as a fresh full-length take at target resolution (never extend the draft — extension is for building length PAST a full take, next paragraph); from then on every fix is an edit.** ⚠️ **Edit-round ceiling — by analogy, no 2.5-specific evidence yet:** treat chained video edits like image edit chains (style-control §2, image-model-logic ch. 24g multi-turn collapse): after 3 edit rounds on one source, stop chaining. Export the best intermediate as .mov (ModelArk item above), register it as the new `@Video 1` source, and continue edits from that file; if the remaining fault is global, regenerate from the original references instead (W8 / production-pipeline ch. 1 review loop). Log each edit round as a Take ID.

🟢 **Extension chains [BD-off]:** 4–30 s per round, forward or backward; carries main characters, environment, narrative pacing, audio continuity. **Chain ceiling ≈60 s** (30 s source + one 30 s extension) — beyond that, re-anchor a NEW generation from the original references instead of extending an extension (degradation compounds). Boundary-frame contract every round: forward — "the first frame of the extended segment directly continues from the last frame of @Video 1" (the last clean frame — boundary-frame source, ch. 14); backward — write the source's first frame as the extension's explicit END state and declare which materials must not appear early ("then connect to the source video" is the documented failure; ch. 14 extension rules). Restate the continuity list each round. 180 s single-flow is a Dreamina-only beta, not a Higgsfield plan.
🟡 **One location per take for narrative intercuts [P28, Seedance 2.0 evidence]:** do not prompt A/B parallel action inside one generation (hero ship ↔ enemy ship); generate one take per location and cut in the NLE — the complexity budget (SKILL rule 3) applied to locations. Montage/commercial takes (next line) are exempt: they may span locations because no parallel action is implied.
🟡 **Montage ceiling and the missing agent [P38]:** commercials/montages are the exception to the 2–3-shot drama budget — cap at **12–15 cuts per 30-s take** ("so it can focus on each cut"; an LLM's first draft had far more). Name the ACTOR of every action: "onions are chopped" rendered a kitchen with no hands in frame — write "the chef's hands chop". 🟡 **Everything unreferenced goes static when the reference count is high [P39, P41]:** with ~9 references the composite held but crowd and sky froze; write background life explicitly ("people moving in the beach bar") or get a ghost town.
🟡 **Write the boundary state from harvested frames [P22]:** before prompting an extension, frame-harvest the source's first/last frame plus 2–3 keyframes, and let the agent write the continuation FROM those stills — who stands where, what each hand holds, where the light comes from — so positions, hand contact and eyeline are held verbatim ("his hand stays on the side of the washing machine"). A well-anchored extension cut together with its source was reported seamless.

🟢 **Timestamp control is a documented channel at generation AND edit time [BD-off]:** three official forms — time ranges (consecutive, non-overlapping), exact points ("At 5 seconds, the camera whip-pans rapidly to the left"), relative timing ("Three seconds after the character presses the button, the room lights gradually turn off"); every timed segment ends on an explicit end state. Still budgets, not frames — "timestamps allocate proportion, not frames" [F]: never demand events inside one second, never plan frame-accurate hits (precision limits, ch. 14).
⚠️ **Per-second beats inside a declared single shot — conflicting official 2.0 evidence [H-off, P47 vs P49]:** one Higgsfield tutorial says a single shot may still "define what happens at each second"; the same team's feature build found "defining what happens at each second is forcing Seedance to do cuts — define it as one continuous motion". Rule until 2.5-specific evidence: in a take declared as ONE continuous shot, write relative timing ("three seconds after …") and end states, not a stamped per-second list; stamped segments belong to declared multishot takes.
