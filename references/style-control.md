## 1. Style stack hierarchy (all models)
🟢 Descending force: **(1) reference images that carry the look → (2) platform settings (CS 4.0 palette/lighting/camera) → (3) prompt style block → (4) model default (usually photorealism).** Video models do not re-stylize on their own: photoreal plate + Pixar prompt = photoreal video; stylized plate + Pixar prompt = stylized video. The look is won in the STILLS (stills-first, production-pipeline ch. 1); the prompt only secures it.
🟢 Why a single style word fails: models default to photorealism; a label without an anchor is overruled or decays after beat 1. Style needs the stack, not a word.
🟢 **The strongest single style carrier for stylized-3D is a FIGURE in frame [PP]:** stylized environments without a character default to photoreal on every image model (their real-world counterparts are near-photoreal); the character forces the whole render into the stylized mode. Hard rule + inverted build order: production-pipeline ch. 1; proven prompt-only alternative for figure-less environments: pixar-look §9 (style-forcing blocks; brightness-dependent).
🟢 **Image block vs. video prompt — do not confuse them.** For IMAGE models (GPT Image 2.5) the style block goes FIRST and works (§2). For VIDEO prompts there is no KEYWORD prefix at the top in any technique: in a Caption Spine (technique A, video-prompting ch. 12h) the look is ONE STYLE line of 8–10 positive tokens directly under the title sentence, paired with the look-carrying references, and the light state is a word inside the beat [PP 2026-09-14]; in the block structure (technique B) style is distributed into the blocks that govern each aspect (placement rule 1). The "paste one global look block on every video prompt" pattern is what Higgsfield's own Shotlist-Director skill emits [H-off, P38] and what several practitioner skills copy — it is official output, not a convenience note; this skill does not adopt it as a keyword prefix — the technique-C Master Style Block is a different object, a 200–400-word medium description (§6c) — because in tests Seedance ignores a floating keyword prefix (and GPT Image 2.5 ignores a keyword-chain opener, §2 — its structured style block is a different thing) while the reference image and per-block placement carry the look. Documented as ⚠️ open conflict (video-prompting ch. 12 primacy caveat). **Technique C — the Master Style Block + story for medium-emulation looks (one of the three techniques of SKILL rule 4, chosen per project; ch. 12 placement rule 1 belongs to technique B and does not apply inside C).** The prefix that fails is a KEYWORD prefix. P51 ran 33 medium-emulation master prompts of 200–500 words as an opening block with the story underneath on Seedance 2.5. Such a block is not a keyword chain; it is a full description of a physical medium in seven layers, motion grammar included (§6c template). Fit, not rule (SKILL rule 4): medium-emulation looks usually run as technique C; a project may instead carry the medium's 8–10 tokens on a Caption Spine STYLE line — the intake draft takes decide (ch. 12h); photoreal, stylized-3D and era looks run on A or B as chosen at intake. If a medium look drifts under C, the logged fallback is the distributed B placement. No A/B against the distributed form exists yet — a project that runs one logs the winner in the bible.

## 2. GPT Image 2.5 — style mechanics
🟢 **Model identity (updated 2026-09-09):** the current OpenAI still model is **GPT Image 2.5** — ChatGPT-native "ChatGPT Images 2.5"; in the API, `gpt-image-2.5-flare` (the **default** — fast/everyday, and it already carries the quality + editing gains) and `gpt-image-2.5-sunburst` (an *extra* level of edit precision at longer generation times — reach for it on locality-critical edits: derived empty plates, figure removal, reverse angles). It **supersedes GPT Image 2** (`gpt-image-2`, no longer listed in the OpenAI image API guide as of 2026-09-09). The AR-class mechanics in this section were production-proven [PP] on the GPT Image lineage and carry forward as the safe default. ⚠️ **What 2.5 CLAIMS to change (OpenAI announcement, first-party [OAI-off] — but 🔴 until a production A/B confirms it):** far better **edit locality** (edit only what's asked, keep the rest — directly targets the "repaints everything" weakness in image-model-logic 24g; if it holds, the derived-empty-plate / figure-removal / reverse-angle edits below get much cheaper), stronger identity/style hold with less drift, ~50% faster, native sizes to 3840 px/edge, better in-image text and world knowledge. Until each claim is production-verified, keep the [PP] defaults in this section (anti-pattern closer, max-3 edits, preserve list on every edit, relational sizing). Ledger: `OPENAI-IMG-API@gpt-image-2.5@2026-09-09` / `CGPT-IMG@gpt-image-2.5@2026-09-09` (platform-ui-workflows §0).
🟢 **Reasoning model, not a keyword matcher:** plans composition before generating; natural descriptive sentences beat adjective/tag chains ("8k, masterpiece, trending" do nothing). Conflicting style mixes produce mud — ONE dominant style per prompt.
🟢 **Style block first — inside a HARD word budget:** sweet spot 100–300 words; beyond ~500, early instructions get ignored — a long scene description must not push the style block back. Formula: style anchor → subject → details → rendering specs.
🟢 **The word budget is a hard rule, and it belongs to the model+VERSION, not to this skill [PP].** Never carry a budget across a version bump or across model families — measure it on the model you are routed to and write the number into the project's bible. Documented budgets, each scoped to its model: GPT Image lineage 100–300 words (this section) · MiniMax H3 Ref2VA 350–500 words (platforms-models ch. 21) · video budgets are per technique and live in SKILL rule 6 / ch. 12h; this section owns only the GPT Image measurement. Measured on the `gpt-image-2` generation: a **1259-word** prompt carried the flat-ground instruction and the uneven-tower instruction in full, correctly worded — **both were ignored**; the identical content cut to **~300 words** landed both on the next run. Two consequences worth internalizing: (a) over-budget instructions fail SILENTLY and look exactly like a model limitation, which is how a prompt fault gets misdiagnosed as "the model can't do this" (SKILL rule 15); (b) the way you get there is a prompt that grows run by run (refinement ratchet: ch. 24b item 8). ⚠️ Provenance: measured on `gpt-image-2`; GPT Image 2.5 claims steadier instruction hold (🔴, section lead) — re-measure the budget on 2.5 rather than assuming the number transfers, in either direction. Lint every still prompt against ch. 24i before delivering it.
🟢 **Production-proven 4-section Pixar structure [PP] — supersedes keyword-avalanche openers:** a front-loaded keyword chain ("whimsical Pixar-style stylized 3D animation, rounded simplified forms, soft global illumination, subsurface scattering…") as the opening line does NOT hold. What works:
```
[1 FRAME]  A Pixar-quality 3D animation still, [aspect ratio, e.g. 16:9 landscape]. Cinematic feature-film look, [lighting].
[2 SCENE]  Concrete scene: specific objects, materials, light — 5–12 concrete nouns.
[3 CHARACTER]  The figure with explicit Pixar proportions: "expressive, slightly oversized eyes
           (classic Pixar proportions)", sculpted detail, believable surface.
[4 ART DIRECTION]  "full-CG Pixar aesthetic — subsurface scattering on [specific surfaces],
           physically based materials, soft shadow ambient occlusion, [specific light cues].
           Clean stylised shapes consistent with [2–3 Pixar film titles] — not photoreal
           uncanny-valley."
```
Image-model rule (AR class): the negations in this section are never ported into a video prompt — there the wanted light/material grammar replaces them (video-prompting ch. 14, third class). The anti-pattern closer ("not photoreal uncanny-valley") at the END of the art-direction section is essential — without it GPT Image 2.5 drifts back to photoreal. Film titles as aesthetic lineage are established (§6 IP line; post-audio-legal ch. 20); characters stay original.
🟢 **Actively repel the photoreal default:** "Pixar style" alone is not enough. What works: (a) **ONE style-repulsion anchor** — the anti-pattern closer at the end of [4 ART DIRECTION] ('not photoreal uncanny-valley' or 'NOT a photograph, NOT photorealistic'), never a second one earlier in the prompt (SKILL rule 6) (community tests: ~80% photoreal without it; the official cookbook uses the same technique inversely: "Avoid cinematic lighting" for documentary realism) — plus (b) **concrete rendering cues**: `subsurface scattering on all surfaces` (strongest single cue), `soft ambient occlusion`, `soft global illumination`, `painted CG material — every surface reads as rendered, not photographed`, `cinematic warm-cool color grade`.
🟢 **Film-reference framing beats technical adjectives:** "This is a still from a Pixar animated feature film / a $200M animated feature."
🟢 **Max 3 edit iterations per asset** [H-off, P49 reproduces it at feature scale] — quality degrades after (noise, shadow artifacts) → rewrite the prompt and regenerate. Refinements: one variable per round; preserve list on every edit ("change only X, keep subject identical").
🟢 **Object size: relation or mask — NEVER canvas fractions [PP]:** image models have no concept of "percent of image width" — that is a post-hoc measuring unit for humans, not something the model reasons in. It thinks in objects and their relations, not in frame shares, so "~1% of the image width" style size specs fail silently and burn reroll budget (production evidence: four consecutive %-scaled runs, all wrong-sized — measured on the `gpt-image-2` generation, for the SIZE of a small object; OpenAI's image prompting guide recommends "relative scale" and placement constraints in words and shows neither coordinates nor percentages [OAI-off]; a platform post laying out a coarse composition in percent coordinates on GPT Image 2.5 is a single unmeasured result, not a method of this skill). What works, in order: (a) **relational anchoring** to an object of known size already in frame — "no larger than the pebbles beside it", "the size of @X in the frame" — with **exactly ONE comparison anchor**: stacking several ("tiny vs. the shelf, the size of a nub, smaller than a mound, a minor speck") averages out like style soup and reads as emphasis, not precision [PP]; (b) for hard size constraints in an EDIT: **masked/region inpaint on a HARD-mask platform** (FLUX Fill, Imagen — outside-mask content is algorithmically preserved, the mask truly defines the size); ⚠️ GPT Image's mask parameter is official-documented as guidance only ("entirely prompt-based… may not follow its exact shape") — there, pair the mask with the full preserve list and expect overflow. Mask-strictness table + full position/scale control ladders: image-model-logic ch. 24. Know the coupled failure mode: **detail demand inflates size** — the moment the prompt asks for visible detail (facets, engraving, texture) on a small object, the model enlarges the object to fit the detail, and no wording overrides that; describe detail AS IT READS at the target size ("two or three sharp glints suggest facets") instead of as modeled geometry, or take the mask path. Numeric canvas units (%, px, fractions of frame) are ballast at best and actively counterproductive at worst — this applies to every image model, not just GPT Image 2.5.
🟢 **Placed objects float unless contact is positively locked [PP]:** "resting on", "at the edge", "slightly overhanging" plus "a small contact shadow" do NOT guarantee ground contact in an edit — the model happily renders the object hovering with a shadow painted beneath it. Write the contact itself as a positive lock: "bottom face flush on the surface, full contact, weight settled — no gap between object and ground." Drop overhang/brink phrasing for small objects entirely; it invites hovering. (Same principle as SKILL rule 6: positive locks sit next to what they protect.)
🟢 **Know the weaknesses:** strong at structured, text-heavy production output; weaker at atmospheric painterly imagery — the style block must be extra strong there. In-image text: exact wording in quotes, 1–5 words, state the position. Resolution: the 2.5 Image API documents native sizes up to 3840 px per edge (multiples of 16, aspect 1:3–3:1) 🟢 [OAI-off]; on the GPT Image 2 generation >2K was experimental (generate lower + upscale) — re-verify native high-res quality on 2.5 before dropping the upscale step.
🟡 **Material rule for critical surfaces** (ice/snow as example; applies to glass/water/metal): the model renders these photoreal (wet, transparent, crystalline). Counter-recipe: anchor the desired material positively AND negate the photo appearance — "matte powdery surface like fresh dry snow — NOT wet, NOT glossy, NOT transparent. Reads as painted CG material."

### Which GPT Image 2.5 structure to use (selector — read before writing any stylized still)
- **Figure IN frame** (character sheet, figure-anchored anchor plate, hero still) → the 4-section structure above; section 3 is mandatory.
- **Figure-LESS stylized environment from scratch** → the pixar-look §9 five-block template, copied verbatim; swap the Scene / Composition / Camera / Lighting-palette blocks AND cut the Avoid block to its five protected traps plus only the scene-specific forms that have appeared in a run (§9 item 5); keep all five load-bearing blocks (priority sentence, thumbnail rule, flat-graphic style, render treatment, avoid list). §9 SUPERSEDES any [STYLE]-first plate opener for this case; generic "stylized animated-feature" wording, no studio name or film title (pixar-look §9 IP wording rule); dark scenes use the §9 bright-anchor method.
- **Figure-less plate DERIVED from an approved figure-anchored plate** → an edit prompt (remove the figure + preserve list, production-pipeline ch. 1 step 3; edit mechanics image-model-logic ch. 24g) — no fresh style template.
- **Photoreal stills** → the capture-context phrases below (one dominant capture frame).

Compact style vocabulary for the [4 ART DIRECTION] section of a figure-in-frame still (NOT a standalone template): "a 3D animated world — NOT a photograph, NOT photorealistic; every surface reads as painted CG material with soft subsurface scattering; simplified sculpted forms with clean readable silhouettes (rounded or faceted — prompt a deliberate mix, pixar-look §9 refinements); soft global illumination, soft ambient occlusion, gentle rim light, cinematic warm-cool color contrast; warm, handcrafted, unmistakably animated."

### Structured image-prompt patterns [G2-gallery]
🟢 **Layout before subject:** when structure matters (sheets, grids, storyboards, posters, plates with fixed composition), allocate space FIRST — canvas, aspect ratio, grid/zone layout — then describe the subject. Stated late, layout gets improvised. This applies to EVERY still prompt, not only structured ones: state the canvas/aspect ratio in the prompt (first line or FRAME block) and set the same ratio in the UI; the Render Slate "no double control" rule (SKILL rule 11) governs video prompts only. 🟢 **Prompt text alone does not bind the ratio [PP]:** a run whose Composition block read "ultra-wide 16:9" came back SQUARE — in an image model the ratio in the prompt is composition language that biases the layout, while the canvas is actually set by the UI/API size parameter. Write it in both places every time; where only one is possible, the UI/API parameter is the one that decides, and a mismatch between the two is a contradiction the model resolves silently (ch. 24b item 2).
🟢 **JSON/config-schema prompts** are a proven GPT Image 2.5 pattern for stills with many interacting systems (environment + subject + materials + lighting + particles + render goals): keys name visual subsystems (GLOBAL_SETTINGS / ENVIRONMENT / CORE_ASSETS / DETAIL_SYSTEMS / OUTPUT with an avoid-array), values are concrete visual constraints. Useful for complex hero plates and product/commercial work; JSON needn't be machine-valid — clean and readable suffices.
🟢 **Director-lineage scene formula** (extends the director-signature shorthand): "A [shot type] in the lineage of [director/film aesthetic]'s [signature]. [Scene with 5–12 concrete nouns]. The color palette is a strict scheme of '[Named Tone 1]', '[Named Tone 2]', '[Named Tone 3]'. Lighting: [source, direction, contrast]. Camera: [lens, angle, focus]. The mood is [2–3 words]." Naming palette tones in quotes as proper nouns ('Millennial Pink', 'Amber and Cobalt') binds them noticeably harder than loose color words. Legally safe as aesthetic lineage; keep characters and settings original.
🟢 **Capture-context phrases for photoreal stills** (name HOW it was captured, not that it's realistic): "RAW, unprocessed, full iPhone camera quality" (kills AI polish) · "amateur photo, shot from the crowd at a distance" (real-event feel) · "eye level, 28 mm lens feel" (architectural) · "natural morning side light" (lifestyle). ONE dominant capture frame per prompt — stacked camera specs conflict.
🟢 **Scene density beats adjectives:** 5–12 concrete nouns + 2–4 material/light constraints; empty quality words ("stunning", "professional", "8k") do nothing in a reasoning image model.

## 3. Nano Banana Pro — style mechanics
🟡 Scope: tested on the model labelled Nano Banana Pro. "Nano Banana 2" (OpenArt, Higgsfield Blender add-on; on Higgsfield's Image selector both Pro and 2 exist side by side, changelog 2026) is a different model — treat §3 as a starting hypothesis, receipt under the surface's exact label, one A/B before relying on it (production-pipeline ch. 5 label-mismatch note).
🟢 **Style-transfer syntax with feature lock:** "Same character as the reference image, redrawn in the style of [X]. Maintain [unique features: scar, hair length, earrings…]." Without explicit feature naming, transfer generalizes the face into a generic anime face. Repeat garment specifics at EVERY zoom level.
🟢 **Placement inverse to GPT Image 2.5:** lock facial markers via text tokens, put the **new style medium at the END of the prompt**; keep outfit + pose identical to the reference for the first transfer.
🟢 "Too realistic" fix: strengthen style keywords (anime style, cel shaded, comic book art) + attach a style reference image (1–3 refs: character/style/background separate).
🟢 Multi-character: map left-to-right explicitly; from 3 characters, **scaffold** — generate two, lock, then add one character at a time onto the locked image (otherwise feature swapping). Capacity ~5 characters/14 objects.
🟢 Manga/comic specialty: full-page generation (one whole page instead of single panels) keeps characters consistent across panels and lays out itself.

## 5. Video layer (Seedance 2.x / Cinema Studio)
🟢 Style comes from the references (§1) — the approved anchor still attached as a tagged reference, a literal start frame only in the chain case (production-pipeline ch. 1); the video prompt only secures it — in a Caption Spine (technique A, video-prompting ch. 12h) with the one STYLE line and light words inside the beats; in the block structure (technique B) **distributed, not as a prefix**: light in LIGHTING, colour in COLOR GRADE or LOCATION, optics in OPTICS, acting/skin in PERFORMANCE, physics in PHYSICS; the 4–8 look tokens sit in the STYLE suffix near the end (§6 meta rule). Block structure: a lock lives once — the load-carrying style aspect goes to POSITIVE LOCKS only if no block states it already (economy doctrine); Caption Spine: the closing "Maintain … throughout" names the one load-carrying aspect. Exclude style bleed from photoreal references by the job sentence ("@X shows the layout and light only" — the Caption Spine form; the block-structure line adds "Do not copy its photographic rendering." once a bleed has actually occurred). Declare mixed styles explicitly ("photorealistic environment, stylized characters"). Motion must match the style (limited animation = static bodies + tableau camera; Pixar = squash & stretch, weight). Official formula (⚠️ superseded default): "@image is the first keyframe and style reference" — read today as "@image is the style and geometry reference"; first-keyframe use only in the chain case (production-pipeline ch. 1).
🟢 CS 4.0: style additionally via settings (palette/lighting/era) — dials before prompt, avoid double control (platforms-models ch. 13b); ⚠️ verify per project that the dial bites on the selected video model, else carry the aspect in its prompt block (platform-ui-workflows §1, blockquote "Do the controls bite?").

## 5b. Style control per video model
🟢 **Meta-finding (multi-source):** no universal style winner — run a **motion ladder** per style and model (subtle portrait → head turn → walk → fast action → interaction). Never copy prompts 1:1 between models.

### Seedance 2.0/2.5
🟢 **Flat 2D is harder than stylized 3D** — the counterintuitive core finding: Pixar-ish 3D forgives (gradients hide frame errors), flat cel punishes every wobble ("lines crawl, the whole frame boils"). Flat 2D needs simpler motion and stricter control.
🟢 **Anti-3D fix for flat anime:** (1) explicit flat rendering terminology: "solid vector lineart, unlit flat tones, traditional anime cel-shading, flat sRGB color space" — suppresses depth maps and forced ambient occlusion, holds line weights in fast motion; (2) the depth suppression written POSITIVELY — "every surface a flat colour plane, no shading gradient, outlines carry all form" — a single concrete exclusion at most, never a repeated "no 3D" (ch. 14 third class: a repeated ban is an attractor).
🟢 **Style anchor workflow:** carry the flat cel style per the project's technique (A: STYLE line; B: STYLE suffix, the anti-3D lock in POSITIVE LOCKS only if no block states it; C: layers 2–3 and 7 of the Master Style Block) + limited palette + character references — never as a bare keyword opening line (§1); drafts on Mini/2.0, finals on the full model. Name the production technique, never a mood ("flat cel shading, bold outlines, no motion blur" not "anime feeling").
🟡 **Medium motion grammar — name how the medium MOVES, or the style arrives as a filter [P51, 33 medium styles, sponsored].** A physical-medium or era-animation look (cel, ink, clay, paper, puppet, screen print, action figure, charcoal) holds in video only when the prompt states the medium's motion signature and refuses interpolated smoothness ONCE: frame cadence ("animated on twos and threes, 8–12 drawings per second, held drawings between key poses"), how fast motion is drawn (smear frames, duplicated limbs, speed lines — never digital motion blur), how faces move (a few mouth shapes, blinks as two or three drawn poses, hold then change decisively), how hair and cloth move (drawn masses, not simulated strands), and the medium's physical lag (marionette limbs settle a beat after the body, screen-print colour layers lag a frame on fast motion, paint-on-glass keeps ghosts of earlier frames, charcoal keeps the incompletely erased previous pose, action-figure joints pivot mechanically with no squash-and-stretch). Without it the model renders smooth 24-fps motion under a surface texture — the same failure class as the §1 style word. Placement on Seedance/CS: inside the Master Style Block that opens a §6c prompt (its layer 7); on a distributed prompt the acting cadence in PERFORMANCE, the medium lag and smears in PHYSICS, the cadence word in STYLE; in a Caption Spine the cadence token on the STYLE line and the medium's lag/smear sentence inside the beat where the fast motion occurs (12h); the anti-interpolation instruction is written as a positive ("movement has the slight stutter of photographed cels") plus at most one concrete exclusion (ch. 14). Pairs with the §6b restraint rule: analogue artefacts (grain, registration shift, dust, tape wobble) stay subtle — "not damaged" — or the footage reads as a VHS filter over a clean render. Compact packages per medium: §6c.
🟢 **Official whole-video style lock pattern:** "Maintain consistent 2D anime illustration style throughout." And mixed media **per element**: "photorealistic environment with real people, cel-shaded flat coloring on hero only, cartoon physics and expressions on hero only." Block placement on Seedance/CS (technique B): the whole-video lock sentence goes in POSITIVE LOCKS; the per-element mixed-media declaration goes in STYLE; in a Caption Spine this is the 'Maintain <one thing> throughout' clause of the closing sentence (12h element 8) — once, no second lock elsewhere.
🟢 Style transfer: attach a style reference + "in the visual style of the reference"; director/DoP/film references as anchors ("Wes Anderson symmetrical framing") — **one** style reference per prompt.
🟡 Also viable: pixel art (limited palette, hard edges, no anti-aliasing, four-frame gait cycle) and oil paint with moving brushstrokes.

### MiniMax H3 (Hailuo 3)
🟢 Stylization strengths: **holds line quality and proportions in 2D/anime** ("which most video models struggle with"); realism trends plastic. Specs: 4–15 s, 24 fps, native 2K on hosted surfaces (⚠️ 768p-base claim retired, platforms-models ch. 21); one beat per shot. Prompt in the official three-field / six-section formats — never port the Seedance block structure 1:1.
🟡 **Unique capability — LoRA:** trained LoRAs (own clips/keyframes) can hard-lock style, character, or motion — potentially the strongest style lock for many-clip consistency, but the training method is still unshown in any fetched source (platforms-models ch. 21).
🟢 Prompt logic: action chain (cause→motion→reaction, chronological) instead of scene description; official modes T2VA/I2VA/FL2VA.

### Kling 3.0
🟢 **Strongest stylization flexibility of the photoreal class**; multi-shot mode holds the art style across shots — hence the anime recommendation of several comparisons. But: anime sits outside the comfort zone → **2–3× reroll budget** vs. realism.
🟢 **Style drifts per generation:** Kling interprets each generation independently — repeat identical style keywords in EVERY prompt of the sequence + reuse the same style reference image. Never mix realism and anime in one prompt.
🟢 MotionControl: reference action video + face binding for body/face/hand motion.

### Veo 3.1
🟢 Photorealism-first: overly smooth physics-correct motion works **against** anime aesthetics (stylized movement is exaggerated, not correct). Can stylize when the motion grammar is prompted along: stop-motion via "12 fps judder, frame-to-frame jitter, no motion blur, preserve handmade imperfection"; anime via "squash-and-stretch, impact frames, speed lines" + "keep character on-model across shots"; vector flat for explainers.

### Grok Imagine (1.5)
🟢 **Native stylization bias:** drifts cartoonish/Pixar-like on its own (even converts photoreal intent) — several aggregator matrices list it as THE pick for "stylized: anime, cyberpunk, cartoon, music-video, art-directed". Negatives unreliable → style qualifiers at the prompt START. Grok Imagine 1.5: 1080p only in specific modes (mode names unverified — read the live selector), 720p otherwise; plan the upscale path unless the receipt shows 1080p.

### Wan 3.x (2.6 → 3.0 Prime) · LTX

### Restyle path (video-to-video, distinct production route)
🟢 Fully restyling existing footage (live action → anime/Pixar/claymation/pixel art) is production-ready — reference class **Runway Aleph** (in-context V2V: re-skinning, object edits, relighting with preserved motion); alternatives Luma Modify, GoEnhance et al. Prompt pattern: short and specific — "Detailed anime film aesthetic, **stable facial structure**, soft cel shading, cinematic anime lighting"; specificity beats length. ⚠️ The quality test is MOTION: many "restyle" apps are frame filters that fall apart in movement. Source limits for Runway Aleph 2.0 Edit Studio are documented (RW-WEB@2026-09-04: 2–30 s, 480p–1080p, 24–30 fps, ≤10 cuts, Single-edit mode only — platform-ui-workflows §3); other restyle apps (Luma Modify, GoEnhance) remain 🟡 untested — run a short clip first. ## 6. Style vocabularies (token packages — placement per model)

## 6b. Non-animation styles: footage authenticity, era looks, technical optics
### A. Footage authenticity (found-footage family)
🟢 **Four-tell rule:** a clip only reads as "genuinely recorded" when FOUR things are named: (1) the recording format (camcorder/VHS shoulder cam, dashcam, bodycam, CCTV, livestream/webcam), (2) a burned-in tell (timecode lower right, REC icon, battery red-light — "battery red-light reflected in breath"), (3) exactly ONE in-frame light source (headlamp, headlights, fluorescent strip), (4) a camera that does NOT behave cinematically (fixed mount or panicked handheld). Name the artifacts in language instead of hoping for filters — "scanline softness on a 1990s shoulder-camcorder, dust in a headlamp beam."
🟢 **Restraint rule:** the scene must stay readable under the damage — "build the fear first, then add only enough tracking drift, timecode, and tape wear to make the clip feel recovered instead of overprocessed."
🟡 Sub-vocabularies: **VHS** — tape grain, tracking errors, scanlines, static bursts, chromatic drift, faded colors, timestamp overlay. **CCTV** — fixed high angle, b/w or IR green-gray, muted tones, noisy shadows, edge blur, burned-in timestamp, corner brackets. **CRT monitor feed** — cool blue tint, phosphor glow, screen curvature, analog noise. **Bodycam/dashcam** — chest-height ultra-wide, motion blur on head/vehicle movement, close distorted audio.
🟢 **Anti-slop bonus:** degraded-media looks have built-in fault tolerance — grain, blur, and compression mask model artifacts (same principle as the UGC path). A footage format is a legitimate rescue style for risk shots.

### B. Era & film-stock looks (prompt layer of the era selector)
🟢 **The year is a rule, not decoration [H-off, P24]:** write the period as a hard bound — "nothing in frame is newer than 2011: no smartphones, no glowing screens in a crowd, no modern cars at the kerb" — because the model pulls every picture toward today by default (an extra will be holding a phone). **Twin sets stay apart by contrast locks:** two rich interiors in the same palette are written as patina vs. polish (dried oxblood, tarnished gold, one aged lamp — vs. saturated crimson, mirror-bright brass, identical lamps in symmetry) plus a never-clause each way ("never tarnish on the new money, never mirror polish on the old").
🟢 **Named film stocks are precision tools** — models know their signatures: Kodak Portra 400 (soft natural skin, faded blacks), Kodachrome 64 (rich, warm), CineStill 800T (tungsten + halation), Fuji Pro 400H (greenish shadows), Kodak Tri-X (b/w, hard grain), Fujifilm Velvia (hyper-saturated landscape). "Scanned film negative" adds realistic imperfections.
🟡 Look building blocks: **16mm** — blooming highlights, heavy grain, jitter texture, vignette, "avoiding any digital sharpness"; **Super 8/8mm home movie** — warm, flickering, family nostalgia; **newsreel** — 16mm b/w, scratches, slightly sped motion; **Polaroid/Instax** — creamy highlights, chemical streaks, white frame border, pastel fade; **1990s disposable** — harsh direct flash, red-eye, date stamp, washed colors; **daguerreotype/Victorian** — sepia-metallic, oval vignette, long-exposure stillness; plus silent-film 1920s, Technicolor 1950s, French New Wave, Y2K digicam flash as established shorthand.
🟢 **Vintage vs. retro — decide explicitly:** vintage = authentically "shot back then" (period-correct fashion, set, imperfections included); retro = modern subjects in old capture technique. The model needs the decision or it mixes. Always couple an era look with period-correct production design.
🟡 **Director signatures as composition shortcuts** (legally safe — style, not work): "Wes Anderson style" = perfectly symmetrical central composition + flat pastel palette + deadpan storybook framing; works cross-model as shorthand for a whole rule set. Similarly usable: noir 1940s (hard shadows, venetian-blind light), European arthouse (muted, soft, emotional).

### C. Technical optics & special cameras
🟡 Prompt vocabulary for optics beyond preset lenses: **FPV drone** — rapid low-altitude weaving, motion blur at frame edges, lens flare through obstacles (opposite of gimbal drone: "flat, stable, horizon-level" is the anti-FPV look); **action cam/GoPro** — ultra-wide FOV, horizon-locked, hyper-stabilized, helmet/chest mount; **thermal** — heat-signature rendering, white-hot/black-hot, temperature gradients instead of texture; **night vision** — IR green, glowing highlights, noisy shadows, pupil glow; **tilt-shift miniature** — extreme selective focus plane turns real scenes into model worlds. Optics choice = genre signal (military, survival, documentary).

**The Master Style Block — how a §6c look is delivered (🟡 [P51 + PP review 2026-09-12]; technique C of the SKILL rule-4 menu).** Seven layers, in this order, written as a description of a physical medium (the P51 blocks run 200–400 words) — never as adjectives — and placed as the opening block of the video prompt. No STYLE block or STYLE line follows — the Master Style Block is the prompt's only style carrier; nothing downstream restates it.

```
MASTER STYLE: Render the entire video as <medium, era, production context — e.g. "an authentic mid-to-late 1980s
   Japanese hand-drawn theatrical anime sequence photographed from painted cels">.
[1 SURFACE / MEDIUM]   what the image is physically made of and photographed from (cels over gouache · wet ink on rice
                       paper · needle-felted wool over wire · carved wood on a proscenium) — visible, not implied.
[2 CONSTRUCTION]       linework and form grammar of characters vs. backgrounds (line weight and its imperfection,
                       anatomy simplification, hair and cloth as masses, characters flatter than the painted BG).
[3 COLOUR]             the palette as pigments or inks, named (aged ivory, oxidised red, chrome cyan), shadow shapes
                       (one-tone / two-tone / halftone), what the medium cannot do (no gradients, no RGB neon).
[4 LIGHT]              light as the medium makes it — painted-in shapes, eraser highlights, backlit fibres, footlights,
                       exposed glass — never physically simulated; one sentence on day and one on night.
[5 CAMERA LANGUAGE]    the moves native to the medium (multiplane pans, held frame + push-in, camera in the stalls,
                       macro over stitches) and the ones it forbids (3D orbit, impossible seat positions).
[6 ANALOGUE CHARACTER] the artefacts, dosed: grain, weave, registration shift, dust, halation — "subtle, not damaged".
[7 MOTION GRAMMAR]     the §5b rule: cadence (on twos/threes, drawings per second), holds and bursts, how fast motion
                       is drawn (smears, duplicated limbs, speed lines — no digital motion blur), face economy (mouth
                       shapes, blinks in 2–3 poses), medium lag (pendulum settle, layer misregistration, ghost poses),
                       and ONE positive anti-interpolation sentence ("the slight stutter of photographed cels").
MUST NOT APPEAR:       one terminal list, 5–12 style words, stated once — the scoped exception to SKILL rule 6 for technique C
                       only (ch. 14 terminal-list note); never restated anywhere in the prompt.
```

**Filled example — technique C on the Sumi-e ink wash row (fictional content):**
```
MASTER STYLE: Render the entire video as a sumi-e ink-wash painting, brushed by hand in black ink on rice paper and photographed sheet by sheet.
SURFACE / MEDIUM: Every image is wet ink on absorbent rice paper — visible fibres, ink pooling where the brush paused, feathered edges where the wash bled. The untouched paper is the mist and the light.
CONSTRUCTION: Figures and rocks are calligraphic silhouettes from a few loaded strokes; each stroke starts dark and wet, dries as it travels and breaks into a dry-brush scratch. Anatomy is suggested by the strokes alone — the heron is a neck stroke, a body stroke, two leg strokes. Backgrounds are paler washes with fewer strokes.
COLOUR: Ink carries the picture in five tones from soaked black to dry grey; colour appears only as restrained mineral accents laid in after the ink — one touch of oxidised red, a breath of indigo, a jade fleck. Every gradient is a wash thinning across the paper; every highlight is unpainted paper.
LIGHT: Light is absent paper. Day is a wide expanse of untouched sheet with the wash thinning toward it; night is a heavier grey wash that leaves the moon as a bare circle of paper. Shadow is pooled ink.
CAMERA LANGUAGE: The camera moves like a hand across a scroll — slow lateral drifts, held frames, a gentle push toward a detail — and stays on the plane of the sheet.
ANALOGUE CHARACTER: Dosed subtle — paper tooth in every wash, faint mottling where the sizing is uneven, the odd stray bristle caught in the ink. The fibres stay fixed; only the ink moves.
MOTION GRAMMAR: Painted on twos and threes, about ten held drawings a second, each pose a fresh sheet so the strokes flicker slightly between frames. Fast motion stretches the figure into an ink mark — a wingbeat becomes a brush arc, a splash a black star — and reforms when it stops. Water is a few parallel dry strokes that redraw themselves. Movement keeps the slight stutter of photographed sheets.

0–4 s, wide: a heron stands motionless on a river stone in mist; the current slides past.
4–7 s, close-up: the heron strikes down through the surface and lifts a fish clear of the splash.
7–10 s, wide: the heron opens its wings and rises off the stone.
End with the heron gone out of the top of frame and the river stone alone on the sheet.
MUST NOT APPEAR: digital watercolour filter, glossy surfaces, photographic depth of field, rendered 3D volume, motion blur, smooth interpolated motion, on-screen text, music.
```

## 7. Reference integration protocol (for prompt-writing agents)
🟢 **Declare the style donor [H-off, P23]:** when references come from different styles, name which one donates rendering style to which receiver and dose it in words — "take the style of the character and apply it to the background" (Higgsfield's own fix on a hybrid short; push harder/softer to control the blend). Undeclared, the model blends silently or leaves the seam. The declaration sits in the donor's reference line (job sentence in A, ACTIVE REFERENCES in B): '@hero is the man in the cap and donates his rendering style to @loc_highway and @taxi' — the declared donor is the ONE case where a reference carries two jobs, named in the same line (Rule 1). Case: pixar-look §10.
🟢 **Style reverse-engineering via LLM [P17]:** to build a project's reusable style block, feed the look-defining references to the LLM FIRST and have it analyze and write out the style (materials, skin/surface treatment, rendering signals) as a base prompt structure — then reuse that structure across all generations, refining per asset with further references until the cast and locations sit. Beats hand-writing style prose from memory. 🟡 The source can be your OWN drawings [P51]: a photo of a sketch or painting uploaded to the LLM (OpenArt's Agent Ori / Director in the source) with "write a detailed master style prompt that recreates exactly this style" produced a reusable style block that matched the artist's loose ink-and-watercolour hand in stills and video — a personal, IP-clean style anchor.
🟢 **Rule 0 — a reference only exists if the prompt addresses it.** "Attach an image in the UI" without a prompt role = undefined behavior. Every prompt with references carries one reference line per reference in the project's technique (Rule 1). Motto: "Use text to direct. Use images to preserve appearance."
🟢 **Rule 0b — address it by its literal `@token`, not by a description [PP].** On a surface with a named element library, the element's handle must appear VERBATIM in the prompt text (`@loc_ridge`, `@anchor_1A`). Prose such as "the reference image" / "the attached still" does NOT bind, even with the image sitting in the slot and visible in the UI — the run is spent and the reference reads as unaddressed. The slot is the delivery mechanism; the token is the address. Trivial, and it cost a full run in production. Where the surface has no library, the same rule applies in its tag form (upload-order tag or Mode B, Rule 2) — and the unverified-token marker goes in the slate's `Inputs` row (SKILL rule 11).
🟢 **Rule 1** — one line per reference, and the line is the JOB. Caption Spine (technique A, video-prompting ch. 12h): one positive sentence — token first, then the one job (`@cat is …`, `@loc shows the look of the room only`, `@anchor_1A is the exact background and the opening composition`) — with NO exclusion clause; what the reference must not deliver follows from the job [PP 2026-09-14: zero `Do not copy` lines, zero reference fighting in four of four runs]. Block structure (technique B): tag/name + "controls only [exactly one job]" + "Do not copy [concrete non-transfers]" — the exclusion clause only for a non-transfer that has actually occurred, economy doctrine (full line shape incl. the identity anchor: ch. 12 ACTIVE REFERENCES — one merged line, not a job line plus a separate anchor line). No tag without a job, no job without a tag.
🟢 **Rule 1b — one SENTENCE per reference beats a paragraph, and on a still prompt it is the preferred form [PP].** Paragraph-long role blocks with an itemized "Do NOT copy" list cost 150–200 words out of a 300-word budget (§2) and did not bind any better in production. Proven shape, placed directly after the opening line: **"Ice material and render level as in @asset; its forms, lighting and composition are not used."** — one clause naming the ONE job, one clause retiring everything else as a CLASS instead of enumerating the exclusions one by one. Enumeration is where the words go and where the pink-elephant risk enters (ch. 24f). Keep the long form only where locality is the point and the budget can carry it: edit prompts with a preserve list (ch. 24g) and style-donor declarations across mixed styles (below); Caption Spine video prompts use the one-sentence job form (Rule 1); block-structure video prompts use the one merged ACTIVE REFERENCES line of Rule 1 — exclusion only after a fault.
🟡 **2D vector art as identity source for a 3D render [P35, sponsored]:** a flat transparent-PNG mascot works as an identity reference re-rendered in 3D when the role line anchors the features and colour scheme to the artwork ("anchor the facial features, hat, tool and colour scheme directly to the vector artwork") — a mixed-style declaration where the STYLE donor is the prompt, the IDENTITY donor the 2D art.
🟢 **Rule 2** — clarify platform syntax BEFORE writing: @image numbers (upload order!), @element_name (Higgsfield), or Mode B (describe the visible feature). Tags are not portable (token forms and the unverified-marker: video-prompting ch. 12b tag token rule).
🟢 **Rule 3** — the attachment checklist IS the Render Slate `Inputs` row in SKILL.md's shape (rule 11), never a line inside the prompt (24b item 1).
🟢 **Rule 4** — style references get the same role discipline: "@image2 controls only the rendering style." (block-structure line; "Do not copy its subject or composition." is appended only after a run has copied subject or composition — Rule 1) — in a Caption Spine: `@image2 shows the rendering style only.`
🟡 **Rule 5 — a restyle transforms CONSTRUCTION, never adds a surface [P52].** When a character sheet or still is re-rendered in a target style (rubber hose, cut-out, sitcom, cel anime …), the prompt names the shape-grammar change the style demands — tubular jointless limbs, wedge heads, bean torsos, four-finger hands, flat cut-paper construction — while the face and outfit stay identifying; and it forbids the surface fake ONCE ("do not fake the style with sepia or film dirt"). A style that arrives as texture, grain or tint over unchanged anatomy is a filter, not a transfer — the same diagnosis as §1's style word. Constraint lists on such sheets name the sheet's own failure modes (cropped heads or feet, extra poses, duplicate body parts, costume changes, added borders), not generic quality words.
🟢 **Diagnosis:** output comes back photoreal despite a style word → the style was a word, not an anchor. Fix order: (1) look-carrying reference (a start frame only in the chain case, production-pipeline ch. 1), (2) upgrade the style carrier to the vocabulary package at its model's placement (§6 placement line; + negation anchor on GPT Image 2.5), (3) style into the locks. Never just sprinkle the style word a third time.
